Guía práctica de vipirc / onekeyirc - Configuración
======================================================

TRADUCCIÓN PRELIMINAR. Escriba comandos y opciones exactamente como aparecen.
Para los detalles de seguridad, consulte MANUAL.txt y SECURITY.md en inglés.

/help configuration
-------------------

[connection] incluye server, port, tls, nick, username, realname, channel, autoconnect, auth y fuentes de credenciales.

[bouncer] type=none|znc|soju, username, network, client y automatic_away definen el perfil bouncer de cada red; véase /help bouncers.

[input] send_mode=direct|review y [output] format=compact|full, queue_notices=true|false, program_messages=true|false, persistent_logging=true|false son preferencias del archivo principal.

[input] command_suggestions=common|history|frequent|alphabetical|contextual ordena los comandos; common es predeterminado.

[input] composer_mode=line|fullscreen elige el editor/comandos minimalista; line es predeterminado. Ambos conservan la vista de mensajes recientes.

[input] force_terminal_signals=false conserva las señales heredadas; true las activa sin reasignar teclas. Se lee al iniciar.

[hotkeys] contiene hasta 64 atajos KEY=action opcionales, sin valores iniciales. Pertenece a la configuración principal; vea /help hotkeys.

[session] single_session=true|false permite o no varios trabajos en segundo plano; false es predeterminado.

[session] default_interface=ncurses|idle es una preferencia principal. Las opciones de inicio se explican abajo.

El formato compact es predeterminado. history_lines en la configuración principal limita el historial de todos los servidores.

[mentions] word= e [ignore] mask= pueden repetirse.

[autocommands] contiene enabled, delay_seconds, interval_seconds y líneas command= repetidas para un servidor.

Estos comandos son texto sin cifrar en la configuración privada. /autocommands los administra sin mostrar secretos en listas ni historial.

Los servidores adicionales guardados usan el catálogo .servers y directorio .d contiguos.

Conecta con /connect HOST y usa /join #channel y /saveconf para guardar la configuración funcional.

/saveconf guarda preferencias y perfiles válidos; recuerda el servidor seleccionado para un futuro /connect sin argumentos.

/quickstart hace cuatro preguntas de conexión. /panel usa 0 para preferencias y 1..8 para perfiles; panel 1 edita el principal.

Los cambios del panel son privados hasta Finish. Aceptar una ruta GPG puede preparar el directorio 0700; cifrado, escritura y conexión esperan la opción final.

Para conservar cambios: /save para el servidor elegido, /save input o /save output para el principal, o /saveconf para perfiles válidos y predeterminado.

La configuración guardada usa <config_path>.commands para leer/escribir recuentos de comandos; el archivo principal no guarda recuentos.

El archivo privado limitado solo contiene nombres canónicos y recuentos, nunca argumentos ni historial. El modo de prueba no lo lee ni escribe.

Los cambios [connection] de /autojoin o /autoauth entran en vigor en el siguiente /connect desconectado; no alteran la sesión activa.

Los archivos de configuración son privados; cada archivo se sustituye atómicamente, no todo el conjunto a la vez. Sin importar/exportar.

Las secciones, claves o valores desconocidos dan error. La configuración usa valores literales, sin comillas shell, escapes, variables ni ~.

Los valores normales se recortan en los extremos. password= y server_password= conservan todo tras = salvo el salto de línea; no añada comentarios ni comillas.

Guardar reescribe ajustes admitidos y sustituye comentarios y formato manual. Conserva tus notas fuera de la configuración generada.

Véase /help authentication para secretos, /help tls para CA, /help logging para registros y /help sessions para trabajadores activos.
