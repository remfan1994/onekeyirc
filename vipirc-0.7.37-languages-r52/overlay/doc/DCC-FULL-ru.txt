ПЕРЕДАЧА ФАЙЛОВ

F6, /dcc или /transfers открывает общий список передач во всех подключениях, указывая исходный IRC-сервер каждой передачи. Действуют обычные клавиши управления списком. Доступные действия:

    Accept    Reject    Send...    Cancel transfer    Back

Для просмотра требуется окно не меньше 12 строк и 20 столбцов. Escape из обозревателя файлов или поля возвращает к форме, а из формы или списка — в чат, сохраняя черновики и уже принятые передачи. Поддерживается только классический активный DCC SEND поверх IPv4: нет CHAT, возобновления, пассивной/обратной передачи, автоматического принятия, поиска адреса или настройки перенаправления портов. Максимальный размер файла — 4,294,967,295 байт. Полученные файлы не открываются и не запускаются автоматически.

DCC — прямое незашифрованное соединение, независимое от IRC TLS, без криптографического подтверждения личности другой стороны. Предложение раскрывает объявленный IPv4-адрес; принятие раскрывает другой стороне IP-адрес получателя. Перед каждым принятием проверьте отправителя, сетевую точку, нужный файл и размер в байтах.

Входящее предложение не открывает файл или сокет до явного подтверждения. Действие Accept в списке открывает форму проверки с Directory/Save as и Edit/Accept/Cancel. Enter в поле лишь подготавливает значение; только Accept в форме запускает передачу. Вставка текста действует лишь в активном редакторе и не может подтвердить предложение. Reject ничего не создаёт.

В полном интерфейсе предлагаемый каталог приёма — $XDG_DATA_HOME/vipirc/downloads, если путь абсолютный; иначе $HOME/.local/share/vipirc/downloads, если HOME абсолютный. Если ни один не подходит, явно укажите путь. Отсутствующие родительские каталоги создаются с правами 0700 только после Accept. Последний родительский каталог должен принадлежать пользователю и быть закрытым; новый файл создаётся с правами 0600. Существующие файлы, символьные ссылки и '..' отвергаются. Имя файла должно быть видимым, не скрытым, без разделителей пути, управляющих символов, символов управления направлением письма или кавычек. Имя в кавычках на уровне протокола может содержать пробелы. Неудачные или отменённые частичные файлы удаляются лишь пока это тот же первоначально созданный файл, а не подменённый объект.

Send... открывает поля Nickname, Source file, Advertised IPv4, Listen port и действия Edit/Browse, Offer, Cancel. Для личного диалога адресат предлагается по умолчанию; форма показывает IRC-сервер. Только Offer запускает прослушивание порта и ставит предложение в очередь отправки через этот зарегистрированный сервер с ограничением темпа. Источник должен быть существующим обычным файлом, без символьных ссылок и '..'. Порт 0 выбирает свободный порт; явно заданные порты должны быть в диапазоне 1..65535. При NAT может понадобиться доступный извне объявленный IPv4 и перенаправление порта; UPnP и внешние службы определения адреса не вызываются.

Browse начинает работу в каталоге запуска: стрелки выбирают элемент, Enter открывает каталог или выбирает файл, parent/Backspace поднимается вверх, Type path принимает абсолютный путь к файлу, Escape отменяет действие без изменения источника. Выбор лишь заполняет форму, не отправляет предложение и не меняет cwd процесса. За один проход проверяется не более 64 записей; список хранит 512 и прекращает обход после 4096 проверенных. Для пропущенных записей используйте Type path. Символьные ссылки и опасные имена исключаются; метаданные повторно проверяются при выборе и отправке предложения.

    /dcc alice file.txt
    /dcc send -address 203.0.113.10 -port 5000 alice file with spaces.txt
    /dcc list
    /dcc accept 1 /home/me/private-downloads
    /dcc reject 2
    /dcc cancel 3

Замените демонстрационный IP доступным адресом. PATH в команде — буквальный остаток строки, включая пробелы, без кавычек оболочки. Относительные пути отсчитываются от cwd при запуске даже после ухода в фон или открытия обозревателя. По умолчанию объявляется локальный IPv4 IRC-сокета; для IRC-соединения только через IPv6 необходим явный IPv4, а при NAT он также может потребоваться. Команда accept без DIRECTORY использует исходный cwd и те же проверки закрытости каталога. Простая /dcc показывает список в минималистичном режиме. Оба интерфейса используют общий менеджер, ограничения и отмену.

При работе через SSH все пути, адреса и соединения относятся к хосту, на котором запущен vipirc, а не к локальному компьютеру с терминалом. Принятые передачи продолжаются при переключении чатов и экранов, а также после IRC Disconnect. Закрытие исходного сервера отменяет его передачи, выход из программы останавливает все. Ошибка, отмена или истечение срока удаляет предложение из очереди, но не может отозвать уже отправленное или отправляемое.

Ограничения рабочего пространства: 8 ожидающих предложений, 4 активные/прослушивающие/подключающиеся передачи и 12 сохранённых записей. Только при заполнении в первую очередь переиспользуются самые старые завершённые или неудачные записи; ID не повторяются в пределах одного запуска. Предложения истекают через 5 минут, передачи останавливаются после 2 минут без прогресса. Передача потока использует ограниченные буферы и накопительные 32-битные подтверждения. В тестовом режиме можно просмотреть/отклонить/отменить образец из памяти; Send/Accept отклоняются до любых файловых или сетевых операций.
