ФАЙЛЫ И ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ

Пути к основной конфигурации по умолчанию:

    $XDG_CONFIG_HOME/vipirc/config.ini
    $HOME/.config/vipirc/config.ini

Непустая XDG_CONFIG_HOME имеет приоритет и должна содержать абсолютный путь. HOME служит запасным вариантом; если HOME не даёт абсолютного домашнего каталога, используется информация базы пользовательских учётных записей. --config FILE выбирает другую основную конфигурацию и соседнее хранилище профилей серверов. Пути, записанные в конфигурации, используются буквально: без раскрытия переменных, тильды или оболочки. Переменные выше лишь поясняют выбор путей по умолчанию. Однако сама оболочка по-прежнему выполняет обычную обработку кавычек и подстановок до передачи аргументов командной строки.

Для основного пути P файл P.servers хранит идентификаторы профилей и необязательный выбор [servers] default=PROFILE_ID, управляемый /saveconf. В P.d/ находятся файлы дополнительных профилей. Каждая сохранённая конфигурация может иметь файл .commands со счётчиками канонических команд и необязательный журнал .log. Созданные конфигурации и дополнительные профили требуют явного Save; счётчики принятых команд автоматически обновляются в уже сохранённом хранилище. Если запомненный профиль по умолчанию отсутствует или недоступен для чтения, выводится ошибка; подключение не перенаправляется молча.

Полный интерфейс предлагает $XDG_DATA_HOME/vipirc/downloads как каталог приёма DCC по умолчанию, если XDG_DATA_HOME абсолютна; иначе предлагает $HOME/.local/share/vipirc/downloads при абсолютной HOME. Предложенный каталог создаётся только после явного согласия. Команда /dcc accept NUMBER без DIRECTORY использует каталог, из которого запущен процесс; он должен принадлежать пользователю и быть закрытым для посторонних. Выбор или просмотр пути не меняет этот каталог запуска.

PATH используется для поиска необязательной программы gpg. Оболочка не запускается; исполняемая программа входит в доверенную локальную среду. GNUPGHOME интерпретируется GnuPG как среда ключей и агента. Клиент не подставляет GNUPGHOME в пути к учётным данным. При удалённой работе по SSH используются окружение и файлы той машины, где работает vipirc.

TERM описывает возможности терминала для ncurses, но не кодировку текста. LANG, LC_CTYPE и LC_ALL выбирают локаль. Для редактирования Unicode и правильной ширины символов нужна установленная локаль UTF-8, соответствующая терминалу. Команды locale, locale charmap и locale -a помогают проверить систему; имена локалей различаются.

Язык интерфейса: при запуске vipirc установите VIPIRC_LANG в id (индонезийский), ms (малайский), tr (турецкий), es (испанский), pt (португальский), fr (французский), de (немецкий), ru (русский), it (итальянский) или ar (арабский). Поддерживаются также значения вида id_ID.UTF-8. Режимы ncurses и -i используют один каталог. Если перевод недоступен, применяется английский. Отсоединённый рабочий процесс сохраняет язык, выбранный при его запуске. Команды IRC с косой чертой, ключи конфигурации и управляющие значения остаются английскими. В этой версии переведены отдельные элементы интерфейса, но не все страницы справки, предупреждения безопасности и ошибки. См. doc/LOCALIZATION.md.

Активное LC_CTYPE учитывается. Некорректная локаль или локаль не в UTF-8 включает явный режим терминала ASCII, указанный на экране приветствия. Ввод не-ASCII отклоняется с сообщением; входящие символы не-ASCII отображаются как '?' без изменения сохранённого сетевого текста. Клиент не угадывает и не перекодирует старые кодировки и не принуждает использовать локаль. Для Unicode выберите установленную локаль UTF-8 и перезапустите программу. ASCII остаётся однобайтным подмножеством UTF-8; SSH не меняет ограничения IRC на число байтов.
