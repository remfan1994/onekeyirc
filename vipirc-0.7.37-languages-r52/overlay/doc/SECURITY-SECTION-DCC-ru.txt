Классическая активная передача DCC SEND по IPv4 идёт открытым текстом без аутентификации независимо от TLS соединения IRC. Ник не подтверждает личность подключающейся стороны. Показанный адрес может быть частным или loopback. При отправке объявляется адрес; при принятии предложения клиент соединяется с указанной стороной и раскрывает адрес хоста, где работает процесс. Одно предложение не создаёт файл или сокет. Для Accept/send требуется явное действие. При работе через SSH файлы и сокеты находятся на удалённом хосте процесса.

Источником должен быть обычный файл, ни один компонент пути не может быть symlink. Файл передаётся потоком, без создания неизменяемого снимка и без защиты от последующих изменений; используйте стабильный источник. Приём создаёт новый файл с правами 0600 в частном каталоге, принадлежащем пользователю, отвергая выход за пределы пути, символьные ссылки и уже существующие цели. Очистка частично полученного файла удаляет только файл с теми же устройством и inode, который создала передача. Файлы никогда не открываются и не исполняются автоматически. Подтверждения числа байтов не являются хешами.

Допускается восемь ожидающих предложений, четыре активные передачи и двенадцать сохранённых записей; максимальный размер файла равен 4294967295 байтам. Предложения истекают через пять минут; активная передача завершается ошибкой после двух минут без прогресса. Повторные одинаковые подтверждения не продлевают этот срок. DCC CHAT, resume, пассивная/обратная передача, файлы неизвестного размера и IPv6 не поддерживаются. Обнаружения публичного адреса или автоматической настройки NAT/firewall нет. Разрыв IRC-соединения не останавливает уже принятые прямые передачи; закрытие соответствующего сервера или выход останавливает их. /cancel не заменяет отдельную отмену передачи.
