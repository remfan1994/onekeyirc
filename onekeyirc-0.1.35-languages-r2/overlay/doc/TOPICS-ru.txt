vipirc / onekeyirc - help topics (ru)
========================================

Commands and option tokens stay in English. Refer to MANUAL.txt and SECURITY.md for exact details.

AUTHENTICATION
--------------
Используйте проверенный TLS: /autoauth sasl USER file PATH или /autoauth sasl USER gpg PATH.

Параметры входа действуют при следующем /connect после отключения; /save сохраняет их.

BOUNCERS (ZNC / soju)
---------------------
Откройте /panel, выберите сервер, затем тип соединения znc или soju.

Сохраните профиль для каждой сети за бунсером. При общем адресе перед /connect выберите нужный профиль.

Бунсер восстанавливает каналы. Локальный /autojoin не повторяется и не меняется; используйте /join и /part.

Клиент подключается только к бунсеру. TLS, вход и хранение на верхнем сервере настраиваются отдельно.

SESSION RECOVERY
----------------
В оболочке выполните --sessions. Проверьте статус и номер задания, а не PID процесса.

Если старый SSH-терминал держит задание: --detach-session NUMBER, затем --resume NUMBER. IRC продолжит работу.

--close-session NUMBER завершает весь job, соединения IRC и передачи. Черновики и история RAM пропадут; настройки и старые логи сохранятся.

TLS
---
Проверенный TLS включен по умолчанию. Имя/адрес и цепь сертификатов должны пройти проверку; отката на plaintext нет.

Порт не отключает TLS. --plain или /connect -plain выбирает IRC без шифрования и без учетных данных.

--check-config не проводит TLS-рукопожатие и не проверяет работу CA или источника учетных данных. --test-mode не соединяется с сервером.

TLS защищает лишь этот канал связи. TLS и история plaintext на бунсере управляются отдельно.

LOGGING
-------
Дисковый журнал необязателен и выключен. /set persistent_logging on включает; /save output сохраняет.

Журналы - plaintext, не шифрованные копии. Лимит 16 MiB на файл; ошибка записи останавливает журнал, не чат.

/clear очищает лишь RAM. Журналы остаются после выхода, --close-session и сохранения. Выключение записи останавливает новые записи, не удаляя старые.

RECONNECT
---------
--reconnect включает повторы для процесса, но не сохраняет настройки и не запускает соединение.

Сообщения в очереди при разрыве теряются и автоматически не повторяются.

TROUBLESHOOTING
---------------
Занято после сбоя SSH? --sessions, проверка задания, --detach-session NUMBER, --resume NUMBER. Не используйте --close-session. See /help sessions.

Каналов нет? Проверьте сервер и вход. Прямой профиль: /autojoin list; бунсер: /join или /part.

Ошибка входа? Проверьте аккаунт, источник, права, TLS, агент GPG. /autoauth status не читает секреты.

Изменения не видны? Нужен /connect после разрыва. Сохранение не включает autoconnect; запуск требует нового процесса.

Используйте --check-config и doc/TROUBLESHOOTING.txt. --test-mode проверяет экран, не DNS, TLS, секреты и бунсер.
