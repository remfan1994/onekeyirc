Практическое руководство vipirc / onekeyirc
===========================================

ЧЕРНОВОЙ ПЕРЕВОД. Пишите команды и параметры точно как показано.
Точные правила безопасности - в английских MANUAL.txt и SECURITY.md.

/help startup
-------------

Запустите программу, закройте приветствие и введите /connect irc.example.org, затем /join #channel.

Создавать профиль сервера, псевдоним или номер заранее не нужно. /server HOST — синоним прямого подключения.

Без ника используется допустимое системное имя входа, иначе user. Ввод ника не запрашивается.

Сохраните настройки и выбранное значение по умолчанию через /saveconf. При следующем запуске /connect их использует.

Сохранение не включает автоподключение: его выбирают отдельно. /quickstart и /panel — необязательные подсказки.

Работают и параметры оболочки: --server HOST, --channel '#CHANNEL', --nick NICK. В оболочке заключайте #CHANNEL в кавычки.

При запуске --nick, --port, --channel, --tls, --plain и --ca-file заменяют сохранённые значения по умолчанию.

Явный --server выбирает первое подключение. --init-config и --check-config используют основной файл настроек.

Смена хоста через --server удаляет старые учётные данные, настройку CA, данные баунсера, каналы и стартовые команды.

Если сохранённый сервер недоступен, укажите --server либо исправьте его до изменения параметров подключения.

Autoconnect, autojoin и autoauth настраиваются для каждого профиля сервера. См. /help autoconnect.

--no-connect блокирует подключение при запуске; --test-mode имитирует работу без сети и записи настроек.

--sessions выводит присоединённые и отсоединённые задания. --resume [NUMBER] присоединяет снова; см. /help background.

--close-session NUMBER завершает всё задание и его соединения IRC с подтверждением. NUMBER — ID задания, не PID.

После потери терминала: --sessions, затем --detach-session NUMBER и --resume NUMBER. Рабочий процесс сохраняет старый код до перезапуска; см. /help sessions.

-h/--help и -v/--version работают без терминала.

/help messages
--------------

Используйте /join #channel для входа в канал и его выбора или /query NICK для личной беседы.

Выберите сохранённый канал через /channel. /msg TARGET TEXT отправляет адресату, /me TEXT — действие.

/query открывает беседу без отправки; /pm — псевдоним. /ql отделяет личные беседы от каналов.

Прямая отправка — по умолчанию; /set send_mode review добавляет проверку. /set composer_mode line|fullscreen меняет вид.

При достижении лимита одного сообщения подтвердите продолжение ввода. Разделение требует отдельного согласия.

До постановки сообщения в очередь нужно войти в канал и пройти аутентификацию. /cancel отменяет очередь, но не отправленное.

/help limits
------------

Лимиты IRC считаются в байтах, а не в символах на экране. Символ UTF-8 может занимать несколько байтов.

Клиент учитывает адресата, команду и накладные байты ретрансляции; символ UTF-8 не разрывается.

При лимите одного сообщения ввод блокируется до подтверждения продолжения через Enter; Enter ничего не отправляет.

Для нескольких частей нужно отдельное согласие даже в прямом режиме. Чат отправляет строку каждые 1.2 секунды.

За раз допускается не более 64 сообщений и 16384 байтов текста. Сократите текст или отправьте частями.

Доступно не более 8 слотов серверов и 32 видов на сервер, включая служебные.

/help quickstart
----------------

По очереди измените сервер, транспорт TLS, порт и ник текущего профиля, затем проверьте настройки.

По умолчанию используется проверенный TLS. Открытое соединение нужно выбирать явно.

Enter сохраняет показанное. Escape возвращает на вопрос; повторите для выхода без изменений. Ответы не входят в историю команд.

В конце выберите: 1 Сохранить и войти, 2 Только сохранить, 3 Войти раз (по умолчанию), 4 Только применить.

Открытие мастера и ранние ответы ничего не применяют, не сохраняют и не подключают.

Войти раз - применить без записи; Только применить - без записи и соединения. Живое соединение не меняет цель и не переподключается скрыто.

Неудачное подключение не отменяет уже примененные или сохраненные изменения.

Для профилей bouncer и других настроек откройте /panel. Quickstart не меняет существующий вход bouncer.

/help save
----------

/save без аргументов пишет настройки выбранного сервера, включая отложенные изменения соединения.

/save input и /save output сохраняют весь основной профиль, предпочтения и подготовленное соединение, а не только указанную часть.

/save all пишет каждый исправный профиль отдельно. При ошибке прежние файлы остаются; о сбое сообщается.

Замена каждого файла приватна и атомарна, но это не общая транзакция. Тестовый режим не пишет настройки.

/help documentation
-------------------

Найдите задачу через /help ls; /help commands объясняет ввод и список команд. Указывайте одну тему или команду.

/help COMMAND показывает синтаксис, действие и примеры. /help /ls объясняет локальный список; /help ls выводит темы.

/help all или /manual открывает справочник. --help описывает запуск; вывод --manual в простом режиме можно записать в файл.

README.md указывает документы, MANUAL.txt описывает интерфейс, INSTALL - сборку. Страница man объясняет вызов из shell.

CONTRIBUTING.md - изменения, doc/SOURCE-MAP.txt - код, tests/README.md - тесты. DESIGN.md описывает порядок и ответственность.

doc/TROUBLESHOOTING.txt - помощь по симптомам. SECURITY.md - угрозы; doc/BOUNCERS.txt и doc/SESSION-CONTROLS.txt - операции. Аудит применим лишь к указанным версиям и средам.

/help security
--------------

Удалённый текст очищается перед выводом в терминал. Ввод трактуется как локальные команды IRC, а не команды оболочки.

Нет /raw, выхода в оболочку и автоматического приёма файлов. Распознанная вставка в скобках не выполняет команду.

TLS проверяет сервер. SASL, PASS и распознанные личные команды входа требуют проверенный TLS. Обновляйте библиотеку TLS; см. SECURITY.md.

Свой пакет CA должен быть непустым обычным файлом PEM размером до 16 MiB; пароль не запрашивается.

Пароли скрыты в справке и настройках. Известные команды с паролями не попадают в повтор команд; секреты в обычном тексте могут сохраниться.

Запись бесед на диск по умолчанию выключена. Изменения конфигурации нужно явно сохранять.

Другие процессы аккаунта, сервер IRC или bouncer и взломанный терминал или ОС вне этих гарантий. TLS не обеспечивает сквозное шифрование чата.

Логи и секреты в настройках - открытый текст. Известные чувствительные команды фильтруются; тайные данные в чате надежно не распознать.

См. /help tls, /help authentication, /help logging и SECURITY.md: ограничения и прошлые проверки.

/help sessions
--------------

Job - один процесс клиента: серверы, передачи, черновики и история. Номер сервера в программе - не shell job ID.

В оболочке выполните --sessions. Проверьте статус и номер задания, а не PID процесса.

Если старый SSH-терминал держит задание: --detach-session NUMBER, затем --resume NUMBER. IRC продолжит работу.

--resume без номера работает при одном отключенном job. Для нескольких нужен номер. Подключенный занят до отключения; номера могут повторяться.

--close-session NUMBER завершает весь job, соединения IRC и передачи. Черновики и история RAM пропадут; настройки и старые логи сохранятся.

Закрытие подтверждается после очистки. При тайм-ауте проверьте --sessions: завершится позже. Ошибка не удаляет адрес и не шлет сигнал чужому PID.

Лишь управляемый job переживает потерю терминала. Процесс на переднем плане не вернуть после обрыва SSH. Сначала --background или /background.

Job принадлежит одному Unix аккаунту и хосту; подключен один терминал. Другие программы того же аккаунта входят в границу доверия.

Установка бинарника не меняет код работающего процесса. Сохраните настройки, остановите старый, проверьте --version и запустите новый.

Старый worker может не знать новые команды или смену интерфейса. При необходимости сохраните совместимый бинарник до остановки worker.

Клиент не меняет тайм-аут бездействия SSH. См. /help background, /help deployment и doc/SESSION-CONTROLS.txt.

/help troubleshooting
---------------------

Занято после сбоя SSH? --sessions, проверка задания, --detach-session NUMBER, --resume NUMBER. Не используйте --close-session. See /help sessions.

Up не возвращает текст: Compose редактирует, Command повторяет команды. Откройте Command через / из лога. Чат и секретные команды не повторяются.

Если текст будто обрезан: редактор занял строки, видны последние. Выйдите или смените канал; видимый текст не доказывает доставку.

Если при смене канала текст полон, дело в окне. При сбое запишите интерфейс, режим, размер, locale и чистые шаги; без паролей и личного чата.

Каналов нет? Проверьте сервер и вход. Прямой профиль: /autojoin list; бунсер: /join или /part.

Ошибка входа? Проверьте аккаунт, источник, права, TLS, агент GPG. /autoauth status не читает секреты.

Нет catch-up: метка могла устареть, лог включился позже, выключился или изменился. См. /help catchup и /help logging; логи не возвращают умерший worker.

Изменения не видны? Нужен /connect после разрыва. Сохранение не включает autoconnect; запуск требует нового процесса.

Если запуск помощника не удается, исправьте SIGCHLD или автоочистку дочерних процессов у запускающей программы, чтобы клиент мог их дождаться.

Используйте --check-config и doc/TROUBLESHOOTING.txt. --test-mode проверяет экран, не DNS, TLS, секреты и бунсер.

/help bouncers
--------------

Откройте /panel, выберите сервер, затем тип соединения znc или soju.

Введите хост и порт TLS баунсера, пользователя, существующую сеть upstream и необязательное постоянное имя клиента.

Сохраните профиль для каждой сети за бунсером. При общем адресе перед /connect выберите нужный профиль.

Клиент формирует имя входа. ZNC берет пароль сервера, soju - пароль авторизации. Вводите лишь пароль bouncer, не общий логин и не пароль NickServ.

Бунсер восстанавливает каналы. Локальный /autojoin не повторяется и не меняется; используйте /join и /part.

Явные команды запуска всё ещё выполняются. Проверьте их перед включением профиля во избежание повторных join и команд служб.

Авто-away при простое/в фоне отключён у баунсера, пока не включён отдельно. Ручные /away и /back работают.

История сохраняет время UTC сервера, направляет личные сообщения адресату; не создает упоминаний, CTCP/DCC и не меняет текущее состояние.

История ограничена. Нет поиска архива по запросу, автообнаружения сетей и создания профилей для каждой сети.

/znc или /soju без аргументов - справка службы. Управляющие тексты не входят в историю или эхо; ответы видны на сервере без постоянного лога.

Известные копии исходящих команд скрыты и при replay со старым ником. Набранный текст может быть виден; у bouncer своя политика логов.

Клиент подключается только к бунсеру. TLS, вход и хранение на верхнем сервере настраиваются отдельно.

О настройке и пределах проверки см. doc/BOUNCERS.txt и примеры баунсеров в examples/.
