onekeyirc справка по командам
Темы справки: /help ls.
Список команд: /help commands. Подробно: /help COMMAND.
Первое подключение: /connect irc.example.org, затем /join #channel.
Личная беседа: /query NICK или /msg NICK TEXT.
Мастер настройки: /quickstart или /panel.
Сохранить настройки: /saveconf. Это не включает autoconnect.
Переключение экранов: /servers, /channels, /ql.
Настройки запуска: /help autoconnect, /help autojoin, /help autoauth.
Восстановить сессии SSH: /help sessions.
Инструкция по bouncer: /help bouncers.
Настройки и клавиши: /help configuration, /help hotkeys.
Проблемы и безопасность TLS: /help troubleshooting, /help security, /help tls.
История и журналы: /help history, /help logging.
Выбор языка: /help language.
Полная справка: /help all или /manual.
Escape закрывает справку; / открывает Команды.

aliases
-------
Альтернативные имена должны совпадать точно; неоднозначные или приблизительные команды не выполняются.
/conn = /connect; /disc = /disconnect; /detach = /background; /exit = /quit
/j = /join; /leave = /part; /message и /privmsg = /msg
/nickname = /nick; /names и /nicks = /users; /unaway = /back
/channellist = /cl; /querylist = /ql; /serverlist = /servers
/configure и /preferences = /panel; /saveconfig = /saveconf
/autocommand = /autocommands
Автодополнение предлагает канонические имена; аргументы не меняются, фильтрация секретов в истории сохраняется.

authentication
--------------
Используйте проверенный TLS: /autoauth sasl USER file PATH или /autoauth sasl USER gpg PATH.
Учётные данные берутся из файла пароля или расшифровки GPG; пути указаны буквально.
Через /panel создайте шифрованный секрет GPG для существующего локального отпечатка открытого ключа.
Нужен уже разблокированный ключ GPG. pinentry не запускается в редакторе чата.
В приватном конфиге возможны также открытые password= и server_password=.
Для каждых учётных данных нужен один источник. /settings и /summary скрывают пути файлов.
/autoauth status показывает текущие и ожидающие пути, не читая файлы и не раскрывая пароли.
Параметры входа действуют при следующем /connect после отключения; /save сохраняет их.
Для баунсера вход и источник вместе задаются в /panel; изменения /autoauth запрещены.
Файлы должны быть обычными, принадлежать владельцу, иметь режим 0600 или 0400. Ссылки и выход к родителям запрещены.
Лимит SASL: 1024 байта; обычный PASS: 503 байта. Составной логин ZNC должен уместиться в строку IRC.
--check-config проверяет конфиг и источник, но не читает секреты и не проверяет вход. См. /help tls и /help bouncers.

bouncers
--------
Откройте /panel, выберите сервер, затем тип соединения znc или soju.
Введите хост и порт TLS баунсера, пользователя, существующую сеть upstream и необязательное постоянное имя клиента.
Сохраните профиль для каждой сети за бунсером. При общем адресе перед /connect выберите нужный профиль.
Клиент формирует имя входа. ZNC берет пароль сервера, soju - пароль авторизации. Вводите лишь пароль bouncer, не общий логин и не пароль NickServ.
Бунсер восстанавливает каналы. Локальный /autojoin не повторяется и не меняется; используйте /join и /part.
Явные команды запуска всё ещё выполняются. Проверьте их перед включением профиля во избежание повторных join и команд служб.
Авто-away при простое/в фоне отключён у баунсера, пока не включён отдельно. Ручные /away и /back работают.
История сохраняет время UTC сервера, направляет личные сообщения адресату; не создает упоминаний, CTCP/DCC и не меняет текущее состояние.
История ограничена. Нет поиска архива по запросу, автообнаружения сетей и создания профилей для каждой сети.
/znc или /soju без аргументов - справка службы. Управляющие тексты не входят в историю или эхо; ответы видны на сервере без постоянного лога.
Известные копии исходящих команд скрыты и при replay со старым ником. Набранный текст может быть виден; у bouncer своя политика логов.
Клиент подключается только к бунсеру. TLS, вход и хранение на верхнем сервере настраиваются отдельно.
О настройке и пределах проверки см. doc/BOUNCERS.txt и примеры баунсеров в examples/.

configuration
-------------
Файл конфигурации по умолчанию: $XDG_CONFIG_HOME/onekeyirc/config.ini; XDG_CONFIG_HOME должен быть абсолютным путём.
Если XDG_CONFIG_HOME не задан или пуст: $HOME/.config/onekeyirc/config.ini. --config FILE выбирает другой файл.
Если нового файла по умолчанию нет, существующий 1keyirc/config.ini под тем же базовым каталогом конфигурации используется на прежнем месте.
Существующие настройки, каталоги серверов и пути учётных данных не перемещаются. Если есть оба файла, приоритет имеет файл по умолчанию onekeyirc.
О небезопасном или нечитаемом файле по умолчанию сообщается вместо молчаливого выбора другого. --config FILE переопределяет этот выбор.
[history] lines= задаёт предел сохраняемой истории чата. Конфигурация не содержит параметров [interface].
[connection] содержит server, port, tls, nick, username, realname, channel, autoconnect, auth и источники учётных данных.
[bouncer] type=none|znc|soju, username, network, client и automatic_away задают bouncer-профиль сети; см. /help bouncers.
[input] send_mode=direct|review и [output] format=compact|full, queue_notices=true|false, program_messages=true|false, persistent_logging=true|false - параметры основного файла.
[input] command_suggestions=common|history|frequent|alphabetical|contextual задаёт порядок команд; по умолчанию common.
[input] composer_mode=line|fullscreen выбирает ввод/команды в простом интерфейсе; обычно line. Оба показывают новые сообщения.
[input] use_signals=false отключает сигналы терминала, пока клиент управляет tty. true включает прежние назначения сигналов. «Применить» действует сразу; «Сохранить» сохраняет настройку в основной конфигурации.
[hotkeys] содержит до 64 необязательных KEY=action без значений по умолчанию. Основной файл; см. /help hotkeys.
[session] single_session=true|false разрешает несколько фоновых заданий; по умолчанию false.
[session] default_interface=ncurses|idle - настройка главного профиля. Варианты запуска описаны ниже.
Формат compact задан по умолчанию. history_lines в главном файле ограничивает историю всех серверов.
[mentions] word= и [ignore] mask= можно повторять.
[autocommands] хранит enabled, delay_seconds, interval_seconds и повторяемые строки command= для сервера.
Текст команд хранится открыто в закрытом файле. /autocommands скрывает секреты в списках и истории.
Дополнительные серверы сохраняются в соседнем каталоге .servers и папке .d.
Подключитесь через /connect HOST, затем /join #channel и /saveconf для сохранения рабочей настройки.
/saveconf сохраняет предпочтения, исправные профили и выбранный сервер для следующего /connect без аргументов.
/quickstart задаёт четыре вопроса. /panel: 0 - настройки, 1..8 - профили; панель 1 меняет основной.
Правки панели скрыты до «Готово». Путь GPG может создать каталог 0700; шифрование, запись и подключение ждут последнего выбора.
Для сохранения: /save - выбранный сервер; /save input или /save output - основной; /saveconf - исправные профили и выбор.
Счётчики команд читаются и пишутся в <config_path>.commands; главный конфиг их не содержит.
Закрытый ограниченный файл хранит только имена команд и счётчики, без аргументов и истории. Тестовый режим его не читает и не пишет.
Правки [connection] через /autojoin или /autoauth действуют при следующем отключённом /connect, не меняя текущий сеанс.
Файлы конфигурации закрыты; каждый заменяется атомарно, но не вся группа одной транзакцией. Импорта/экспорта нет.
Неизвестные разделы, ключи и значения - ошибки. Значения буквальные, без кавычек shell, экранирования, переменных и ~.
Обычные значения обрезаются по краям. password= и server_password= хранят всё после = до конца строки; без кавычек и комментариев.
Сохранение перезаписывает настройки и удаляет ручное форматирование/комментарии. Заметки храните отдельно.
Секреты: /help authentication; CA: /help tls; дисковые логи: /help logging; активные процессы: /help sessions.
onekeyirc всегда использует idle. В его панели приложения нет выбора интерфейса; /set default_interface принимает только idle.
Общий анализатор конфигурации сохраняет любое из двух распознаваемых записанных значений. Сохранённое значение ncurses не меняет интерфейс этого отдельного клиента.

deployment
----------
Для запуска сеанса без терминала и приветственного нажатия используйте --background.
Настройте и сохраните /autoconnect on для каждого запускаемого сервера.
--background сам не включает autoconnect; --no-connect по-прежнему запрещает соединения при запуске.
Предупреждение выводится один раз до отсоединения. Успех означает локальное задание, а не вход на IRC.
В другом терминале той же учётной записи используйте --sessions и --resume [NUMBER].
--sessions включает присоединённые задания. --detach-session NUMBER отсоединяет терминал без завершения задания, позволяя продолжить в другом месте. --close-session NUMBER завершает выбранное задание и все соединения IRC.
Используйте указанный ID задания, а не PID. Неотвечающие рабочие процессы и старые версии без нужной команды управления могут завершить запрос ошибкой. Восстановление и обновление: /help sessions.
Перезапуск VPS завершит задания, черновики и историю в RAM. Системная задача может запустить новый клиент.
Инструкции OpenBSD и необязательный пример rc.d: doc/OPENBSD-VPS.txt.
Запускайте как обычный пользователь с абсолютными путями конфигурации и секретов. Ключ GPG не сможет запросить ввод при загрузке.
--check-config проверяет настройки, но не доступ к секретам, DNS, TLS или вход на IRC.
Для временных сбоев сети используйте --reconnect; контроль падения процесса выполняет ОС отдельно.
Запускающая программа должна позволять ожидание дочерних процессов: игнорирование SIGCHLD или автоматический сбор их статуса нарушает первый фоновый запуск, создание резолвера или помощника учётных данных. Управляемое повторное отсоединение не создаёт нового рабочего процесса.

documentation
-------------
Найдите задачу через /help ls; /help commands объясняет ввод и список команд. Указывайте одну тему или команду.
/help COMMAND показывает синтаксис, действие и примеры. /help /ls объясняет локальный список; /help ls выводит темы.
/help all или /manual открывает справочник. --help описывает запуск; вывод --manual в простом режиме можно записать в файл.
README.md указывает документы, MANUAL.txt описывает интерфейс, INSTALL - сборку. Страница man объясняет вызов из shell.
CONTRIBUTING.md - изменения, doc/SOURCE-MAP.txt - код, tests/README.md - тесты. DESIGN.md описывает порядок и ответственность.
doc/TROUBLESHOOTING.txt - помощь по симптомам. SECURITY.md - угрозы; doc/BOUNCERS.txt и doc/SESSION-CONTROLS.txt - операции. Аудит применим лишь к указанным версиям и средам.

history
-------
История сообщений и команд ограничена в RAM. Постоянные журналы необязательны и по умолчанию отключены.
При смене вида показываются последние записи; /mentions показывает совпадающие исходные строки.
Настройка истории приложения ограничивает общее число записей всех серверов и представлений; изменяйте её через /panel, затем 0.
Сохраняется не более меньшего из заданного значения и 2048 записей; отдельно действует жёсткий предел 512 KiB в байтах.
/catchup в канале или личной беседе начинает с последнего составленного вами сообщения, отправленного локально. Сначала пробует подходящий закрытый журнал, затем сохранённую память; /help catchup объясняет оба режима чтения.
Постоянное восстановление пропущенного раздельно для каждого сервера и беседы. При отправке опорного сообщения запись журнала уже должна быть включена: это закрытый журнал открытого текста до 16 MiB на сохранённый профиль, без шифрования.
История команд хранит до 64 записей и 64 KiB, удаляя самые старые. /clear очищает историю беседы, а не историю команд.
Подсказки Недавняя история используют эти полные строки. Delete удаляет выбранную строку истории.
Подсказки Самые частые используют до 96 канонических имён команд и ограниченные счётчики в <config_path>.commands.
При сохранённой конфигурации принятые команды и сбросы частоты автоматически обновляют этот закрытый файл. Аргументы, адресаты и сообщения в нём не сохраняются.
Несохранённые профили держат счётчики в памяти до первого успешного Сохранить. Отсутствующие или непригодные файлы счётчиков не мешают запуску.
Справка и многострочные ответы команд используют отдельный читатель с буфером до 512 KiB. Они не становятся историей чата.
Принятые команды можно вызвать из истории в редакторе команд. Изменения аутентификации, входы в канал с ключом и конфиденциальные служебные сообщения пропускаются.
Up/Down в Compose двигает курсор, не возвращает отправленный чат. В Command возвращаются только принятые команды.
Отсоединение/возобновление с тем же интерфейсом сохраняет черновики и историю команд. Поддерживаемое переключение интерфейсов удаляет их и формы настройки; выход или перезагрузка также удаляет чат в памяти и опорные точки восстановления пропущенного.
Сохранённые счётчики частоты содержат только имена. Старые журналы открытого текста переживают выход, но не импортируются автоматически в новый сеанс или редактор.
/clear удаляет историю вида из RAM, но не старый журнал на диске. Повтор bouncer предоставляет сам bouncer.
Предел истории приложения по умолчанию — 100 записей.

hotkeys
-------
Этот клиент редактирует привязки через команды; /bindings выводит текущую таблицу.
Свои назначения клавиш необязательны и изначально пусты. Обычная навигация и редактор сохраняются.
Для списка: /bindings, клавиш: /bindings keys, функций: /bindings actions.
Назначьте через /bind KEY ACTION; повторное назначение заменит. Удалите через /unbind KEY или /unbind all.
Изменения сразу касаются всех серверов; /save input пишет их в основную конфигурацию. Доппрофили таблицу не меняют.
Формат: [hotkeys], затем по одной KEY=action на строку, до 64. Повторы, включая алиасы терминала, ошибочны.
Действуют лишь в основном чате и строке команд: не в паролях, настройке, вставке, читалке или подтверждениях.
В минимальном режиме просмотр сохраняет черновик и курсор. Смена экрана/редактора запрещена при черновике; завершите или очистите его.
Нет действия отправки, произвольных команд, shell или макросов. Фон и выход работают как обычно.
Доступны F1..F12, Ctrl-A..Z, Alt-a..z/0..9 и клавиши навигации; печатные символы остаются текстом.
Ctrl-H/Backspace, Ctrl-I/Tab, Ctrl-J/Ctrl-M/Enter и Ctrl-[/Escape имеют общие байты; разные привязки невозможны.
Сигналы терминала и сочетания мультиплексора главнее. Ctrl-C и Ctrl-Z действуют только если байт дошёл; клавиши не переназначаются.
Распознанная вставка с маркерами не запускает привязки. Вставку без маркеров нельзя отличить от ввода; см. /help keys.

keys
----
Журнал: / открывает Команда; ? объясняет выбранный журнал беседы/наблюдения. Другие печатные клавиши открывают Сообщение, сохраняя введённый символ.
Пользовательские привязки могут заменить эти действия в основном чате/Команда; по умолчанию привязок нет. См. /help hotkeys.
Текущий журнал: Up на строку назад, Page Up на страницу, Home к самой старой сохранённой странице. Down/Page Down/End оставляют текущий вывод; Left/Right/Delete/Backspace не открывают Сообщение.
Insert или Enter открывает пустое Сообщение. Стрелки, Home/End, Delete и Backspace редактируют текст. Tab/Shift-Tab дополняет ники в Сообщение и имена команд в Команда.
Однострочный режим ввода оставляет одну строку под текущим концом журнала; полноэкранный использует многострочный редактор с меньшей областью текущего журнала.
В Команда клавиша Down выбирает подсказки. Up/Down перемещается по ним; Up от первой возвращает ко вводу.
Enter на подсказке вставляет её без выполнения. Прочитайте/измените, затем после показа отдельно нажмите Enter для выполнения.
В Команда клавиша Up вызывает подходящие принятые строки истории; Down возвращает к исходному вводу. В Сообщение Up/Down двигает курсор, в том числе при удержании; Enter отправляет.
Delete удаляет выбранную строку Недавняя история или сбрасывает выбранный счётчик Самые частые. Команды каталога остаются доступны.
? на выбранной команде объясняет её и даёт ссылку на справку экрана команд. Во всех текстовых редакторах ? — обычный текст.
Проверка использует временный альтернативный экран; черновик/запрос никогда не входят в историю чата. Новое нажатие Enter подтверждает; Escape или ввод восстанавливает редактор/черновик/курсор. Просмотр: Up/Down, Page Up/Down и Home/End.
В справке/ответе Up/Down прокручивает; Page Up/Down меняет страницу; Home/End переходит в начало/конец.
В списке пользователей Enter возвращает к журналу; в справке и других читателях ответов Enter прокручивает одну строку.
В читателе / открывает Команда с обычным дополнением и историей. Escape отменяет этот ввод и возвращает в читатель.
В читателе сводки r обновляет снимок; ? объясняет ответ и его читатель.
В контекстной справке Enter открывает выделенную ссылку Об экране. Escape возвращает к справке элемента, затем точно на исходный экран.
В настройке Tab выбирает заголовок вопроса; ? объясняет параметр/экран. Tab/Enter возвращает к редактированию ответа.
Выполнение команды заменяет предыдущий ответ. Краткие подтверждения возвращают к журналу; краткие ошибки оставляют команду доступной для редактирования.
Escape отменяет редактор Сообщение/Команда и возвращает к журналу. Из Проверки Escape возвращает в редактор, сохраняя черновик. Escape в журнале переводит клиент в фон.
Одиночный Escape ждёт около 500 ms; начатая последовательность допускает 1000 ms между продолжающими байтами. Сеть продолжает работать.
Полные последовательности клавиш обрабатываются сразу. Если начальный маркер вставки задержится после своего первого Escape дольше этого срока, клиент может уйти в фон.
После начала захвата вставки её конечный маркер распознаётся даже при произвольно задержанных и разделённых чтениях.
Назначения клавиш прерывания, выхода и приостановки остаются прежними; «Использовать сигналы» = no отключает их сигналы, пока клиент активен.
[input] use_signals=false No (по умолчанию) отключает сигналы терминала на время работы программы; Ctrl-C/Ctrl-Z отменяют черновик. Yes включает существующие сопоставления клавиш сигналам, не изменяя их. Внешние сигналы процессу не блокируются ([input] use_signals=true).
Включённые терминальные сигналы завершают или приостанавливают после восстановления терминала; fg возобновляет приостановленное задание.
Ctrl-D не действует без привязки в основном чате/Команда. /quit завершает работу; /background освобождает терминал, сохраняя работу сети.
Обычные экраны не повторяют подсказки клавиш; эта тема остаётся полным справочником по клавиатуре.
Распознанная вставка с обрамлением остаётся буквальным текстом. Клавиши ждут видимого редактора, нового ввода и паузы. Крошечный/сбойный кадр не даёт подтверждения; измените размер и отпустите удерживаемые клавиши.
Вставка в журнал наблюдения открывает Сообщение с буквальными косыми чертами. Вставка в Команда остаётся там; CR/LF/Tab становятся пробелами. Проверьте, затем вновь нажмите Enter.
Вставка без обрамления неотличима от печати; используйте поддержку вставки с обрамлением.

limits
------
Лимиты IRC считаются в байтах, а не в символах на экране. Символ UTF-8 может занимать несколько байтов.
Клиент учитывает адресата, команду и накладные байты ретрансляции; символ UTF-8 не разрывается.
При лимите одного сообщения ввод блокируется до подтверждения продолжения через Enter; Enter ничего не отправляет.
Для нескольких частей нужно отдельное согласие даже в прямом режиме. Чат отправляет строку каждые 1.2 секунды.
За раз допускается не более 64 сообщений и 16384 байтов текста. Сократите текст или отправьте частями.
Доступно не более 8 слотов серверов и 32 видов на сервер, включая служебные.

logging
-------
Дисковый журнал необязателен и выключен. /set persistent_logging on включает; /save output сохраняет.
Профиль пишет в CONFIG_PATH.log. Родительский каталог: свой, 0700. Файл: обычный, свой, одна ссылка, строго 0600. Symlink и выход к родителям запрещены.
Журналы - plaintext, не шифрованные копии. Лимит 16 MiB на файл; ошибка записи останавливает журнал, не чат.
Полный лог уберите из активного пути и перезапустите запись. Ротация или перезапись портит якорь /catchup; отправьте новую подходящую запись.
Пароли и черновики исключены, даже при старых никах. Чат, неизвестные службы и свои секреты могут сохраниться. Сервер и bouncer хранят отдельно.
/catchup читает лог лишь с точным местным якорем, записанным этим процессом. Не берёт архив bouncer и старые логи после перезапуска.
/clear очищает лишь RAM. Журналы остаются после выхода, --close-session и сохранения. Выключение записи останавливает новые записи, не удаляя старые.
Медленный диск может задерживать процесс. См. /help catchup, /help history и SECURITY.md.

messages
--------
Используйте /join #channel для входа в канал и его выбора или /query NICK для личной беседы.
Выберите сохранённый канал через /channel. /msg TARGET TEXT отправляет адресату, /me TEXT — действие.
/query открывает беседу без отправки; /pm — псевдоним. /ql отделяет личные беседы от каналов.
Прямая отправка — по умолчанию; /set send_mode review добавляет проверку. /set composer_mode line|fullscreen меняет вид.
При достижении лимита одного сообщения подтвердите продолжение ввода. Разделение требует отдельного согласия.
До постановки сообщения в очередь нужно войти в канал и пройти аутентификацию. /cancel отменяет очередь, но не отправленное.

reconnect
---------
--reconnect включает повторы для процесса, но не сохраняет настройки и не запускает соединение.
Без этой опции неудачное соединение требует /connect. /autoconnect управляет только запуском.
Временные сбои DNS, отказ/потеря соединения и тайм-ауты повторяются через 5, 10, 20, 40, 80, 160, затем 300 секунд.
Регистрация на 60 секунд или дольше сбрасывает задержку. Опрос не применяет блокирующий сон.
Ошибки сертификата, входа, протокола и конфигурации оставляют соединение отключенным до исправления.
ERROR сервера до регистрации удерживается; после регистрации может вызвать повторное подключение.
Явный /disconnect отменяет ожидающий повтор. Позднее /connect начинает новую попытку.
Повторы используют текущие настройки; отложенные изменения по-прежнему требуют явного /connect.
Сообщения в очереди при разрыве теряются и автоматически не повторяются.
При новом соединении вход и команды запуска выполняются вновь. Прямые профили повторяют autojoin; баунсеры восстанавливают каналы.
Автономный тестовый режим никогда не соединяется с сетью повторно.

security
--------
Удалённый текст очищается перед выводом в терминал. Ввод трактуется как локальные команды IRC, а не команды оболочки.
Нет /raw, выхода в оболочку и автоматического приёма файлов. Распознанная вставка в скобках не выполняет команду.
TLS проверяет сервер. SASL, PASS и распознанные личные команды входа требуют проверенный TLS. Обновляйте библиотеку TLS; см. SECURITY.md.
Свой пакет CA должен быть непустым обычным файлом PEM размером до 16 MiB; пароль не запрашивается.
Пароли скрыты в справке и настройках. Известные команды с паролями не попадают в повтор команд; секреты в обычном тексте могут сохраниться.
Запись бесед на диск по умолчанию выключена. Изменения конфигурации нужно явно сохранять.
Другие процессы аккаунта, сервер IRC или bouncer и взломанный терминал или ОС вне этих гарантий. TLS не обеспечивает сквозное шифрование чата.
Логи и секреты в настройках - открытый текст. Известные чувствительные команды фильтруются; тайные данные в чате надежно не распознать.
См. /help tls, /help authentication, /help logging и SECURITY.md: ограничения и прошлые проверки.

sessions
--------
Job - один процесс клиента: серверы, передачи, черновики и история. Номер сервера в программе - не shell job ID.
В оболочке выполните --sessions. Проверьте статус и номер задания, а не PID процесса.
Если старый SSH-терминал держит задание: --detach-session NUMBER, затем --resume NUMBER. IRC продолжит работу.
--resume без номера работает при одном отключенном job. Для нескольких нужен номер. Подключенный занят до отключения; номера могут повторяться.
--close-session NUMBER завершает весь job, соединения IRC и передачи. Черновики и история RAM пропадут; настройки и старые логи сохранятся.
Закрытие подтверждается после очистки. При тайм-ауте проверьте --sessions: завершится позже. Ошибка не удаляет адрес и не шлет сигнал чужому PID.
Лишь управляемый job переживает потерю терминала. Процесс на переднем плане не вернуть после обрыва SSH. Сначала --background или /background.
Job принадлежит одному Unix аккаунту и хосту; подключен один терминал. Другие программы того же аккаунта входят в границу доверия.
Установка бинарника не меняет код работающего процесса. Сохраните настройки, остановите старый, проверьте --version и запустите новый.
Старый worker может не знать новые команды или смену интерфейса. При необходимости сохраните совместимый бинарник до остановки worker.
Клиент не меняет тайм-аут бездействия SSH. См. /help background, /help deployment и doc/SESSION-CONTROLS.txt.

startup
-------
Запустите программу, закройте приветствие и введите /connect irc.example.org, затем /join #channel.
Создавать профиль сервера, псевдоним или номер заранее не нужно. /server HOST — синоним прямого подключения.
Без ника используется допустимое системное имя входа, иначе user. Ввод ника не запрашивается.
Сохраните настройки и выбранное значение по умолчанию через /saveconf. При следующем запуске /connect их использует.
Сохранение не включает автоподключение: его выбирают отдельно. /quickstart и /panel — необязательные подсказки.
Работают и параметры оболочки: --server HOST, --channel '#CHANNEL', --nick NICK. В оболочке заключайте #CHANNEL в кавычки.
При запуске --nick, --port, --channel, --tls, --plain и --ca-file заменяют сохранённые значения по умолчанию.
Явный --server выбирает первое подключение. --init-config и --check-config используют основной файл настроек.
Смена хоста через --server удаляет старые учётные данные, настройку CA, данные баунсера, каналы и стартовые команды.
Если сохранённый сервер недоступен, укажите --server либо исправьте его до изменения параметров подключения.
Autoconnect, autojoin и autoauth настраиваются для каждого профиля сервера. См. /help autoconnect.
--no-connect блокирует подключение при запуске; --test-mode имитирует работу без сети и записи настроек.
--sessions выводит присоединённые и отсоединённые задания. --resume [NUMBER] присоединяет снова; см. /help background.
--close-session NUMBER завершает всё задание и его соединения IRC с подтверждением. NUMBER — ID задания, не PID.
После потери терминала: --sessions, затем --detach-session NUMBER и --resume NUMBER. Рабочий процесс сохраняет старый код до перезапуска; см. /help sessions.
-h/--help и -v/--version работают без терминала.
onekeyirc всегда использует idle. В его панели приложения нет выбора интерфейса; /set default_interface принимает только idle.
Общий анализатор конфигурации сохраняет любое из двух распознаваемых записанных значений. Сохранённое значение ncurses не меняет интерфейс этого отдельного клиента.
Из оболочки: onekeyirc --sessions; onekeyirc --detach-session NUMBER; onekeyirc --resume NUMBER; onekeyirc --close-session NUMBER.
onekeyirc --manual выводит это полное руководство.

tls
---
Проверенный TLS включен по умолчанию. Имя/адрес и цепь сертификатов должны пройти проверку; отката на plaintext нет.
Порт не отключает TLS. --plain или /connect -plain выбирает IRC без шифрования и без учетных данных.
Укажите точные имя TLS-хоста и порт провайдера. Причины ошибки: не тот адрес, истекший/чужой сертификат или доверие системы; смотрите ошибку.
По умолчанию TLS использует системные доверенные CA. --ca-file FILE или ca_file= задает пакет PEM CA, но не закрепляет сертификат сервера.
Пакет CA: непустой обычный файл до 16 MiB. Ссылка на CA допустима; для путей секретов и конфига правила строже.
Файл CA открывается раз, размер проверяется при чтении. FIFO и устройства запрещены; защищённый PEM не запросит пароль.
Ограничение размера не ограничивает задержку I/O файлов и сетевых ФС. Нужен надёжный пакет CA на подходящем диске.
--check-config не проводит TLS-рукопожатие и не проверяет работу CA или источника учетных данных. --test-mode не соединяется с сервером.
TLS защищает лишь этот канал связи. TLS и история plaintext на бунсере управляются отдельно.

troubleshooting
---------------
Занято после сбоя SSH? --sessions, проверка задания, --detach-session NUMBER, --resume NUMBER. Не используйте --close-session. See /help sessions.
Up не возвращает текст: Compose редактирует, Command повторяет команды. Откройте Command через / из лога. Чат и секретные команды не повторяются.
Если текст будто обрезан: редактор занял строки, видны последние. Выйдите или смените канал; видимый текст не доказывает доставку.
Если при смене канала текст полон, дело в окне. При сбое запишите интерфейс, режим, размер, locale и чистые шаги; без паролей и личного чата.
Каналов нет? Проверьте сервер и вход. Прямой профиль: /autojoin list; бунсер: /join или /part.
Ошибка входа? Проверьте аккаунт, источник, права, TLS, агент GPG. /autoauth status не читает секреты.
Нет catch-up: метка могла устареть, лог включился позже, выключился или изменился. См. /help catchup и /help logging; логи не возвращают умерший worker.
Изменения не видны? Нужен /connect после разрыва. Сохранение не включает autoconnect; запуск требует нового процесса.
Если запуск помощника не удается, исправьте SIGCHLD или автоочистку дочерних процессов у запускающей программы, чтобы клиент мог их дождаться.
Используйте --check-config и doc/TROUBLESHOOTING.txt. --test-mode проверяет экран, не DNS, TLS, секреты и бунсер.

Система команд
---------------------------
Нажмите / в журнале, чтобы открыть Команда; начальная косая черта уже вставлена. Enter при фокусе на вводе выполняет отредактированную команду; Escape отменяет её.
Синтаксис: /COMMAND ARGUMENTS. Регистр имён не важен; используйте показанные слова параметров. Слова ЗАГЛАВНЫМИ (UPPERCASE) — заполнители, [items] необязательны, | означает выбор альтернативы.
Вводите одну команду за раз. Пробелы разделяют аргументы; кавычек, подстановок и цепочек команд оболочки нет. Параметры запуска из оболочки используются вне этого редактора.
TEXT и PATH учётных данных используют весь остаток строки буквально, включая пробелы. Перед вставкой полной /command удалите готовую косую черту; вставленные переводы строк становятся пробелами, а не отдельными командами.
Home/End/Delete/Backspace редактируют. Tab/Shift-Tab дополняет имена команд; Up из ввода вызывает принятые строки истории.
Down выбирает подсказки; Enter вставляет выбранную команду для редактирования. Отдельное нажатие Enter после показа выполняет её.
В настройках приложения выберите Частые, Недавняя история, Наиболее используемые в этой конфигурации, По алфавиту или Контекстные.
Частые — заранее подобранный удобный порядок. Контекстные запоминают фактический экран, открывший ввод команды. Другие совпадения по префиксу остаются доступны.
? на выбранной подсказке открывает справку элемента и экрана. В поле ввода это обычный текст.
Delete удаляет выбранную недавнюю запись или сбрасывает личный счётчик частоты; команда каталога никогда не удаляется.
В ограниченную историю в памяти попадают только принятые безопасные команды. Команды паролей/служб и входы в канал с ключом исключены.
Команда с неожиданными аргументами завершается ошибкой без выполнения запрошенного действия. Справка показывает синтаксис, последствия и примеры.
Команды сообщений создают план отправки. До постановки в очередь действуют режим отправки и обязательное подтверждение нескольких сообщений.
Большинство команд действует на выбранном сервере. /server NUMBER выбирает другой; /server без аргументов выбирает его представление MOTD.
Для обычного подключения и общения используйте /connect HOST, /join #channel, /query NICK и /saveconf.
Сохраните принятые настройки, чтобы они пережили перезапуск. Сохранённые профили автоматически обновляют закрытый файл .commands только для счётчиков использования; аргументов и чата в нём нет.
/summary читает всё текущее состояние клиента локально; /list [MASK] запрашивает каналы сети, а /ls и /cl перечисляют локальные представления.
/help ls перечисляет все темы справки.
Команды (синтаксис и примеры: /help COMMAND)
--------------------------------------------------------------------

  /autoauth     Проверить или подготовить аутентификацию SASL

  /autocommands Подготовить отложенные команды для следующего подключения

  /autoconnect  Проверить или изменить автоподключение при запуске

  /autojoin     Проверить или подготовить входы в каналы при запуске

  /away         Задать статус отсутствия или снять его без сообщения

  /back         Снять статус отсутствия

  /background   Сохранить подключения и освободить терминал

  /bind         Назначить свою клавишу локальной функции программы

  /bindings     Показать назначения клавиш или доступные действия и клавиши

  /cancel       Отменить чат и команды запуска в очереди

  /catchup      Читать эту беседу с последнего отправленного вами сообщения

/autoauth - Проверить или подготовить аутентификацию SASL
------------------------------------------------------------------------
Использование: /autoauth [status|off|sasl USER file PATH|sasl USER gpg PATH]

Меняет аутентификацию выбранного сервера для следующего подключения. Нужен проверенный TLS.
Без аргументов или с status показывает состояние соединения/входа и пути к файлам учетных данных, но не пароли.
Текущие и ожидающие настройки различаются. Длинные пути выводятся полностью в подписанных строках продолжения.
PATH означает весь оставшийся текст, включая пробелы; подстановка shell и разбор кавычек не выполняются.
Эта команда не открывает файлы. Ключи GPG должны быть разблокированы вне программы.
Пароли открытым текстом допускаются только явно в закрытом файле настроек, а не в аргументах команд.
Для профиля баунсера используйте /panel; /autoauth запрещен, поскольку вход и источник данных управляются вместе.
Сохраните через /save. Сначала отключитесь, затем /connect применит изменения; текущее соединение не меняется.

Примеры:
/autoauth status
/autoauth sasl myaccount gpg /home/me/irc-account.gpg
/autoauth off
/save

/autocommands - Подготовить отложенные команды для следующего подключения
------------------------------------------------------------------------
Использование: /autocommands [list|add COMMAND|remove NUMBER|clear|on|off|delay SECONDS|interval SECONDS]

Команды относятся к выбранному серверу. Они выполняются один раз после регистрации и обязательной SASL-аутентификации.
Задержка по умолчанию 15 секунд; между завершёнными командами не меньше 2 секунд.
Время задают delay 0..300 и interval 2..60. Зависшее соединение не вызывает очередь накопленных команд.
Поддержаны /msg, /join, /nick, /away, /back и /whois, а также их точно указанные псевдонимы.
Не более 16 команд по 511 байт UTF-8. Каждая должна поместиться в одно IRC-сообщение и не делится автоматически.
Нет оболочки, сырого IRC и подстановки текущего диалога. Автовход в канал не меняет выбранный экран.
Изменения действуют при следующем соединении. /cancel отменяет ещё не отправленные команды запуска.
В списках скрыты сообщения и ключи каналов; автокоманды не попадают в историю и локальные повторы.
Сохраняйте через /save. Файл должен быть закрытым (0600 или 0400); непустой активный список требует проверенный TLS.
Тестовый режим не запускает автокоманды. Их текст хранится в настройках буквально, без шифрования GPG.

Примеры:
/autocommands add /msg ChanServ op #chat mynick
/autocommands delay 15
/autocommands interval 2
/autocommands list
/save

/background - Сохранить подключения и освободить терминал
------------------------------------------------------------------------
Использование: /background

Восстанавливает терминал и отсоединяет сеанс. Оболочка выводит нумерованную команду возврата.
В оболочке --sessions показывает подключённые и отдельные задания; --resume возобновляет единственное доступное отдельное задание.
Если заданий несколько, используйте --resume NUMBER. NUMBER — ID задания, не PID; он постоянен до выхода, затем может использоваться снова.
--detach-session NUMBER отключает терминал, сохраняя процесс, IRC-соединения, черновики и историю для --resume NUMBER.
--close-session NUMBER закрывает задание, IRC, передачи, черновики и историю RAM. Успех — лишь после проверки завершения.
Если после обрыва SSH возврат занят, выведите задания, отсоедините нужное и возобновите. См. /help sessions.
Старый или зависший worker может не выполнить запрос. Установка бинарника не меняет работающий worker: после обновления перезапустите его.
Возврат показывает историю RAM без новых сообщений. /set single_session on запрещает второе фоновое задание, чтобы --resume был однозначным.
Для запуска без терминала примените --background в оболочке; параметры см. в --help.
При background_away и разрешении профиля /background или обрыв ставит AWAY. Возврат снимает только этот статус, сохраняя ручной /away.
Добавьте --reconnect для повтора временно неудачных соединений. См. /help deployment и /help reconnect.
Мультиплексор терминала не нужен. Незавершённое разрешение имён или помощник пароля может потребовать повтора.
Пауза обычного процесса останавливает сеть. В возобновлённом задании контроллер терминала может спать, а рабочий процесс продолжит связь.
Из оболочки: onekeyirc --sessions; onekeyirc --detach-session NUMBER; onekeyirc --resume NUMBER; onekeyirc --close-session NUMBER.

Примеры:
/background

/bind - Назначить свою клавишу локальной функции программы
------------------------------------------------------------------------
Использование: /bind KEY ACTION

По умолчанию нет своих привязок клавиш. Списки имен: /bindings keys и /bindings actions.
Новая привязка заменяет прежнее действие клавиши на всех серверах; остальные остаются.
Работает в чате и командной строке, но не при вставке, вводе пароля, настройке, чтении или подтверждении.
Вступает в силу сразу, но до /save input не сохранится. Без активной привязки навигация обычная.
Только именованные локальные функции; нет произвольных команд, макросов, отправки или раскрытия shell.
Зарезервированная терминалом клавиша может не дойти до программы; привязка не меняет сигналы терминала.

Примеры:

/bind Alt-c command
/save input

/bindings - Показать назначения клавиш или доступные действия и клавиши

Этот клиент редактирует привязки через команды; /bindings выводит текущую таблицу.

/catchup - Читать эту беседу с последнего отправленного вами сообщения
------------------------------------------------------------------------
Использование: /catchup

Начинает с последнего местного сообщения/действия в канале или чате. У видов сервера и упоминаний нет якоря.

Изменённый или заменённый якорь диска недействителен. Новый процесс не восстанавливает якоря старых журналов. См. /help logging и /help history.

/connect - Подключиться к серверу или использовать сохраненное соединение
------------------------------------------------------------------------
Использование: /connect [-tls|-plain] [-nick NICK] HOST [PORT] | /connect

Начните с /connect irc.example.org. Не нужно заранее создавать профиль, псевдоним или номер сервера.
Новый сервер использует проверенный TLS на порту 6697 и системный логин или user, если он не подходит.
Уже настроенный подходящий сервер сохраняет порт, транспорт, ник и аутентификацию.
Для имени используйте -nick NICK или /nick NICK до подключения. Пароли не являются позиционными аргументами.
-plain включает IRC без шифрования (начальный порт 6667). -tls и -ssl выбирают проверенный TLS.
+PORT также выбирает TLS. Обычный номер порта не выключает TLS. --tls, --plain и --nick тоже принимаются.
Соединение выбирается, открывается вид сервера/MOTD. Уже активное совпадающее соединение не дублируется.
Другой адрес получает новые настройки входа; данные и каналы другого сервера не копируются.
/connect без аргументов использует выбранный сервер и настройки. /saveconf запоминает его по умолчанию для нового запуска.
Если профили баунсера имеют один хост, выберите нужный через /server NUMBER, затем вызовите /connect.
Существующие номера серверов тоже принимаются. Тестовый режим офлайн; настройки нужно сохранять явно.

Примеры:
/connect irc.example.org
/join #chat
/saveconf
/connect
/connect -nick mynick irc.example.org +6697
/connect -plain localhost 6667

/dcc - Предлагать, проверять и управлять прямыми передачами файлов
------------------------------------------------------------------------
Использование: /dcc [list|NICK PATH|send [-address IPV4] [-port PORT] NICK PATH|accept NUMBER [DIRECTORY]|reject NUMBER|cancel NUMBER]

Без аргументов показ передач. /dcc NICK PATH предлагает файл на выбранном сервере.
PATH - оставшийся буквальный текст, включая пробелы; путь относительно каталога запуска процесса.
Клиент не меняет этот каталог, даже при просмотре файлов и в фоновом режиме.
Краткая отправка объявляет локальный IPv4 IRC-соединения. За NAT укажите доступный IPv4 через -address и проброшенный порт через -port.
Внешний поиск адреса не выполняется. Для IRC только по IPv6 нужен явный адрес IPv4.
DCC - прямое незашифрованное соединение. Партнёр видит объявленный IP; принятие предложения также раскрывает ваш IP.
Входящее предложение не открывается до /dcc accept NUMBER. DIRECTORY по умолчанию каталог запуска; он должен быть вашим и закрытым.
Существующие файлы не перезаписываются; ссылки и спецфайлы запрещены. Тестовый режим не открывает файлов и сокетов.
Отклонить предложение: /dcc reject NUMBER. Отменить передачу: /dcc cancel NUMBER.
Номера передач общие для всех серверов процесса. Закрытие исходного сервера отменяет его передачи; разрыв IRC не отменяет принятую.

Примеры:
/dcc alice file.txt
/dcc list
/dcc accept 1 ./downloads
/dcc send -address 203.0.113.20 -port 5000 alice file.txt
/dcc cancel 2

Игнорирование не создаёт личных чатов и упоминаний. Состояние протокола, уведомления сервера и членство работают.
Сохраните маски этого сервера командой /save.

Примеры:
/ignore list
/ignore add noisy!*@*
/ignore remove noisy!*@*

Нужна регистрация. Ключ — один печатаемый токен ASCII; он не сохраняется ни в файле, ни в истории команд.
При прямом соединении канал добавляется в текущий автозаход; при сохранении приоритет у ожидающих изменений /autojoin.
Команда /autojoin задаёт следующее явное соединение прямого профиля без входа сейчас. Bouncer сам ведёт список каналов.

Примеры:
/join #ircnow
/join #private channel-key

/list - Запросить и отфильтровать каталог каналов сети
------------------------------------------------------------------------
Использование: /list [MASK] [--min-users N] [--max-users N] [--name TEXT] [--topic TEXT] [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list show [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list clear

Запрашивает список каналов выбранного IRC-сервера; требуется регистрация. Серверу передаётся только фильтр MASK.
Фильтры минимума/максимума участников, имени и темы работают локально даже без расширенных фильтров LIST у сети.
Значения --sort: channel, users, topic; стандарт — users по убыванию. --limit 0 не ограничивает показ в ограниченном кэше.
/list show показывает кэш; --sort, --asc/--desc и --limit сортируют и ограничивают его без нового запроса IRC. /list clear очищает кэш.
При разрыве или отказе в LIST частичный кэш остаётся, но запрос завершается; повторите /list после регистрации либо /list clear.
Полноэкранный клиент открывает сортируемый каталог каналов; минимальный режим использует те же опции и /list show.
Для локального списка каналов используйте /ls или /cl; /list ищет в сети.

Примеры:
/list
/list *linux* --min-users 5 --max-users 500
/list --topic help --sort users --desc --limit 100
/list show --sort channel --asc --limit 50
/list clear

/panel - Открыть интерактивную панель настройки
------------------------------------------------------------------------
Использование: /panel

Выберите 0 (по умолчанию) для настроек приложения или панели профилей 1..8; панель 1 редактирует основной профиль. Это номера панелей, а не идентификаторы заданий оболочки.
Настройки приложения задают хранение истории, режим отправки, формат вывода, уведомления очереди и подсказки команд для всех серверов.
Они работают без настроенного сервера. Итоговые варианты: 1 Сохранить (по умолчанию) и 2 Применить без сохранения; ни один не подключается.
Панель сервера содержит только его настройки подключения, запуска, аутентификации, упоминаний и игнорирования.
Выбор любой панели не переключает вашу беседу.
Enter сохраняет показанное значение; '-' очищает необязательное поле. Escape возвращает на один вопрос назад; повторяйте для выхода без применения изменений.
Tab выбирает заголовок вопроса. Нажмите там ? для справки о параметре и его экране; Tab или Enter возвращает к ответу.
В любом редактируемом ответе ? остаётся обычным текстом, включая первый символ и маски с подстановочными знаками.
Слова для наблюдения и маски игнорирования вводятся по одному; пустая новая запись завершает список.
Ввод учётных данных скрыт, ответы настройки никогда не попадают в историю команд. При редактировании существующие файлы учётных данных не читаются.
Для источника GPG выберите Создать новый или Использовать существующий. Создание предлагает закрытый путь по умолчанию; Enter принимает его и подготавливает каталог (0700).
Другое место назначения должно быть в существующем вашем каталоге с режимом 0700. Путь проверяется до вопросов о ключе и пароле.
Затем создание запрашивает полный отпечаток локального открытого ключа и пароль дважды. Существующие файлы и символические ссылки никогда не заменяются.
Пути учётных данных сохраняются как абсолютные. /autoauth status показывает их полные настроенные расположения, не читая содержимое.
Шифрование начинается только после Готово, не блокирует IRC и никогда не использует временный файл открытого текста. Escape отменяет ожидающую работу.
При ошибке сохранения конфигурации готовый шифротекст остаётся для осознанной повторной попытки; файлы, указанные в сохранённой конфигурации, сохраняются.
Тестовый режим не запускает GPG и не создаёт файлы учётных данных. Перед аутентификацией разблокируйте соответствующий закрытый ключ вне приложения.
Итоговые варианты панели сервера: 1 Сохранить и подключиться, 2 Только сохранить (по умолчанию), 3 Подключиться один раз или 4 Только применить.
Само открытие панели или ответы на её предыдущие вопросы ничего не применяют, не сохраняют и не подключают.
Войти раз - применить без записи; Только применить - без записи и соединения. Живое соединение не меняет цель и не переподключается скрыто.
Неудачное подключение не отменяет уже примененные или сохраненные изменения.
Для краткой настройки сервера, транспорта, порта и ника используйте /quickstart.

Примеры:
/panel

Использование: /part [#CHANNEL] [MESSAGE]

Войти раз - применить без записи; Только применить - без записи и соединения. Живое соединение не меняет цель и не переподключается скрыто.
Неудачное подключение не отменяет уже примененные или сохраненные изменения.

/save - Сохранить текущий сервер, настройки приложения или все профили
------------------------------------------------------------------------
Использование: /save [input|output|all]

/save без аргументов пишет настройки выбранного сервера, включая отложенные изменения соединения.
/save input и /save output сохраняют весь основной профиль, предпочтения и подготовленное соединение, а не только указанную часть.
/save all пишет каждый исправный профиль отдельно. При ошибке прежние файлы остаются; о сбое сообщается.
Замена каждого файла приватна и атомарна, но это не общая транзакция. Тестовый режим не пишет настройки.

/saveconf - Сохранить конфигурацию и выбранное подключение
------------------------------------------------------------------------
Использование: /saveconf

Сохраняет параметры приложения и все исправные профили серверов, запоминая выбранный сервер как основной.
При следующем запуске /connect использует его; номер сервера или повторная настройка не нужны.
Включены ник, каналы, вход и параметры запуска; явные ожидающие правки подключения имеют приоритет.
Это не включает автоподключение при запуске. При необходимости сначала /autoconnect on.
Каждый файл заменяется приватно и атомарно. Успешные записи сохраняются, даже если другой файл не записан.
Сервер по умолчанию сохраняется лишь при успехе записи; ошибки сообщаются, нечитаемые профили не перезаписываются.
Тестовый режим не пишет настройки. /save предлагает более точное сохранение профилей и предпочтений.

Примеры:
/connect irc.example.org
/join #chat
/saveconf
/quit

/server - Подключиться к серверу или выбрать существующий
------------------------------------------------------------------------
Использование: /server [-tls|-plain] [-nick NICK] HOST [PORT] | /server [NUMBER|add HOST [PORT] [NICK]|connect NUMBER|disconnect NUMBER|close NUMBER]

С именем хоста действует как прямой /connect; заранее создавать профиль не нужно.
Без аргумента выбирает сообщения/MOTD сервера. NUMBER выбирает слот без подключения.
add создаёт профиль с новыми учётными данными, проверенным TLS и отключённым autoconnect; не выбирает, не соединяет и не сохраняет.
Значение PORT по умолчанию 6697. Другой порт не выключает TLS; открытый текст надо выбрать явно.
connect/disconnect не меняют выбор. close удаляет вторичную сессию/запись списка, но не файл профиля.
Номера серверов в простом интерфейсе: 1..8, главный 1. Главный остаётся; отключайте, а не закрывайте.
Номера постоянны до конца сессии. Panel 0 предназначена для настроек приложения.

Примеры:
/server irc.example.org
/join #chat
/saveconf
/servers
/server 1

------------------------------------------------------------------------
Использование: /servers

Показывает слоты серверов 1..8 (основной 1), выбранный сервер, состояние и autoconnect для каждого сервера.
Загруженный профиль доступен даже без соединения.

Примеры:
/servers
/server 1

/set - Выбрать общие настройки ввода, вывода и присутствия
------------------------------------------------------------------------
Использование: /set send_mode direct|review | /set composer_mode line|fullscreen | /set output_format compact|full | /set queue_notices on|off | /set program_messages on|off | /set persistent_logging on|off | /set single_session on|off | /set default_interface idle|ncurses | /set command_suggestions alphabetical|common|history|frequent|contextual | /set part_message [TEXT] | /set quit_message [TEXT] | /set background_away on|off | /set background_away_message TEXT | /set autoaway_minutes 0..1440 | /set autoaway_message TEXT

direct — режим по умолчанию: Enter отправляет текст; для нескольких сообщений IRC нужно подтверждение.
review добавляет проверку перед постановкой обычных сообщений в очередь.
output_format compact — по умолчанию: выбранный чат показывает [HH:MM:SS] <nick> текст.
output_format full выводит сервер, дату и цель каждой строки. compact сохраняет происхождение упоминаний и диагностики других серверов.
queue_notices off скрывает обычные уведомления очереди и повтор после проверки. Ошибки и подтверждение нескольких сообщений видны.
program_messages off скрывает мелкие сообщения об отмене черновика, очистке ввода и сохранении черновика. Ошибки и предупреждения остаются видны.
persistent_logging on: .log (0600) в частном каталоге 0700. Обычно выключен. Лимит 16 MiB: архив, off/on. Опасный/занятый файл остановит запись, чат продолжится.
single_session on оставляет одну фоновую задачу клиента; --resume без номера однозначен. Несколько серверов IRC допустимы в одной сессии.
default_interface задаёт интерфейс при новом запуске, если доступно; текущий не меняет. /save input сохраняет выбор.
command_suggestions выбирает алфавит, частые, последние, самые используемые команды либо подходящие исходному экрану.
composer_mode line оставляет строку ввода под чатом; fullscreen даёт многострочный редактор и окно чата. По умолчанию: line.
part_message и quit_message — причины выхода IRC по умолчанию. Явный текст /part или /quit заменяет их; пустое значение отключает.
background_away отправляет background_away_message после /background или потери терминала. autoaway_minutes включает away при простое; 0 отключает.
Только установленный клиентом away сбрасывается после возврата или реального ввода. Ручной /away не изменяется и не сбрасывается.
«Часто используемые» — по умолчанию. «Контекстные» выделяет команды канала, диалога, сервера или клиента, сохраняя другие совпадения.
«Часто используемые» использует заранее заданный удобный порядок. «Контекстные» помнит исходный экран, включая общий просмотр сводки.
Это настройки клиента для всех серверов. Для сохранения используйте /save input или /save output.
/panel, затем 0, меняет эти настройки и общий предел истории.
onekeyirc всегда использует idle. В его панели приложения нет выбора интерфейса; /set default_interface принимает только idle.
Общий анализатор конфигурации сохраняет любое из двух распознаваемых записанных значений. Сохранённое значение ncurses не меняет интерфейс этого отдельного клиента.

Примеры:
/set send_mode review
/set composer_mode line
/set command_suggestions contextual
/save input
/set output_format full
/set queue_notices off
/set program_messages off
/set persistent_logging on
/set single_session on
/save output

/soju - Управлять выбранным bouncer soju
----------------------------------------------------------
Использование: /soju [COMMAND]

Нужен подключённый профиль soju из /panel. Без аргумента запрашивается помощь BouncerServ.
COMMAND уходит одним приватным сообщением с интервалом, без локального эха и истории команд.
Прямое соединение IRC не поддерживает эту команду. Ответы видны на экране сервера.
Команды учётной записи и сети описаны в справке самого баунсера.

Примеры:
/soju
/soju network status

/summary - Сводка всех текущих сеансов серверов и активности
------------------------------------------------------------------------
Использование: /summary

Показывает все серверы, channel 0, каналы/личные чаты, непрочитанное, упоминания, очередь, команды запуска и передачи файлов.
Локальная сводка доступна без сети. Для обновления нажмите r в просмотрщике или повторите команду.
Открытие не меняет чат и не помечает сообщения прочитанными. Копии упоминаний не входят в итог активности.
Упоминания могут быть непрочитанными; итоги не складывайте. Различаются открытые и покинутые каналы.
Отчёт читается с прокруткой и хранит черновики. Косая черта открывает команды; отмена возвращает к сводке.
При ошибке обновления остаётся старая сводка. Открытие и обновление не делают сетевых запросов.
Данные входа, содержимое очереди сообщений и автокоманд никогда не выводятся.

Примеры:
/summary

/topic - Запросить или изменить текущую тему канала
------------------------------------------------------------------------
Использование: /topic [TEXT]

Нужны регистрация и вход на канал. Без текста запрашивает тему, иначе дословно отправляет TEXT.
Сервер решает, позволяют ли ваши права менять тему канала.

Примеры:
/topic
/topic Welcome to our channel

/transfers - Управлять передачами файлов (псевдоним /dcc)
------------------------------------------------------------------------
Использование: /transfers [ARGUMENTS]

Те же команды и защита, что у /dcc. Описание отправки, приёма и отмены: /help dcc.

Примеры:
/transfers
/transfers alice file.txt

/unbind - Удалить одну или все пользовательские привязки клавиш
------------------------------------------------------------------------
Использование: /unbind KEY|all

Удаление возвращает клавише обычное действие. all очищает только пользовательские привязки.
Действует сразу для всех серверов. Чтобы сохранить после перезапуска, используйте /save input.

Примеры:
/unbind F7
/unbind all
/save input

/unignore - Удалить одну локальную маску игнорирования
------------------------------------------------------------------------
Использование: /unignore MASK

То же, что /ignore remove MASK. Сохраните выбранный профиль, чтобы изменение сохранилось.

Примеры:
/unignore noisy!*@*

/unread - Список непрочитанных бесед на всех серверах
------------------------------------------------------------------------
Использование: /unread

Строки содержат номер сервера, имя беседы, непрочитанные сообщения и упоминания.
Выберите /server NUMBER, затем /channel или /pm для перехода к беседе.

Примеры:
/unread
/server 1
/pm alice

/users - Вывести известных пользователей текущего или названного канала
------------------------------------------------------------------------
Использование: /users [#CHANNEL]

Это текстовый список людей, не переключатель видимости. Известные префиксы режимов показаны.
Список открывается в отдельном окне даже пустой. Enter, Escape или q возвращает в выбранный чат.
Up/Down и Page Up/Down прокручивают список. В Help клавиша Enter продолжает прокрутку.
Неполные или усечённые ответы NAMES отмечаются. Запросы WHOIS не отправляются.

Примеры:
/users
/users #ircnow

/view - Выбрать беседу по имени или канал по номеру
------------------------------------------------------------------------
Использование: /view NAME|NUMBER

Номера каналов есть в /channels, имена личных диалогов в /ql. Подходят также сервер и упоминания.
Используйте /help вместо внутреннего буфера руководства.

Примеры:
/view #ircnow
/view alice
/view 0

/views - Список каналов (псевдоним /channels)
-------------------------------------------------------------------
Использование: /views

Псевдоним использует номера каналов; личные диалоги остаются в /ql.

Примеры:
/views

/watch - Управлять дополнительными буквальными строками упоминаний
------------------------------------------------------------------------
Использование: /watch [list|add TEXT|remove TEXT]

Упоминания ника всегда активны. Add/remove считает остаток буквальным текстом, не регулярным выражением.
До 32 дополнительных строк по 1..127 байт UTF-8 на сервер. Сохранить: /save.

Примеры:
/watch list
/watch add release day
/watch remove release day
/mentions

/whois - Запросить информацию о нике у сервера
------------------------------------------------------------------------
Использование: /whois NICK

Требуется регистрация. Открывает вид сервера для показа ответа. Локальные команды не выполняются.

Примеры:
/whois alice

/znc - Управлять выбранным bouncer ZNC
--------------------------------------------------------
Использование: /znc [COMMAND]

Нужен подключённый профиль ZNC из /panel. Без аргумента запрашивается Help у *status.
COMMAND уходит одним приватным сообщением с интервалом, без локального эха и истории команд.
Для модуля ZNC используйте /msg *module COMMAND. Ответ виден на экране сервера.
Прямое соединение IRC не поддерживает команду. См. справку баунсера.

Примеры:
/znc
/znc ListNetworks
/znc Connect
