Arabic terminal text (language pack r12)
======================================

STATUS

r12 provides optional Arabic shaping, paragraph-aware right-to-left layout,
and visual editing in onekeyirc, vipirc's minimalist interface, and vipirc's
full ncurses interface. It uses the installed system FriBidi library. The
application versions remain onekeyirc 1.0-a and vipirc 1.0-a, English source r1.

Arabic catalogs and input remain logical UTF-8. Temporary display maps supply
joined glyphs, wrapped rows, cursor positions, mouse targets and highlights.
Sending, parsing, saving or exporting text never uses those visual forms.

The implementation and automated Linux checks cover the scope below. Native
OpenBSD 7.8 execution, Crostini and other physical terminal/font checks, and
fluent Arabic review remain necessary target acceptance work. No automatic
byte/cell test can prove a terminal font's appearance.

r12 REFINEMENTS

Each editor redraw now prepares one temporary layout shared by the text and
cursor. A successful preparation includes the paint buffer; the snapshot
supplies geometry and glyph groups without further allocation. If preparation fails, the complete
redraw uses the ordinary logical path. This prevents a logical cursor from
being paired with visually reordered text after a transient allocation failure.

The ncurses visual painter keeps combining marks with their base at the
bottom-right window cell, within the existing per-cell capacity. Up/Down at the first or
last editor row keeps the current insertion stop when movement is clamped,
even when several logical stops share one screen cell. The ncurses history
view reuses one prepared map per record for row counting and painting. If
preparation fails, both steps use the same logical path, so their wrapped
heights remain consistent. This reuse lasts only for the current draw.

Minimalist readers reuse paragraph layouts during a scrolling operation,
reducing repeated mapping work. Early checks bypass unnecessary or unavailable
wide-text conversion and keep the logical fallback available. These changes
preserve logical UTF-8 drafts, messages, logs and manual exports. Translation
coverage and the target acceptance limits above are unchanged: native
OpenBSD/Crostini terminal and font checks, and fluent Arabic review, remain
necessary. The full ncurses manual and SECURITY.md remain in English.

ENABLE VISUAL TEXT

Use a UTF-8 locale installed on your system. Check locale -a and locale charmap.
Use visual mode on terminals that do not already shape/reorder Arabic:

    ONEKEYIRC_LANG=ar ONEKEYIRC_ARABIC_VISUAL=1 ./onekeyirc
    VIPIRC_LANG=ar VIPIRC_ARABIC_VISUAL=1 ./vipirc -i
    VIPIRC_LANG=ar VIPIRC_ARABIC_VISUAL=1 ./vipirc --ncurses

Menu language and visual text mode are independent. For example, English
menus can show and edit Arabic messages with:

    ONEKEYIRC_LANG=en ONEKEYIRC_ARABIC_VISUAL=1 ./onekeyirc
    VIPIRC_LANG=en VIPIRC_ARABIC_VISUAL=1 ./vipirc --ncurses

The visual variable accepts 1 or visual, ignoring case for visual. The client
uses its own nonempty variable first, then the other client's variable.
An explicit 0 disables conversion. An unset variable defaults to logical text.
Leave visual mode off if the terminal already handles Arabic; applying
bidirectional reordering twice can make text unreadable.

Install your operating system's FriBidi package if the runtime library is
absent. No library is bundled or downloaded by either client. configure probes
the dynamic loader separately from TLS, including systems needing -ldl.
If loading, UTF-8 locale checks, glyph-width checks, mapping or allocation fail,
the ordinary logical path remains available. IRC_NO_ARABIC_VISUAL compiles
without the converter. The normal build needs no FriBidi development headers.

OpenBSD uses dlopen("libfribidi.so"), allowing its documented loader search to
resolve the installed versioned library. This was checked against OpenBSD 7.8
documentation and compiled conditionally on Linux; it is not a native test.

READING AND WRAPPING

- Minimalist help, context readers, history, catch-up panes, live WATCH output,
  editor tails, setup labels and messages use the shared paragraph layout.
- Full ncurses labels, history, manual/readers, command and search editors,
  prompts, settings, guided setup and transfer fields use the same maps.
- A paragraph's first strong character selects its base direction. An ASCII
  timestamp, nickname or command prefix can make a mixed paragraph left-to-
  right. An Arabic-leading paragraph flows right-to-left. Rows retain their
  top-to-bottom order. Arabic rows align within their assigned text area.
- Wrapping uses shaped display widths and prefers whitespace. Emergency breaks
  keep a base and its following zero-width marks together. Very narrow rows
  can split a word, URL or command into rows without changing stored text.
- Each physical line receives its own Arabic joining forms. Read-only text
  can use lam-alef ligatures; editable text retains separate letter positions.
- Latin commands, nicknames, channel names, URLs and numbers retain their
  character order within a directional run. Search highlights and channel
  mouse targets refer back to original logical spans.

The text layout does not mirror the application's buttons, panel arrangement
or key bindings. They retain their existing locations. Mixed-direction caret
junctions can have multiple logical insertion points at the same screen cell.

TYPING, CURSORS AND SELECTION

- Left and Right move through visible insertion stops. A soft wrap retains
  both caret affinities, so the caret can cross between two physical rows
  without losing the logical insertion position at their shared boundary.
- Up and Down keep the nearest display column where the field uses vertical
  editing. Existing command-history and suggestion bindings still take their
  usual priority. A mouse click chooses a legal insertion boundary nearby.
- Home and End retain document-start and document-end behavior. They do not
  become physical left-edge and right-edge shortcuts.
- Backspace removes the preceding logical cluster; Delete removes the next.
  A cluster here means a base plus following zero-width characters, matching
  the existing editor. This is not a full Unicode grapheme-break algorithm.
- Typing and paste insert logical Unicode text. Resizing recalculates layout
  while retaining the logical draft and insertion position.
- Existing select-all and replacement work for the entire logical draft,
  including text outside the viewport. Arbitrary range selection is not added.
- Secret fields remain masked and use their existing logical cursor behavior.

The visual map is bounded to 8192 Unicode scalars and 16384 UTF-8 bytes, matching
the editor limits. An edit layout reserves a real caret cell when width is
greater than one. A one-column field remains bounded and retains distinct
logical insertion stops even when they share the only screen cell.

DATA AND COPY/PASTE

IRC wire text, stored drafts, configuration, retained history and saved logs
remain logical UTF-8. Plain-text manual exports also stay logical:

    ONEKEYIRC_LANG=ar ./onekeyirc --manual > manual-ar.txt
    VIPIRC_LANG=ar ./vipirc -i --manual > manual-ar.txt

These exports need no terminal or IRC connection. The full ncurses manual
still has English prose; its visual renderer is integrated, but this pack does not
add a translation of that separate manual.

Selecting/copying visually transformed terminal output can copy presentation
forms and visual order. Use a logical manual export or saved log when original
text is required. Saved logging must already have been enabled. Bracketed
paste preserves the existing submit guards and inserts the supplied logical
text; the client cannot infer the intended order of externally reversed text.

CHECKS AND REPRODUCTION

After configure and make:

    make check-arabic-visual

For full vipirc ncurses:

    make check-arabic-ncurses

Focused tests included with both clients:

- test_arabic_layout.c: exact joined forms, lam-alef, combining spans,
  paragraph bases, wrapping, logical/byte maps, bounds and optional fallback;
  also a deterministic matrix of 640 mixed text/mark/joiner/width cases.
- test_editor_visual.c: logical bytes and deletion, visual movement, wrapped
  affinity at widths 1/2/4, mixed Latin rows, explicit newlines, mouse, resize,
  select-all, 8192-character input, disabled converter and ordinary fallback.
- test_arabic_visual_core.c: retained logical text, atomic live-output
  queue retry, scoped paragraph reuse, EOF and mode/width transitions,
  and coherent editor frames after a failed snapshot.
- test_editor_visual_failure.c: every temporary snapshot allocation
  individually failed, complete cleanup and unchanged logical drafts,
  allocation-free geometry/painting, partial and disabled converters.
- test_arabic_editor_terminal.py: actual frontend typing and transmission to a
  private loopback IRC fixture, with visual mode both off and on.

The vipirc test_arabic_ncurses.c fixture reads actual ncurses wide cells. It
covers joined letters/marks, readers and highlights, channel hit targets,
editor caret/mouse positions, scrolling/resize and masked Arabic passwords.
It requires ncurses wide-character development headers and a terminal runtime.
Tests do not contact a public IRC server and do not use screenshots.

Strict Linux builds and focused AddressSanitizer/UndefinedBehaviorSanitizer
runs passed. LeakSanitizer could not run in the validation environment's
ptrace setup and was disabled for those sanitizer runs. This is not evidence
of native OpenBSD, physical terminal/font or linguistic acceptance.

TRANSLATION COVERAGE

r10's complete minimalist manuals remain translated in ten languages,
including Arabic, with 844 catalog entries per language. r12 refines
text rendering and editing. Full ncurses MANUAL.txt, SECURITY.md, some other
contextual help and diagnostics still need translation. All translations
remain drafts pending native-speaker review.

SECURITY NOTE FOR PATCH r15

RTL text is display-only. Unsafe Unicode directional controls, including
U+206A..U+206F, and annotation controls U+FFF9..U+FFFB are replaced by '?'
in sanitized display text. Similar-looking Unicode letters can still be
confused with one another; never infer identity from visual appearance.
Verify published archive SHA-256 sums before running the patch installer.
See doc/LOCALIZATION-SECURITY-en.txt and SECURITY.md.
