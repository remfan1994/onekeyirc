VIPIRC / ONEKEYIRC LOCALIZATION CONTINUATION
Release date: 2026-11-19 (America/Los_Angeles)
vipirc 0.7.40 and onekeyirc 0.1.39

BASELINE
- Continued from vipirc 0.7.39 and onekeyirc 0.1.38, which carried the
  separate source-comment/contributor pass forward.
- The original README, security guides, contributor notes, source comments,
  command grammar and application behavior are retained.

LOCALIZATION
- Ten language catalogs: Indonesian (id), Malay (ms), Turkish (tr), Spanish
  (es), Portuguese (pt), French (fr), German (de), Russian (ru), Italian (it),
  Arabic (ar), with English fallback.
- Increased each catalog from 267 to 290 translated display strings.
- New translations cover 23 detailed help lines: authentication, bouncers,
  session recovery, verified TLS and plaintext boundaries, logging, reconnect
  and troubleshooting. The existing help line renderer uses translations
  only when the exact whole display string is present; other help lines
  remain English. No parser, network, protocol or config tokens changed.
- Ten reproducible offline doc/TOPICS-XX.txt companion guides carry precisely
  these 23 translated help lines from the same JSON catalogs.
- New generator tools/generate_locale_topic_guides.py and regression
  tests/test_detailed_help_translation.py verify source, catalog and guide
  parity, byte bounds and command syntax preservation. Offline PTY
  tests/test_l10n_topics_terminal.py verifies /help bouncers with all 10 locales.
- Existing doc/START-XX.txt introductory guides and doc/LOCALIZATION.md remain.
- All source comments remain English for maintainers; previous source-comment
  pass and doc/USE-MODIFY-REDISTRIBUTE.txt remain intact.

RUNNING
  VIPIRC_LANG=id onekeyirc
  VIPIRC_LANG=tr vipirc -i
  /help bouncers
  /help authentication
  /help sessions
  /help tls
  /help logging
  /help troubleshooting

INSTALL
  ./configure --prefix=/usr/local
  make
  make install
  make uninstall

BUILD WITHOUT LOCALIZATIONS
  CPPFLAGS=-DIRC_DISABLE_LOCALIZATION ./configure --prefix=/usr/local
  make

Use a UTF-8 terminal/locale for international text. Existing background
workers retain the code and language from their original launch.
