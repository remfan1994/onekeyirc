/help aliases
-------------

Les alias exigent une correspondance exacte ; aucune exécution ambiguë ou approximative.

/conn = /connect; /disc = /disconnect; /detach = /background; /exit = /quit

/j = /join; /leave = /part; /message et /privmsg = /msg

/nickname = /nick; /names et /nicks = /users; /unaway = /back

/channellist = /cl; /querylist = /ql; /serverlist = /servers

/configure et /preferences = /panel; /saveconfig = /saveconf

/autocommand = /autocommands

La complétion propose les noms canoniques ; les arguments restent intacts et le filtrage d'historique sensible est identique.

/help authentication
--------------------

Utilisez TLS vérifié avec /autoauth sasl USER file PATH ou /autoauth sasl USER gpg PATH.

Le fichier de mot de passe ou le contenu GPG déchiffré fournit l'identifiant ; les chemins sont littéraux.

Utilisez /panel pour créer un secret chiffré GPG avec une empreinte de clé publique locale déjà présente.

Utilisez une clé GPG déjà déverrouillée. Aucun pinentry ne s'ouvre dans l'éditeur de discussion.

Les valeurs en clair password= et server_password= sont aussi acceptées dans les fichiers de config privés.

Choisissez une seule source par secret. /settings et /summary masquent les chemins des fichiers.

/autoauth status affiche les chemins actuels et en attente sans lire les fichiers ni révéler les mots de passe.

Les réglages d'authentification s'appliquent au prochain /connect apres déconnexion; /save les enregistre.

Sur un profil bouncer, gérez connexion et source ensemble via /panel ; /autoauth refuse les changements.

Les fichiers secrets doivent être ordinaires, appartenir à l'utilisateur, mode 0600 ou 0400 ; liens symboliques et traversée des parents sont refusés.

Limite SASL : 1024 octets ; PASS ordinaire : 503 octets. L'identité ZNC assemblée doit tenir sur une ligne IRC.

--check-config vérifie config et source sans lire les secrets ni tester la connexion. Voir /help tls et /help bouncers.

/help bouncers
--------------

Ouvrez /panel, choisissez un serveur, puis le type znc ou soju.

Saisissez hôte et port TLS du bouncer, son identifiant, le réseau amont existant et, si souhaité, un nom client stable.

Enregistrez un profil par reseau en amont. Si l'hote est partage, choisissez le bon profil avant /connect sans argument.

Le client construit l'identité. ZNC utilise le mot de passe serveur; soju utilise celui d'authentification. Saisissez seulement le secret du bouncer, ni identifiant combine ni mot de passe NickServ.

Le bouncer restaure les canaux. /autojoin local n'est pas rejoue et ne peut etre modifie; utilisez /join et /part.

Les commandes de démarrage explicites s'exécutent encore. Vérifiez-les avant d'activer le profil pour éviter des jointures ou commandes de service répétées.

L'absence automatique en veille/arrière-plan est désactivée par profil bouncer sauf activation. /away et /back manuels fonctionnent toujours.

L'historique transmis garde les dates UTC d'origine, dirige les messages prives vers leur destinataire et ne cree ni mentions, ni CTCP/DCC, ni changement d'etat actif.

L'historique est limité. Pas de recherche d'archives à la demande, de découverte de réseaux ni de profil automatique par réseau.

Utilisez /znc ou /soju sans argument pour l'aide du service. Les contrôles n'entrent ni dans l'historique ni dans l'echo; les réponses vont a la vue serveur sans journal persistant.

Les copies connues des contrôles sortants sont masquees meme lors d'une relecture sous un ancien pseudo. Le texte edite peut apparaitre et le bouncer applique sa politique de journaux.

Le client se connecté uniquement au bouncer. Configurez séparément TLS, authentification et conservation en amont.

Voir doc/BOUNCERS.txt et les exemples bouncer dans examples/ pour la configuration et les limites des tests réalisés.

/help configuration
-------------------

[connection] contient server, port, tls, nick, username, realname, channel, autoconnect, auth et les sources des identifiants.

[bouncer] type=none|znc|soju, username, network, client et automatic_away définissent le profil bouncer par réseau; voir /help bouncers.

[input] send_mode=direct|review et [output] format=compact|full, queue_notices=true|false, program_messages=true|false, persistent_logging=true|false sont des préférences du fichier principal.

[input] command_suggestions=common|history|frequent|alphabetical|contextual définit le classement; common est le défaut.

[input] composer_mode=line|fullscreen choisit la saisie et les commandes minimalistes; line est le défaut. Les deux montrent les messages récents.

[input] use_signals=false Use signals est réglé sur no par défaut. Ctrl-C et Ctrl-Z annulent un message ou une commande non envoyés sans quitter ni suspendre le programme. Choisissez yes dans le panneau 0 ou les paramètres Interface de vipirc pour activer les signaux du terminal. Apply agit immédiatement ; Save enregistre aussi [input] use_signals=true|false. Les paramètres initiaux du terminal sont rétablis à la sortie ou lors de la suspension.

[hotkeys] contient jusqu'à 64 raccourcis KEY=action facultatifs, sans défaut. Propriété du fichier principal ; voir /help hotkeys.

[session] single_session=true|false permet ou non plusieurs tâches en arrière-plan; false par défaut.

[session] default_interface=ncurses|idle est une préférence principale. Les options au démarrage sont expliquées plus bas.

Le format compact est le défaut. history_lines dans le fichier principal règle la rétention sur tous les serveurs.

[mentions] word= et [ignore] mask= peuvent être répétés.

[autocommands] contient enabled, delay_seconds, interval_seconds et des lignes command= répétées pour un serveur.

Ces commandes sont en clair dans le fichier privé. /autocommands les gère sans divulguer les secrets dans les listes ni l'historique.

Les serveurs supplémentaires enregistrés utilisent le catalogue .servers et le répertoire .d voisins.

Connectez-vous avec /connect HOST, puis /join #channel et /saveconf pour enregistrer votre configuration.

/saveconf conserve préférences et profils sains et mémorise le serveur choisi pour un prochain /connect sans argument.

/quickstart pose quatre questions de connexion. /panel utilise 0 pour les préférences, 1..8 pour les profils; 1 modifie le principal.

Les changements du panneau restent privés avant Finish. Un chemin GPG accepté peut préparer un dossier 0700; chiffrement, sauvegarde et connexion attendent le choix final.

Pour garder les changements : /save pour le serveur choisi, /save input ou /save output pour le principal, ou /saveconf pour les profils sains et le défaut.

La configuration enregistrée utilise <config_path>.commands pour lire/écrire les compteurs de commandes; le fichier principal ne les stocke pas.

Ce fichier privé borné ne stocke que noms canoniques et compteurs, sans arguments ni historique. Le mode test ne le lit ni ne l’écrit.

Les changements [connection] préparés par /autojoin ou /autoauth s’appliquent au prochain /connect déconnecté, sans modifier la connexion active.

Les fichiers de configuration sont privés; chaque fichier est remplacé atomiquement, pas tout l’espace en une transaction. Pas d’import/export.

Sections, clés ou valeurs inconnues sont refusées. La configuration utilise des valeurs littérales, sans guillemets shell, échappements, variables ou ~.

Les valeurs ordinaires sont élaguées aux extrémités. password= et server_password= gardent tout après = sauf la fin de ligne ; sans commentaires ni guillemets.

Enregistrer réécrit les réglages pris en charge et remplace formatage/commentaires manuels. Gardez les notes ailleurs.

Voir /help authentication pour secrets, /help tls pour CA, /help logging pour journaux et /help sessions pour tâches actives.

/help deployment
----------------

Utilisez --background pour lancer une session sans terminal ni touche d'accueil.

Configurez puis enregistrez /autoconnect on pour chaque serveur à démarrer.

--background n'active pas autoconnect seul; --no-connect interdit toujours les connexions au lancement.

L'avertissement usuel s'affiche une fois avant le détachement. Le succès confirme une tâche locale, pas la connexion IRC.

Depuis un autre terminal du même compte, utilisez --sessions et --resume [NUMBER].

--sessions inclut les tâches rattachées. --detach-session NUMBER libère le terminal rattaché sans détruire la tâche, pour la reprendre ailleurs. --close-session NUMBER termine la tâche sélectionnée et toutes ses connexions IRC.

Utilisez l'ID de tâche affiché, pas un PID. Les processus bloqués ou anciens sans le contrôle demandé peuvent échouer. Voir /help sessions pour la récupération et la mise à niveau.

Redémarrer le VPS termine les tâches, brouillons et historique RAM. Une tâche système peut lancer un nouveau client.

Instructions OpenBSD et exemple rc.d facultatif : doc/OPENBSD-VPS.txt.

Exécutez sous un compte normal avec des chemins absolus pour configuration et secrets. Une clé GPG verrouillée ne peut pas demander de saisie au démarrage.

--check-config vérifie les réglages, pas l'accès aux secrets, DNS, TLS ou la connexion IRC.

Utilisez --reconnect lors des coupures réseau temporaires; surveiller les plantages relève du système d'exploitation.

Les lanceurs doivent permettre d'attendre les processus fils : ignorer SIGCHLD ou les récupérer automatiquement fait échouer le premier démarrage en arrière-plan, la création du résolveur ou de l'auxiliaire d'identifiants. Détacher à nouveau une tâche gérée ne crée aucun nouveau processus.

/help documentation
-------------------

Cherchez une tâche avec /help ls; /help commands explique la saisie et liste les commandes. Consultez un sujet ou une commande a la fois.

/help COMMAND donne la syntaxe, les effets et les exemples. /help /ls explique la liste locale; /help ls enumere les sujets.

/help all ou /manual ouvre cette référence. --help explique les options de lancement; la sortie de --manual en mode minimal peut aller dans un fichier.

README.md guide la documentation; MANUAL.txt décrit l'interface et INSTALL la compilation. La page man installee explique l'emploi depuis le shell.

CONTRIBUTING.md explique les modifications; doc/SOURCE-MAP.txt repere le code; tests/README.md repertorie les tests. DESIGN.md explique la propriété et l'ordre.

doc/TROUBLESHOOTING.txt guide par symptome. SECURITY.md definit les menaces; doc/BOUNCERS.txt et doc/SESSION-CONTROLS.txt décrivent les operations. Les audits ne valent que pour leurs versions et environnements.

/help history
-------------

L'historique affiché et des commandes est borné en RAM. Les journaux persistants sont facultatifs et désactivés par défaut.

Changer de vue réaffiche ses enregistrements récents; /mentions réaffiche les lignes sources correspondantes.

Le réglage d'historique limite l'ensemble des entrées de tous les serveurs et vues ; modifiez-le avec /panel, puis 0.

La conservation est limitée au plus petit de ce réglage et de 2048 entrées, avec une limite stricte distincte de 512 KiB.

Dans un canal ou une conversation privée, /catchup commence à votre dernière composition envoyée localement. Il essaie un journal privé admissible, puis la mémoire conservée ; /help catchup décrit les deux lecteurs.

Le rattrapage persistant est propre au serveur et à la conversation. La journalisation doit déjà être active à l'envoi du point de repère ; c'est une transcription privée en clair, limitée à 16 MiB par profil enregistré, et non un stockage chiffré.

Le rappel des commandes conserve au plus 64 entrées et 64 KiB, supprimant les plus anciennes. /clear efface l'historique de conversation, pas celui des commandes.

Les suggestions d'historique récent utilisent ces lignes complètes. Delete supprime la ligne d'historique sélectionnée.

Les suggestions les plus utilisées emploient au plus 96 noms canoniques de commandes et des compteurs bornés dans <config_path>.commands.

Pour les configurations enregistrées, les commandes acceptées et remises à zéro des fréquences actualisent automatiquement ce fichier privé. Arguments, destinataires et messages n'y sont pas conservés.

Les profils non enregistrés gardent les compteurs en mémoire jusqu'au premier Enregistrer réussi. Des fichiers de compteurs absents ou inutilisables n'empêchent pas le démarrage.

L'aide et les réponses de commandes sur plusieurs lignes utilisent un lecteur distinct avec un tampon limité à 512 KiB. Elles n'entrent pas dans l'historique de conversation.

Les commandes acceptées peuvent être rappelées dans l'éditeur de commandes. Les changements d'authentification, entrées dans un canal avec clé et messages sensibles aux services sont omis.

Up/Down dans Compose déplace le curseur, pas les messages envoyés. Seul Command rappelle les commandes acceptées.

Détacher puis reprendre dans la même interface conserve brouillons et rappel des commandes. Changer d'interface, lorsque permis, les supprime ainsi que les formulaires de configuration ; quitter ou redémarrer le système supprime aussi les conversations en mémoire et leurs points de rattrapage.

Les compteurs de fréquence enregistrés ne contiennent que des noms. Les anciens journaux en clair subsistent après la fermeture, mais ne sont pas importés automatiquement dans une nouvelle session ou l'éditeur.

/clear efface l'historique RAM de la vue, pas l'ancien journal disque. Le bouncer fournit son propre rejeu.

/help hotkeys
-------------

Les raccourcis personnalisés sont facultatifs et vides par défaut. Navigation et édition d'origine restent disponibles.

Utilisez /bindings pour la liste, /bindings keys pour les touches et /bindings actions pour les fonctions locales.

Assignez par /bind KEY ACTION; répétez pour remplacer. Retirez avec /unbind KEY ou /unbind all.

Effet immédiat sur tous les serveurs ; /save input les enregistre dans la configuration principale. Les autres profils ne remplacent pas cette liste.

Format : [hotkeys] puis une ligne KEY=action par touche, 64 au maximum. Doublons et alias du terminal sont des erreurs.

Les actions agissent dans le chat principal et l'invite de commande, pas dans les mots de passe, réglages, collages, lecteurs ou confirmations.

En mode minimal, les lecteurs gardent le brouillon et le curseur. Changer de vue ou d'éditeur exige de finir ou vider le brouillon.

Ni action d'envoi, ni commande arbitraire, shell ou macro. Arrière-plan et quitter gardent leurs effets habituels.

Touches : F1..F12, Ctrl-A..Z, Alt-a..z/0..9 et navigation ; les caractères imprimables restent du texte.

Ctrl-H/Backspace, Ctrl-I/Tab, Ctrl-J/Ctrl-M/Enter et Ctrl-[/Escape partagent des octets ; pas de raccourcis distincts.

Les signaux et raccourcis du terminal/multiplexeur priment. Ctrl-C ou Ctrl-Z n'agit que si l'octet arrive ; aucune touche n'est réattribuée.

Le collage balisé reconnu n'exécute pas de raccourcis. Sans balises, il ressemble à la frappe ; voir /help keys.

/help keys
----------

Journal : / ouvre Commande ; ? explique le journal de conversation ou de surveillance sélectionné. Les autres touches imprimables ouvrent Rédiger en conservant le caractère saisi.

Des raccourcis personnalisés peuvent remplacer ces commandes dans la conversation principale ou Commande ; aucun n'est affecté par défaut. Voir /help hotkeys.

Journal en direct : Up recule d'une ligne, Page Up d'une page, Home atteint la plus ancienne page conservée. Down/Page Down/End restent en direct ; Left/Right/Delete/Backspace n'ouvrent pas Rédiger.

Insert ou Enter ouvre Rédiger vide. Les flèches, Home/End, Delete et Backspace modifient le texte. Tab/Shift-Tab complète les pseudonymes dans Rédiger et les noms de commandes dans Commande.

Le mode de rédaction en ligne garde une ligne de saisie sous la fin du journal en direct ; le plein écran garde un éditeur multiligne avec un panneau de journal en direct plus petit.

Dans Commande, Down sélectionne les suggestions. Up/Down les parcourt ; Up depuis la première revient à la saisie.

Enter sur une suggestion l'insère sans l'exécuter. Lisez ou modifiez-la, puis, après son affichage, appuyez de nouveau sur Enter pour l'exécuter.

Dans Commande, Up rappelle les commandes acceptées correspondantes ; Down revient vers la saisie d'origine. Dans Rédiger, Up/Down déplace le curseur, même maintenu ; Enter envoie.

Delete supprime la ligne sélectionnée d'Historique récent ou remet à zéro le compteur sélectionné de Plus utilisé. Les commandes du catalogue restent disponibles.

? sur une commande sélectionnée l'explique et donne accès à l'aide de son écran. Dans tous les éditeurs de texte, ? reste du texte ordinaire.

Révision utilise un écran alternatif temporaire ; brouillon et invite n'entrent jamais dans l'historique. Un nouvel Enter confirme ; Escape ou la saisie restaure éditeur, brouillon et curseur. Up/Down, Page Up/Down et Home/End permettent de parcourir l'écran.

Dans l'aide ou une réponse, Up/Down fait défiler ; Page Up/Down change de page ; Home/End atteint le début ou la fin.

Dans la liste des utilisateurs, Enter revient au journal ; dans l'aide et les autres lecteurs de réponses, Enter avance d'une ligne.

Dans le lecteur, / ouvre Commande avec la complétion et l'historique habituels. Escape annule cette invite et revient au lecteur.

Dans un lecteur de résumé, r actualise l'instantané ; ? explique la réponse et son lecteur.

Dans l'aide contextuelle, Enter suit le lien surligné À propos de l'écran. Escape revient à l'aide de l'élément, puis à l'écran d'origine exact.

Dans la configuration, Tab sélectionne l'en-tête de la question ; ? explique son option ou écran. Tab/Enter revient à la modification de la réponse.

Exécuter une commande remplace la réponse précédente. Les confirmations courtes reviennent au journal ; les erreurs courtes laissent la commande modifiable.

Escape annule Rédiger ou Commande et revient au journal. Depuis Révision, Escape revient à l'éditeur sans supprimer le brouillon. Escape dans le journal met le client en arrière-plan.

Escape seul attend environ 500 ms ; une séquence en cours autorise 1000 ms entre octets de continuation. L'activité réseau continue.

Les séquences de touches complètes sont traitées immédiatement. Un marqueur de début de collage retardé au-delà de ce délai après son premier Escape peut mettre le client en arrière-plan.

Une fois la capture du collage commencée, son marqueur de fin reste reconnu malgré des lectures fractionnées ou des délais arbitraires.

Les touches d'interruption, de sortie et de suspension conservent leurs affectations ; Use signals = no désactive leurs signaux tant que le client est actif.

[input] use_signals=false No (par défaut) désactive les signaux du terminal pendant que le programme le contrôle ; Ctrl-C/Ctrl-Z annulent le brouillon. Yes active les associations de touches existantes sans les modifier. Les signaux externes du processus restent actifs ([input] use_signals=true).

Les signaux de terminal activés terminent ou suspendent après restauration du terminal ; fg reprend une tâche suspendue.

Ctrl-D est inactif sauf s'il est affecté dans la conversation principale ou Commande. /quit quitte ; /background libère le terminal pendant que l'activité réseau continue.

Les écrans usuels omettent les rappels de touches répétés ; ce sujet reste la référence complète du clavier.

Le collage délimité reconnu reste littéral. Les touches attendent un éditeur visible, une saisie nouvelle et une pause. Un affichage trop petit ou échoué ne peut l'approuver ; redimensionnez et relâchez les touches maintenues.

Coller dans le journal de surveillance ouvre Rédiger avec des barres obliques littérales. Coller dans Commande y reste ; CR/LF/Tab deviennent des espaces. Vérifiez, puis appuyez de nouveau sur Enter.

Le collage sans délimiteurs ne se distingue pas de la frappe ; utilisez la prise en charge du collage délimité.

/help limits
------------

Les limites IRC portent sur les octets, non sur les caractères affichés. Un caractère UTF-8 peut occuper plusieurs octets.

Le client calcule l'espace en comptant cible, commande et relais ; il ne coupe jamais un caractère UTF-8.

À la limite d'un message, tout ajout attend la confirmation par Enter de poursuivre l'édition ; cet Enter n'envoie rien.

Un message fractionné exige un accord distinct, même en mode direct. Le chat envoie une ligne toutes les 1.2 secondes.

Un envoi contient au plus 64 messages et 16384 octets de texte. Raccourcissez ou envoyez séparément.

Il y a au plus 8 emplacements de serveur et 32 vues par serveur, y compris les vues réservées.

/help logging
-------------

Les logs persistants sont facultatifs et desactives par défaut. /set persistent_logging on active; /save output conserve le choix.

Chaque profil sauvé ajoute à CONFIG_PATH.log. Le dernier dossier parent doit appartenir à l'utilisateur avec le mode 0700; fichier régulier, possédé, lien unique, mode exact 0600. Liens symboliques et traversée des parents interdits.

Les logs sont plaintext, pas des sauvegardes chiffrées. Limite 16 MiB/fichier; une erreur arrête le log, pas la discussion.

Archivez le journal plein ailleurs, puis désactivez/réactivez les journaux. Rotation ou réécriture peut invalider le repère de /catchup; envoyez un nouveau message admissible avant de vous y fier.

Identifiants connus et brouillons non envoyés sont exclus, y compris l'authentification rejouée sous d'anciens pseudos. Discussions ordinaires et secrets saisis peuvent être enregistrés. La rétention serveur/bouncer est indépendante.

/catchup n'utilise un journal sain que si son repère local exact a été écrit dans cette session. Il ne demande pas d'archives au bouncer et n'importe pas les anciens journaux après redémarrage.

/clear efface seulement la RAM. Les logs restent après sortie, --close-session et sauvegarde. Désactiver les logs arrête les nouvelles entrées sans effacer les anciennes.

Les E/S sur disque lent peuvent retarder le processus. Voir /help catchup, /help history et SECURITY.md.

/help messages
--------------

Utilisez /join #channel pour rejoindre et choisir un canal, ou /query NICK pour ouvrir une conversation privée.

Choisissez un canal conservé avec /channel. /msg TARGET TEXT envoie à une cible ; /me TEXT envoie une action.

/query ouvre une conversation sans envoyer ; /pm est un alias. /ql sépare les conversations privées des canaux.

L'envoi direct est le mode par défaut ; /set send_mode review ajoute une révision. /set composer_mode line|fullscreen modifie l'affichage.

À la limite d'un message, confirmez la poursuite de l'édition ; la division exige encore un accord distinct.

Il faut avoir rejoint et être authentifié avant la mise en file de messages. /cancel annule la file, pas les envois déjà faits.

/help reconnect
---------------

--reconnect active les tentatives de reconnexion pour ce processus; il ne sauve rien et n'ouvre pas la connexion.

Sans cette option, une connexion échouée exige /connect. /autoconnect gère seulement le démarrage.

Les pannes DNS temporaires, refus/coupures et délais expirés réessaient après 5, 10, 20, 40, 80, 160 puis 300 secondes.

Une connexion inscrite pendant au moins 60 secondes réinitialise l'attente. La boucle ne dort pas en bloquant.

Les erreurs de certificat, authentification, protocole invalide et configuration restent déconnectées jusqu'à correction.

Un ERROR serveur avant inscription est retenu; après inscription il peut déclencher une reconnexion.

Un /disconnect explicite annule la tentative en attente. /connect ultérieur démarre une nouvelle tentative.

Les reprises utilisent les réglages actifs; les modifications en attente exigent encore /connect explicite.

Les messages en attente sont perdus a la déconnexion et jamais renvoyes automatiquement.

L'authentification et les commandes de départ actives sont répétées. Les profils directs rejouent autojoin; les bouncers restaurent leurs canaux.

Le mode test hors ligne ne se reconnecte jamais au réseau.

/help security
--------------

Le texte distant est assaini avant affichage. L'entrée est interprétée comme commande IRC locale, jamais comme shell.

Pas de /raw, d'échappement shell ni d'acceptation automatique de fichiers. Un collage balisé reconnu n'exécute jamais de commande.

TLS vérifié l'identité du serveur. SASL, PASS et les commandes privees d'authentification exigent TLS vérifié. Maintenez a jour la bibliotheque TLS du systeme; voir SECURITY.md.

Un bundle CA personnalisé doit être un fichier PEM ordinaire non vide, de 16 MiB au maximum, sans demande de mot de passe.

Les mots de passe configures sont masques dans l'aide et les réglages. Les commandes de secrets connues sont exclues du rappel; les secrets saisis comme texte peuvent rester en mémoire.

Aucune transcription sur disque par défaut. Les modifications de configuration nécessitent un enregistrement explicite.

Les autres processus du meme compte, le serveur IRC ou bouncer et un terminal ou systeme compromis echappent a ces protections. TLS ne chiffre pas les discussions de bout en bout.

Les journaux facultatifs et secrets dans la configuration sont en clair. Les commandes sensibles connues sont filtrees, mais les secrets dans les messages ne sont pas toujours reconnaissables.

Voir /help tls, /help authentication, /help logging et SECURITY.md pour les limites et anciens audits.

/help sessions
--------------

Une tâche est un processus client avec ses serveurs, transferts, brouillons et historique. Un numéro de serveur dans l'application n'est pas un ID de tâche du shell.

Depuis le shell, lancez --sessions. Consultez l'etat attache/detache et utilisez l'ID du travail, pas le PID.

Si l'ancien terminal SSH garde le travail, faites --detach-session NUMBER puis --resume NUMBER. IRC reste actif.

--resume seul ne reprend qu'une tâche detachee verifiee. Plusieurs taches exigent un numéro; une tâche attachee est occupee jusqu'au detachement. Les numéros peuvent être reutilises.

N'utilisez --close-session NUMBER que pour terminer tout le travail. Il ferme IRC et les transferts; brouillons et historique RAM sont perdus, fichiers et journaux conservés.

La fermeture reussit seulement après nettoyage vérifié. En cas d'expiration, verifiez --sessions: elle peut finir plus tard. Un échec ne supprime pas la connexion active ni n'envoie un signal a un PID suppose.

Seule une tâche geree survit a la perte du terminal. Un processus normal au premier plan n'est pas récupérable après perte de SSH. Demarrez avec --background ou utilisez /background avant.

Une tâche appartient au meme compte Unix et au meme hote; un seul terminal peut être attache. Un autre programme de ce compte est dans le meme perimetre de confiance.

Installer un executable ne remplace pas le code du processus actif. Enregistrez la configuration, arretez l'ancien, verifiez --version et demarrez un nouveau processus.

Une ancienne tâche peut manquer de contrôles recents ou du changement d'interface. Gardez l'executable compatible jusqu'a son arret si necessaire.

Le client ne change pas la politique d'inactivite SSH. Voir /help background, /help deployment et doc/SESSION-CONTROLS.txt.

/help startup
-------------

Lancez le programme, fermez l'accueil, puis tapez /connect irc.example.org et /join #channel.

Il n'est pas nécessaire de créer un profil, un alias ou un numéro au préalable. /server HOST est un alias de connexion directe.

Sans pseudo fourni, le nom de connexion système valide est utilisé, sinon user. Aucune saisie de pseudo n'est demandée.

Enregistrez la configuration et le choix par défaut avec /saveconf. Au prochain lancement, /connect les réutilise.

L'enregistrement n'active pas la connexion automatique : c'est un choix distinct. /quickstart et /panel sont facultatifs.

Les options shell fonctionnent aussi : --server HOST, --channel '#CHANNEL' et --nick NICK. Mettez #CHANNEL entre guillemets.

Au démarrage normal, --nick, --port, --channel, --tls, --plain et --ca-file remplacent les valeurs par défaut mémorisées.

Un --server explicite choisit la première connexion. --init-config et --check-config utilisent le fichier principal de configuration.

Changer --server vers un autre hôte efface les anciens identifiants, la CA personnalisée, l'identité du bouncer, les canaux et les commandes de démarrage.

Si le défaut mémorisé manque, indiquez --server ou corrigez-le avant de remplacer les paramètres de connexion.

Autoconnect, autojoin et autoauth sont propres à chaque profil de serveur enregistré. Voir /help autoconnect.

--no-connect empêche les connexions au démarrage ; --test-mode simule sans réseau ni écriture de configuration.

--sessions répertorie les tâches attachées et détachées. --resume [NUMBER] les rattache ; voir /help background.

--close-session NUMBER ferme toute la tâche choisie et ses connexions IRC après confirmation. NUMBER est un ID de tâche, pas un PID.

Après perte du terminal, utilisez --sessions, puis --detach-session NUMBER et --resume NUMBER. Le processus garde son ancien code jusqu'au redémarrage ; voir /help sessions.

-h/--help et -v/--version fonctionnent sans terminal.

/help tls
---------

TLS vérifié est le défaut. Nom/adresse du serveur et chaine de certificats doivent etre valides; aucun contournement ni repli plaintext.

Un port ne desactive pas TLS. --plain ou /connect -plain choisit IRC non chiffre et interdit les identifiants compte/serveur.

Utilisez le nom d'hôte et port TLS exacts du fournisseur. Échec possible: mauvais serveur, certificat expiré/non fiable ou confiance locale; lire l'erreur d'abord.

TLS utilise la liste de confiance du système. --ca-file FILE ou ca_file= choisit un ensemble PEM CA, sans épingler le certificat final.

Un paquet CA personnalisé doit être un fichier ordinaire non vide de 16 MiB max. Lien symbolique vers CA permis ; chemins secrets/config plus stricts.

Le fichier CA est ouvert une fois, borné et sa taille revérifiée. FIFO, périphériques et autres types sont refusés ; un PEM protégé ne peut pas demander de mot de passe.

Limiter la taille du fichier ne limite pas la latence I/O du disque ou du réseau. Utilisez un paquet CA fiable sur un stockage adapté.

--check-config ne teste pas la connexion TLS ni le bon fonctionnement du CA ou des identifiants. --test-mode ne contacte aucun serveur.

TLS ne protege que cette connexion. Le TLS amont et l'historique plaintext du bouncer sont geres séparément.

/help troubleshooting
---------------------

Occupe apres coupure SSH ? Faites --sessions, vérifiez le travail, puis --detach-session NUMBER et --resume NUMBER. Évitez --close-session. See /help sessions.

Up ne rappelle rien: Compose edite les messages; Command rappelle les commandes acceptees. Ouvrez Command avec / depuis le journal. Messages envoyes et commandes sensibles ne sont pas rappeles.

Si un message renvoye a la ligne semble coupe: l'editeur reserve des lignes et affiche les plus recentes. Quittez l'editeur ou reselctionnez le salon; l'affichage ne prouve pas la livraison distante.

Si changer de salon montre tout, c'est une difference de fenetre. Si le probleme dure, notez interface, mode, taille du terminal, locale et etapes expurgees sans mots de passe ni conversations privees.

Aucun canal ? Vérifiez l'ecran serveur et l'authentification. Profil direct : /autojoin list; bouncer : /join ou /part.

Echec d'authentification ? Vérifiez compte, source, droits, TLS et agent GPG. /autoauth status ne lit aucun secret.

Rattrapage indisponible: l'ancre a pu disparaitre, la journalisation demarrer plus tard ou s'arreter, ou le fichier changer. Voir /help catchup et /help logging; les journaux ne recreent pas le processus termine.

Changement ignore ? Reconnectez avec /connect apres déconnexion. Sauvegarder n'active pas autoconnect; options de lancement demandent un redémarrage.

Si le lancement d'un auxiliaire échoue, corrigez la politique SIGCHLD ou de collecte automatique des enfants du lanceur pour permettre leur attente.

Utilisez --check-config et doc/TROUBLESHOOTING.txt. --test-mode teste l'interface, pas DNS, TLS, identifiants ou bouncer réel.

/help /autoauth
---------------

Examiner ou préparer l'authentification SASL
Utilisation : /autoauth [status|off|sasl USER file PATH|sasl USER gpg PATH]

Modifie l'authentification du serveur choisi pour sa prochaine connexion. Un TLS vérifié est requis.

Sans argument ou avec status, affiche l'etat connexion/authentification et les chemins des identifiants, jamais les mots de passe.

Les réglages actifs et en attente sont distingues. Les chemins longs figurent en entier sur des lignes de suite étiquetées.

PATH reprend littéralement tout le texte restant, espaces compris; aucune expansion du shell ni interpretation des guillemets.

Cette commande n'ouvre aucun fichier. Les clés GPG doivent etre déverrouillées hors du programme.

Les mots de passe en clair ne peuvent etre configures qu'explicitement dans un fichier privé, jamais en arguments.

Utilisez /panel pour un profil bouncer; /autoauth y est refusé car identite et source d'identifiants sont gérées ensemble.

Utilisez /save pour enregistrer. Déconnectez-vous puis lancez /connect ; la connexion active n'est jamais redirigée.

Exemples :
/autoauth status
/autoauth sasl myaccount gpg /home/me/irc-account.gpg
/autoauth off
/save

/help /autocommands
-------------------

Préparer des commandes différées pour la prochaine connexion
Utilisation : /autocommands [list|add COMMAND|remove NUMBER|clear|on|off|delay SECONDS|interval SECONDS]

Les commandes concernent le serveur sélectionné. Elles s'exécutent une fois après l'inscription et le SASL requis.

Le délai par défaut est de 15 secondes, avec au moins 2 secondes entre deux commandes terminées.

Réglez avec delay 0..300 et interval 2..60. Une connexion bloquée ne déclenche pas de rafale de rattrapage.

Commandes autorisées : /msg, /join, /nick, /away, /back et /whois, ainsi que leurs alias exacts documentés.

Au plus 16 commandes de 511 octets UTF-8 chacune. Chaque commande tient dans un message IRC ; aucune coupure automatique.

Ni shell, ni IRC brut, ni expansion de la conversation actuelle. Les jonctions automatiques ne changent pas de vue.

Les modifications valent à la prochaine connexion. /cancel arrête les commandes de démarrage non envoyées.

Les listes masquent les messages et clés de salon ; les commandes automatiques restent hors historique et échos locaux.

Enregistrez avec /save. Le fichier doit rester privé (0600 ou 0400) ; une liste active non vide exige un TLS vérifié.

Le mode test n'exécute jamais ces commandes. Le texte est stocké tel quel dans la configuration, sans chiffrement GPG.

Exemples :
/autocommands add /msg ChanServ op #chat mynick
/autocommands delay 15
/autocommands interval 2
/autocommands list
/save

/help /background
-----------------

Garder les connexions et libérer le terminal
Utilisation : /background

Restaure le terminal et détache la session active. Le shell reçoit la commande numérotée permettant de la reprendre.

Dans le shell, --sessions liste les tâches privées attachées et détachées; --resume reprend l'unique tâche détachée disponible.

S'il existe plusieurs tâches, utilisez --resume NUMBER. NUMBER est l'identifiant de tâche, pas un PID; il reste stable jusqu'à la fin, puis peut être réutilisé.

--detach-session NUMBER libère le terminal attaché mais conserve le processus, les connexions IRC, brouillons et historique pour --resume NUMBER.

--close-session NUMBER termine toute la tâche, ses connexions IRC et transferts, les brouillons non sauvés et l'historique en mémoire. Le succès n'est annoncé qu'après vérification.

Si la reprise est occupée après une perte SSH, listez les tâches, détachez celle-ci puis reprenez-la. Voir /help sessions.

Une tâche bloquée ou ancienne sans la commande de contrôle demandée peut échouer. Installer un binaire ne met pas à jour la tâche en cours; redémarrez-la après mise à niveau.

Reprendre réaffiche l'historique en mémoire même sans nouveau message. /set single_session on interdit une seconde tâche en arrière-plan; --resume reste sans ambiguïté.

Pour démarrer sans terminal, utilisez --background dans le shell. Voir --help pour les options.

Si background_away est actif et autorisé, /background ou la perte du terminal envoie AWAY après détachement. La reprise efface seulement cette absence automatique; un /away manuel reste.

Ajoutez --reconnect pour réessayer les connexions après des échecs passagers. Voir /help deployment et /help reconnect.

Aucun multiplexeur de terminal n'est requis. Une résolution DNS ou un assistant d'identifiants en attente peut nécessiter un nouvel essai.

Suspendre un processus classique au premier plan arrête son réseau. Une tâche reprise peut suspendre son contrôleur de terminal tout en gardant son processus géré connecté.

Exemples :
/background

/help /bind
-----------

Affecter une touche personnalisée à une fonction locale du programme
Utilisation : /bind KEY ACTION

Aucun raccourci personnalisé par défaut. Consultez /bindings keys et /bindings actions pour les noms acceptés.

Une nouvelle attribution remplace l'action de cette touche sur tous les serveurs ; les autres restent intactes.

Les raccourcis agissent dans le chat et les commandes, pas dans le collage, les mots de passe, les réglages, les lecteurs ni les confirmations.

Effet immédiat, mais /save input est requis pour conserver le changement. Sans raccourci actif, la navigation normale fonctionne.

Seules les fonctions locales nommées sont permises : aucune commande arbitraire, macro, action d'envoi ou expansion shell.

Une touche réservée au terminal peut ne jamais parvenir au programme ; l'attribution ne modifie pas les signaux du terminal.

Exemples :
/bindings actions
/bind F7 summary
/bind Alt-c command
/save input

/help /bindings
---------------

Lister les raccourcis personnalisés ou les actions et touches disponibles
Utilisation : /bindings [actions|keys]

Sans argument, affiche les raccourcis personnalisés de toute l'application. Une liste vide signifie aucun raccourci.

Utilisez /bind pour attribuer ou remplacer, /unbind KEY pour retirer et /unbind all pour tout effacer.

Touches disponibles : F1..F12, Ctrl-A..Ctrl-Z, Alt-a..Alt-z, Alt-0..Alt-9 et touches de navigation nommées.

Ctrl-H vaut Backspace, Ctrl-I vaut Tab, Ctrl-J et Ctrl-M valent Enter et Ctrl-[ vaut Escape : un même raccourci.

Alt utilise les minuscules sans Shift. Les touches de fonction/Alt dépendent du terminal et du multiplexeur.

Jusqu'à 64 raccourcis KEY=action dans [hotkeys] du fichier principal. /save input les enregistre.

Voir /help hotkeys pour la portée, la protection des brouillons et les signaux du terminal.

Exemples :
/bindings
/bindings keys
/bindings actions
/help hotkeys

/help /catchup
--------------

Lire cette conversation depuis votre dernier message envoyé
Utilisation : /catchup

Repart du dernier message ou acte envoyé localement dans le canal ou la conversation choisie. Les vues serveur et mentions n'ont pas ce repère.

Essaie d'abord un journal privé valable, actif lors de l'envoi du repère et toujours sain. Les identifiants sensibles ne servent pas de repère sur disque. Sinon, le repère encore présent en mémoire est utilisé.

Le lecteur disque affiche un instantané fixe: Up/Down déplace d'une ligne, Page Up/Page Down d'une page, Home revient au repère, End va à la fin et Escape revient au direct. Le trafic nouveau ne le déplace pas.

Le repli mémoire ouvre l'historique conservé au repère. Home atteint la page la plus ancienne; End ou Escape revient au direct. Les messages antérieurs restent consultables.

Un repère modifié ou remplacé n'est plus utilisable sur disque. Un nouveau processus ne restaure pas les anciens repères. Voir /help logging et /help history.

Exemples :
/catchup

/help /connect
--------------

Se connecter au serveur ou réutiliser la connexion enregistrée
Utilisation : /connect [-tls|-plain] [-nick NICK] HOST [PORT] | /connect

Commencez par /connect irc.example.org. Aucun profil, alias ni numéro de serveur n'est requis auparavant.

Un nouveau serveur utilise TLS vérifié sur le port 6697 et votre login systeme, ou user si celui-ci ne convient pas.

Un serveur correspondant conserve son port, son transport, son pseudonyme et son authentification configurés.

Utilisez -nick NICK pour un pseudo précis ou /nick NICK avant connexion. Les mots de passe ne sont pas des arguments positionnels.

Utilisez -plain pour IRC non chiffre (port initial 6667). -tls et -ssl choisissent TLS vérifié.

+PORT choisit aussi TLS. Un port numerique ordinaire ne désactive pas TLS. --tls, --plain et --nick sont acceptes.

La connexion est sélectionnée et la vue serveur/MOTD s'ouvre. Une connexion active identique n'est pas dupliquee.

Une destination différente obtient de nouveaux réglages d'authentification; identifiants et canaux ne sont pas copies.

/connect seul utilise le serveur choisi et ses réglages appliques. /saveconf mémorise le serveur par defaut pour le prochain lancement.

Si des profils bouncer partagent un hôte, choisissez avec /server NUMBER puis lancez /connect seul.

Les numéros de serveur existants restent acceptes. Le mode test est hors ligne; les changements demandent une sauvegarde explicite.

Exemples :
/connect irc.example.org
/join #chat
/saveconf
/connect
/connect -nick mynick irc.example.org +6697
/connect -plain localhost 6667

/help /dcc
----------

Proposer, examiner et gérer les transferts directs de fichiers
Utilisation : /dcc [list|NICK PATH|send [-address IPV4] [-port PORT] NICK PATH|accept NUMBER [DIRECTORY]|reject NUMBER|cancel NUMBER]

Sans argument, liste les transferts. /dcc NICK PATH propose un fichier sur le serveur sélectionné.

PATH est le texte littéral restant, espaces compris ; il est relatif au répertoire initial du processus.

Le client ne change jamais ce répertoire, même pendant la navigation ou en arrière-plan.

L'envoi court annonce l'IPv4 locale du lien IRC. Derrière NAT, utilisez -address avec votre IPv4 joignable et -port avec le port redirigé.

Aucune recherche d'adresse externe. Un lien IRC uniquement IPv6 nécessite une IPv4 explicitement indiquée.

DCC est une connexion directe non chiffrée. Le pair reçoit votre IP annoncée ; accepter une offre lui révèle aussi votre IP.

Les offres entrantes restent fermées jusqu'à /dcc accept NUMBER. DIRECTORY vise le répertoire initial et doit être privé et vous appartenir.

Les destinations existantes ne sont pas écrasées ; liens symboliques et fichiers spéciaux sont refusés. Le mode test n'ouvre ni fichier ni socket.

Utilisez /dcc reject NUMBER pour refuser ou /dcc cancel NUMBER pour annuler un transfert en cours.

Les numéros de transfert sont communs aux serveurs du processus. Fermer le serveur d'origine annule ses transferts ; couper IRC n'annule pas un transfert accepté.

Exemples :
/dcc alice file.txt
/dcc list
/dcc accept 1 ./downloads
/dcc send -address 203.0.113.20 -port 5000 alice file.txt
/dcc cancel 2

/help /list
-----------

Demander et filtrer l'annuaire des canaux du réseau
Utilisation : /list [MASK] [--min-users N] [--max-users N] [--name TEXT] [--topic TEXT] [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list show [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list clear

Demande les canaux au serveur IRC choisi ; la connexion doit être enregistrée. Seul MASK est envoyé comme filtre au serveur.

Les filtres sur le minimum/maximum d'utilisateurs, le nom et le sujet sont locaux, même sans filtres LIST avancés sur le réseau.

--sort accepte channel, users ou topic ; par défaut users décroissant. --limit 0 ne limite pas l'affichage du cache borné.

/list show affiche le cache ; --sort, --asc/--desc et --limit le trient ou le limitent localement sans nouvelle requête IRC. /list clear vide le cache.

Une déconnexion ou un refus de LIST conserve le cache partiel mais clôt la requête ; réessayez /list après inscription ou utilisez /list clear.

L'interface plein écran ouvre un navigateur de canaux triable ; le mode minimal utilise les mêmes options et /list show.

Utilisez /ls ou /cl pour les canaux locaux ; /list interroge le réseau.

Exemples :
/list
/list *linux* --min-users 5 --max-users 500
/list --topic help --sort users --desc --limit 100
/list show --sort channel --asc --limit 50
/list clear

/help /ls
---------

/help /panel
------------

Ouvrir le panneau de configuration interactif
Utilisation : /panel

Choisissez 0 (par défaut) pour les préférences de l'application, ou un panneau de profil 1..8 ; le panneau 1 modifie le profil principal. Ce sont des choix de panneau, pas des ID de tâches du shell.

Les préférences de l'application regroupent la conservation de l'historique, le mode d'envoi, le format de sortie, les avis de file d'attente et les suggestions de commandes pour tous les serveurs.

Elles fonctionnent sans serveur configuré. Les choix finaux sont 1 Enregistrer (par défaut) et 2 Appliquer sans enregistrer ; aucun n'établit de connexion.

Un panneau de serveur contient uniquement ses réglages de connexion, démarrage, authentification, mentions et exclusions.

Choisir un panneau ne change pas votre conversation.

Enter conserve la valeur affichée ; '-' vide un champ facultatif. Escape revient d'une question à la fois ; répétez pour quitter sans appliquer les modifications.

Tab sélectionne l'en-tête de la question. Appuyez sur ? à cet endroit pour l'aide sur l'option et son écran ; Tab ou Enter reprend la réponse.

Toute réponse modifiable conserve ? comme texte littéral, y compris en premier caractère et dans les masques à caractères génériques.

Les termes surveillés et masques d'exclusion se saisissent un par un ; une nouvelle entrée vide termine la liste.

La saisie des identifiants est masquée et les réponses de configuration n'entrent jamais dans l'historique des commandes. Les fichiers d'identifiants existants ne sont pas lus pendant la modification.

Pour une source GPG, choisissez Créer ou Utiliser un fichier existant. La création propose un chemin privé par défaut ; Enter l'accepte et prépare son répertoire (0700).

Toute autre destination doit se trouver dans un répertoire existant vous appartenant, de mode 0700. Le chemin est vérifié avant les questions sur la clé et le mot de passe.

La création demande ensuite l'empreinte complète d'une clé publique locale et le mot de passe deux fois. Aucun fichier ni lien symbolique existant n'est remplacé.

Les chemins d'identifiants sont enregistrés sous forme absolue. /autoauth status montre leurs emplacements configurés complets sans lire leur contenu.

Le chiffrement commence seulement après Terminer, laisse IRC réactif et n'utilise jamais de fichier temporaire en clair. Escape annule le travail en attente.

Si l'enregistrement de la configuration échoue, le résultat déjà chiffré reste disponible pour une nouvelle tentative explicite ; les fichiers référencés par une configuration enregistrée sont conservés.

Le mode test ne lance pas GPG et ne crée pas de fichiers d'identifiants. Déverrouillez la clé privée correspondante à l'extérieur du programme avant l'authentification.

Les choix finaux du panneau de serveur sont 1 Enregistrer et connecter, 2 Enregistrer seulement (par défaut), 3 Connecter une fois et 4 Appliquer seulement.

Ouvrir le panneau ou répondre aux questions précédentes n'applique rien, n'enregistre rien et ne connecte pas.

Connecter une fois applique sans enregistrer; Appliquer seul n'enregistré ni ne connecte. Une liaison active ne change jamais de cible ni ne se reconnecte implicitement.

Un échec de connexion n'annule pas les changements déjà appliques ou enregistrés par l'action finale.

Utilisez /quickstart pour une configuration abrégée du serveur, du transport, du port et du pseudonyme.

Exemples :
/panel

/help /set
----------

Choisir les préférences de saisie, de sortie et de présence pour toute l'application
Utilisation : /set send_mode direct|review | /set composer_mode line|fullscreen | /set output_format compact|full | /set queue_notices on|off | /set program_messages on|off | /set persistent_logging on|off | /set single_session on|off | /set default_interface idle|ncurses | /set command_suggestions alphabetical|common|history|frequent|contextual | /set part_message [TEXT] | /set quit_message [TEXT] | /set background_away on|off | /set background_away_message TEXT | /set autoaway_minutes 0..1440 | /set autoaway_message TEXT

direct est le mode par défaut : Enter envoie le texte ; plusieurs messages IRC imposent une confirmation.

review ajoute une étape de vérification volontaire avant de mettre les messages habituels en file.

output_format compact est le défaut : le chat choisi affiche [HH:MM:SS] <nick> texte.

output_format full inclut serveur, date et cible par ligne. compact conserve l'origine utile des mentions et diagnostics d'autres serveurs.

queue_notices off masque les avis ordinaires de file. En mode minimal, un envoi déjà vérifié évite l'avis redondant. Erreurs et confirmation multi-messages restent visibles.

program_messages off masque les avis locaux secondaires : brouillon annulé, saisie effacée ou brouillon conservé. Erreurs et confirmations de sécurité restent visibles.

persistent_logging on écrit le chat dans un .log privé (0600) sous le dossier privé (0700) de configuration. Désactivé par défaut ; limite 16 MiB : archiver puis basculer off/on. Fichier dangereux/occupé arrête le journal, pas le chat.

single_session on limite à un seul travail en arrière-plan du client : --resume sans numéro est clair. Plusieurs serveurs IRC restent possibles dans la même session.

default_interface choisit l'interface du prochain lancement neuf, si pris en charge, sans changer l'actuelle. /save input enregistre ce choix.

command_suggestions choisit l'ordre alphabétique, les commandes communes, récentes, fréquentes ou liées à l'écran d'origine.

composer_mode line garde une ligne de saisie sous le chat en direct ; fullscreen offre un éditeur multiligne et un volet chat. Défaut : line.

part_message et quit_message sont les motifs IRC par défaut ; un texte explicite /part ou /quit prime. Une valeur vide désactive le motif.

background_away envoie background_away_message après /background réussi ou perte du terminal. autoaway_minutes règle away après inactivité ; 0 désactive.

Seul l'état away créé par le client est effacé à la reprise ou à une vraie saisie locale. Un /away manuel n'est ni modifié ni effacé.

Common est le défaut. Contextual favorise les commandes de canal, dialogue, serveur ou client tout en gardant les autres correspondances.

Common suit un ordre utile prédéfini. Contextual retient l'écran d'origine, y compris le lecteur de résumé général.

Ces préférences s'appliquent à tous les serveurs. Utilisez /save input ou /save output pour les conserver.

/panel puis 0 modifie ces préférences et la limite globale d'historique.

Exemples :
/set send_mode review
/set composer_mode line
/set command_suggestions contextual
/save input
/set output_format full
/set queue_notices off
/set program_messages off
/set persistent_logging on
/set single_session on
/save output
