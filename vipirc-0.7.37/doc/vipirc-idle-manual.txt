/j = /join; /leave = /part; /message and /privmsg = /msg
/nickname = /nick; /names and /nicks = /users; /unaway = /back

Completion suggests canonical names; arguments are preserved literally and secret-history filtering is identical.

authentication
--------------
Use verified TLS with /autoauth sasl USER file PATH or /autoauth sasl USER gpg PATH.
The password file or decrypted GPG content supplies the credential; paths are literal.
Use /panel to create a new GPG-encrypted credential for an existing local public-key fingerprint.
Use an already-unlocked GPG key. No pinentry runs inside the chat editor.
Explicit plaintext password= and server_password= are also supported in private config files.
Choose only one source for each credential. /settings and /summary keep file locations redacted.
/autoauth status shows current and pending credential file locations without reading files or showing passwords.
Applied authentication settings take effect on the next disconnected /connect; /save persists them.
On a bouncer profile, use /panel to manage the required login and source together; /autoauth changes are refused.
Credential files must be owned regular files with mode 0600 or 0400; symlinks and parent traversal are refused.
The SASL credential limit is 1024 bytes; ordinary server PASS permits 503 bytes. An assembled ZNC login must also fit its one IRC line.
--check-config validates configuration and source selection without reading credentials or checking the login. See /help tls and /help bouncers.

bouncers
--------
Use /panel, select a server, then choose connection type znc or soju.
Enter the provider's bouncer hostname and TLS port, bouncer username, existing upstream network name and an optional stable client name.
Use one saved profile per upstream network. Select the intended profile before bare /connect when several use the same hostname.
The client assembles the login identity. ZNC uses the server-password source; soju uses the authentication-password source. Enter only the bouncer password, not a combined login string or a NickServ password.
Bouncers restore their joined channels. Local auto-join lists are not replayed and /autojoin edits are refused; use /join and /part to change memberships.
Explicit startup commands still run. Review them before enabling a bouncer profile to avoid unwanted repeated joins or service commands.
Automatic idle/background away is off for each bouncer profile unless its automatic-away setting is enabled. Manual /away and /back still work.
Known pushed history uses original UTC server timestamps, routes outgoing private chat to its recipient, and does not create fresh mentions, execute CTCP/DCC or mutate live state.
History storage stays bounded. There is no on-demand archive search, automatic network discovery or automatic creation of one profile per network.
Use /znc or /soju without arguments for service help. Their control text and service-target messages are excluded from input history and local echo; service replies are shown in the server view without persistent logging.
Recognized outgoing control copies are suppressed even when replay uses an old nickname. Editing can still show typed text, and the bouncer has its own logging policy.
The client connects only to the bouncer. Configure the bouncer's upstream TLS, network authentication and retention separately.
See doc/BOUNCERS.txt and the bouncer examples in examples/ for setup and the limits of recorded validation.

configuration
-------------
Default config file: $XDG_CONFIG_HOME/vipirc/config.ini; XDG_CONFIG_HOME must be absolute.
When XDG_CONFIG_HOME is unset or empty: $HOME/.config/vipirc/config.ini. --config FILE selects another file.
Minimalist mode uses the usual application configuration and saved server catalog.
[interface] history_lines= sets the retained-chat limit; other interface preferences remain saved.
[connection] holds server, port, tls, nick, username, realname, channel, autoconnect, auth and credential sources.
[bouncer] type=none|znc|soju, username, network, client and automatic_away select a per-network bouncer profile; see /help bouncers.
[input] send_mode=direct|review and [output] format=compact|full, queue_notices=true|false, program_messages=true|false, and persistent_logging=true|false are application preferences in the main config file.
[input] command_suggestions=common|history|frequent|alphabetical|contextual selects command ordering; common is the default.
[input] composer_mode=line|fullscreen selects the minimalist composer/command layout; line is the default and both layouts retain a live tail.
[input] use_signals=false disables terminal-generated signals while this client owns the tty. true enables the existing terminal signal mappings. Apply takes effect now; Save persists this primary-owned preference.
[hotkeys] contains optional KEY=action bindings, up to 64, with no defaults. It is owned by the primary config; see /help hotkeys.
[session] single_session=true|false controls whether more than one background job may exist; false is the default.
[session] default_interface=ncurses|idle is a primary-owned application preference. The supported startup choices are described below.
Compact output is the default. The main history_lines value controls native retention across all servers.
[mentions] word= and [ignore] mask= may repeat.
[autocommands] contains enabled, delay_seconds, interval_seconds and repeated command= lines for one server.
These command lines are literal plaintext in a private config; /autocommands manages them without exposing secret text in lists or history.
Saved extra servers use the adjacent .servers catalog and .d directory.
Connect with /connect HOST, then use /join #channel and /saveconf to remember your working configuration.
/saveconf saves preferences and healthy server profiles, and remembers the selected server for a later bare /connect.
/quickstart provides four connection questions. /panel uses 0 for application preferences and 1..8 for profiles; panel 1 edits the primary.
Panel edits remain private until Finish. Accepting an offered GPG destination can prepare its 0700 directory; encryption, configuration writes and connection actions wait for the final choice.
To retain changes across restarts, use /save for the selected server, /save input or /save output for the primary profile, or /saveconf for healthy profiles plus the selected default.
Saved configurations use <config_path>.commands for automatic personal count reads and writes; the main config does not store counts.
This private bounded file contains canonical names and counts only, never arguments or message history. Test mode does not read or write it.
[connection] edits staged by /autojoin or /autoauth take effect on the next disconnected /connect, without altering a live connection.
Config files are private; writes replace individual files atomically, not the whole workspace as one transaction. No import/export commands exist.
Unknown sections or keys and invalid values are errors. Configuration uses literal values, not shell quoting, escapes, variables or ~ expansion.
Ordinary values are trimmed at their ends. password= and server_password= preserve everything after = except the line ending; no inline comment or quotes should be added.
Save rewrites supported settings and replaces hand-written formatting/comments. Keep notes outside the generated configuration.
See /help authentication for secrets, /help tls for CA files, /help logging for disk transcripts and /help sessions for live-worker controls.
Default interface: ncurses. /set default_interface idle|ncurses chooses the next fresh launch; /save input saves the choice in the main config.
Explicit -i/--idle or -N/--ncurses overrides that launch without saving the override. Lowercase -n still selects the nickname.

deployment
----------
Use --background to launch a client session without a terminal or a welcome keypress.
Configure and save /autoconnect on for every server to start.
--background does not enable autoconnect by itself; --no-connect still suppresses startup connections.
The usual warning is printed once before detaching. Success confirms a local background job, not a successful IRC login.
Use --sessions and --resume [NUMBER] from a later terminal under the same user account.
--sessions includes attached jobs. --detach-session NUMBER non-destructively releases an attached terminal so it can be resumed elsewhere. --close-session NUMBER ends the selected job and every IRC connection.
Use the listed job ID, not a PID. Unresponsive workers and legacy workers lacking a requested control can fail. See /help sessions for recovery and upgrade steps.
A VPS reboot ends all old jobs, drafts and in-memory history. An OS startup job can launch a fresh client.
OpenBSD instructions and an optional rc.d example are in doc/OPENBSD-VPS.txt.
Run the client as a normal user with absolute config and credential paths. A locked GPG key cannot prompt at boot.
--check-config validates settings, not credential access, DNS, TLS or IRC login.
Use --reconnect for temporary network outages; process-crash supervision is a separate operating-system task.
Launchers must leave children waitable: ignored SIGCHLD or automatic child reaping makes first background startup, resolver or credential-helper creation fail. A managed re-detach creates no new worker.

history
-------
Recent displayed records and command history are bounded in memory. Persistent logging is optional and disabled by default.
Changing a view replays its retained recent records; /mentions replays retained matching source lines.
The application history setting caps records across all servers/views together; edit it through /panel, then 0.
Retention is limited to the smaller of that setting and 2048 records, with a separate 512 KiB hard byte cap.
/catchup in a channel or query starts at your most recent locally sent composition. It tries an eligible private log, then retained memory; /help catchup explains the two readers.
Durable catch-up is per server and conversation. Persistent logging must already be enabled when you send the anchor; it is a private plaintext transcript capped at 16 MiB per saved profile, not encrypted storage.
Command recall retains at most 64 entries and 64 KiB, evicting the oldest. /clear clears conversation history, not command recall.
Recent history suggestions use these complete lines. Delete removes a selected history row.
Most-used suggestions instead use at most 96 canonical command names and bounded counts in <config_path>.commands.
For saved configurations, accepted commands and frequency resets update that private file automatically. Arguments, targets and messages are not persisted in it.
Unsaved profiles keep counts in memory until the first successful Save. Missing or unusable count files do not prevent startup.
Help and multi-line command responses use a separate reader backed by a 512 KiB bounded buffer. They do not become chat history.
Accepted commands can be recalled in the command editor. Authentication changes, keyed joins and sensitive service messages are omitted.
Compose Up/Down moves the caret; it does not recall sent chat. Only accepted command lines are recalled in Command.
Same-interface detach/resume retains drafts and recall. Switching interfaces, where supported, discards drafts, recall and setup forms; exit or reboot also ends retained in-memory chat and catch-up anchors.
Saved frequency counts contain names only. Old plaintext logs survive exit but are not automatically imported into a new session or into the editor.
/clear removes retained memory for a view, not its old disk transcript. Bouncer replay is separately supplied by the bouncer.
The default application history limit is 500 records.

hotkeys
-------
In full ncurses, App -> Key bindings or /bindings opens an editable table with Apply, Save and Escape/Cancel; -i uses the commands.
Custom key bindings are optional and empty by default. Existing navigation and editor controls remain available.
Use /bindings to inspect the list, /bindings keys for key names and /bindings actions for the local function list.
Assign with /bind KEY ACTION; replace by binding the same key again. Remove with /unbind KEY or /unbind all.
Changes apply to all servers immediately; /save input saves them in the primary configuration. Extra server profiles do not override that table.
The config form is [hotkeys] followed by one KEY=action per line, up to 64. Duplicate keys, including terminal aliases, are errors.
Custom actions run only in the main chat and command prompt. They do not override passwords, setup, paste, readers or confirmation screens.
In the minimalist interface, read-only shortcut readers preserve the draft/caret. A shortcut that changes its target or editor refuses a nonempty draft; finish it or deliberately clear it first.
The allowlist has no send action, arbitrary commands, shell code or text macros. Background and quit have their existing program effects.
F1..F12, Ctrl-A..Z, Alt-a..z/0..9 and named navigation keys are available; ordinary printable characters remain text.
Ctrl-H/Backspace, Ctrl-I/Tab, Ctrl-J/Ctrl-M/Enter and Ctrl-[/Escape share terminal bytes and cannot have separate bindings.
Terminal signals and terminal/multiplexer shortcuts take precedence. A Ctrl-C or Ctrl-Z binding works only if that byte reaches the application; no terminal key is reassigned.
Recognized bracketed paste cannot run bindings. Unframed paste is indistinguishable from typing. See /help keys for terminal timing and paste limits.

keys
----
Log: / opens Command; ? explains the selected conversation/watch log. Other printable keys open Compose with that character retained.
Custom bindings may override these controls in main chat/Command; none are assigned by default. See /help hotkeys.
Live log: Up scrolls a row older, Page Up a page, Home the oldest retained page. Down/Page Down/End stay live; Left/Right/Delete/Backspace do not open Compose.
Insert or Enter opens empty Compose. Arrows, Home/End, Delete and Backspace edit text. Tab/Shift-Tab completes nicknames in Compose and command names in Command.
Line composer mode keeps one input row below the live tail; fullscreen keeps a multi-line editor with a smaller live-tail pane.
Command Down selects suggestions. Up/Down moves through them; Up from the first returns to the input.
Suggestion Enter inserts without running. Read/edit it, then press Enter separately after display to execute.
Command Up recalls matching accepted history; Down returns toward the original input. Compose Up/Down moves the caret, even when held; Enter submits.
Delete removes a selected Recent history row or resets a selected Most-used count. Catalog commands remain available.
? on a selected command explains it and links to command-screen help. In all text editors, ? is ordinary text.
Review uses a temporary alternate screen; its draft/prompt never enter chat history. Fresh Enter confirms; Escape or typing restores the editor/draft/caret. Up/Down, Page Up/Down and Home/End browse it.
Help/response Up/Down scrolls; Page Up/Down changes page; Home/End reaches the beginning/end.
Roster Enter returns to the log; Help and other response readers use Enter to scroll one line.
In the reader, / opens Command with normal completion/history. Escape cancels that prompt back to the reader.
In a summary reader, r refreshes the snapshot; ? explains the response and its reader.
In context help, Enter follows the highlighted About screen link. Escape returns to item help, then to the exact originating screen.
Setup Tab selects the question heading; ? explains its option/screen. Tab/Enter returns to answer editing.
Executing a command replaces the previous response. Short acknowledgments return to the log; short errors keep the command editable.
Escape cancels a Compose/Command editor to the log. From Review, Escape returns to that editor without discarding the draft. Escape on the log backgrounds the client.
Bare Escape waits about 500 ms; a sequence in progress allows 1000 ms between continuation bytes. Networking continues.
Complete key sequences are handled immediately. An opening paste marker delayed after its first Escape past that grace can background the client.
Once paste capture starts, its closing marker remains recognized across arbitrarily delayed, split reads.
Terminal interrupt/quit/suspend mappings are preserved; signals are disabled by default.
[input] use_signals=false is the default. Ctrl-C/Ctrl-Z cancel unfinished input; true enables terminal interrupt/suspend signals without remapping keys.
Enabled terminal signals terminate or suspend after restoring the terminal; fg resumes a suspended job.
Ctrl-D is inert unless bound in main chat/Command. /quit exits; /background releases the terminal while networking continues.
Routine screens omit recurring key hints; this topic remains the complete keyboard reference.
Recognized bracketed paste stays literal. Keys wait for a visible editor, fresh input and a pause. Tiny/failed frames cannot approve it; resize and release held keys.
Watch-log paste opens Compose with literal slashes. Paste inside Command stays there; CR/LF/Tab become spaces. Review it, then press a fresh Enter.
Unframed paste is indistinguishable from typing; use bracketed-paste support.

limits
------
IRC limits are byte limits, not counts of displayed glyphs. UTF-8 characters can occupy more than one byte.
The client computes a message budget including target, command and relay overhead; it never splits a UTF-8 scalar.
At one-message capacity, further text is blocked until Enter explicitly acknowledges continued editing; that Enter sends nothing.
A multi-message composition still requires separate consent before queueing, even in direct mode. Chat is paced at one line per 1.2 seconds.
A send plan has at most 64 messages and 16384 bytes of composed text. More text must be shortened or sent deliberately in separate submissions.
There are at most 8 server slots and 32 views per server, including reserved views.

logging
-------
Persistent logging is optional and off by default. /set persistent_logging on enables it; /save output saves that application preference.
Each saved server profile appends to CONFIG_PATH.log. The final parent directory must be owned with mode 0700; the file must be owned, regular, single-link and exactly 0600. Symlinks and parent traversal are refused.
Logs are plaintext, not encrypted backups. Each file stops at 16 MiB. An unsafe path, write error or busy file stops logging with a visible error while live chat continues.
Archive a full log outside the active path, then toggle logging off/on to resume. Rotation or rewriting can invalidate the previous catch-up anchor; send a new eligible message before relying on a later absence's disk catch-up.
Known credential/service traffic and unsent drafts are excluded, including replayed authentication under old nicknames and qualified service targets. Ordinary chat, unknown service formats and custom secret text may still be recorded. Server and bouncer retention are separate policies.
/catchup can use a healthy log only when its exact locally sent anchor was recorded in that running session. It never asks the bouncer to fetch an archive and does not import old logs after a process restart.
/clear clears memory only. Existing log files survive quit, --close-session and configuration saves. Turning logging off stops new records without deleting old ones.
Regular disk I/O can delay the process on slow storage. See /help catchup, /help history and SECURITY.md for the limits.

messages
--------
Use /join #channel to join and select a channel, or /query NICK to open a private conversation.
Select a retained channel with /channel. Use /msg TARGET TEXT for an explicit destination or /me TEXT for an action.
/query opens a conversation without sending; /pm is an alias. /ql keeps queries separate from channels.
Direct send is the default; /set send_mode review adds a review stage. /set composer_mode line|fullscreen changes presentation.
Reaching one-message capacity requires a continued-editing acknowledgement; splitting still requires separate send consent.
Joining and authentication must finish before messages can be queued. /cancel cancels queued chat, not already-sent text.

reconnect
---------
The shell option --reconnect enables retries for this process; it does not save a setting or initiate a connection.
Without this option, a failed connection still requires /connect. /autoconnect controls startup only.
Temporary DNS, refused/lost connections and server timeouts retry after 5, 10, 20, 40, 80, 160 and then 300 seconds.
A registered connection lasting at least 60 seconds resets that backoff. Polling continues without blocking sleeps.
Certificate verification, authentication, malformed-protocol and configuration errors remain disconnected for correction.
A server ERROR before registration is held; one after registration can trigger a reconnect.
Explicit /disconnect cancels a pending retry. A later /connect starts a fresh attempt.
Retries use the current connection settings; staged edits still need an explicit /connect.
Pending chat messages are discarded on disconnect and are never automatically resent.
Configured authentication and enabled startup commands run again on a new connection. Direct profiles replay autojoin after registration/authentication; bouncers restore their own memberships.
Offline test mode never reconnects to the network.

security
--------
Remote text is sanitized before terminal output. Inputs are parsed as local IRC commands, never shell commands.
There is no /raw, shell escape or automatic file acceptance. Recognized bracketed paste never submits a command.
TLS verifies the server identity. SASL, server PASS and recognized private authentication commands require verified TLS. Keep the system TLS library patched as well as the client; see SECURITY.md.
A custom CA bundle must be a nonempty regular PEM file of at most 16 MiB; it never prompts for a password.
Configured passwords are redacted from help/settings. Recognized credential commands are excluded from recall; secrets typed as ordinary text may still be retained.
No disk conversation transcript is enabled by default. Configuration changes require an explicit save.
A process under the same account, the IRC server/bouncer, and a compromised terminal or operating system remain outside these protections. TLS is not end-to-end chat encryption.
Optional logs and inline configuration secrets are plaintext. Known sensitive commands are filtered, but arbitrary secrets in ordinary chat cannot be recognized reliably.
See /help tls, /help authentication, /help logging and SECURITY.md for exact boundaries and historical review scope.

sessions
--------
A job is one running client worker with all of its servers, transfers, drafts and retained history. A server number inside the application is not a shell job ID.
From a shell, run the application with --sessions. Inspect its current attached/detached status and use that listed job ID, not a process ID.
If an old SSH terminal still owns the job, run --detach-session NUMBER, then --resume NUMBER. Detach releases the controller while keeping IRC and state alive.
Bare --resume selects only a sole verified detached job. Multiple jobs require a number; an attached job is busy until detached. Job numbers may be reused after exit.
Use --close-session NUMBER only when the whole job should end. It closes IRC and transfers and loses unsaved drafts and in-memory history; saved configs and existing logs remain.
Close reports success only after verified cleanup. If it times out, recheck --sessions: the request may finish later. Failure does not remove a live endpoint or signal a guessed PID.
Only a managed job can survive terminal loss. An ordinary foreground process that has never backgrounded is not made resumable by SSH disconnection. Start with --background or use /background first.
A job belongs to the same Unix account and host, with one attached terminal at a time. Another program under that account is within the local trust boundary.
Installing an executable does not replace a running worker's code. Save desired configuration, quit or close the old worker, check the installed --version, then start a fresh worker.
A legacy worker may lack newer controls or interface switching. Keep its compatible executable until it is stopped if required for attachment.
The client does not change SSH idle-timeout policy. See /help background, /help deployment and doc/SESSION-CONTROLS.txt.

startup
-------
Run the program, dismiss the welcome, then type /connect irc.example.org and /join #channel.
No server profile, alias or number needs to be created first. /server HOST is an alias for direct connection.
When no nickname is supplied, your valid system login name is used, with user as the fallback. No nickname prompt is required.
Use /saveconf to save your configuration and selected default. Next launch, /connect reuses it.
Saving does not enable autoconnect; that remains an explicit choice. /quickstart and /panel are optional guides.
Shell options also work: --server HOST, --channel '#CHANNEL' and --nick NICK. Quote #CHANNEL for the shell.
At normal startup, --nick, --port, --channel, --tls, --plain and --ca-file override the remembered default.
An explicit --server selects the first connection instead. --init-config and --check-config use the main config file.
Changing --server to a different host clears the old host's credentials, CA override, bouncer identity, channels and startup commands.
If the remembered default is unavailable, specify --server or repair it before applying connection overrides.
Autoconnect, autojoin and autoauth belong to each saved server profile. /help autoconnect explains the toggle.
--no-connect suppresses startup connections; --test-mode simulates activity without network or config writes.
--sessions lists attached and detached jobs. --resume [NUMBER] reattaches; /help background explains selection.
--close-session NUMBER closes the selected whole job and all its IRC connections after verified completion. NUMBER is a job ID, not a PID.
After terminal loss, use --sessions, then --detach-session NUMBER and --resume NUMBER. A running worker keeps its loaded code until restarted; see /help sessions.
-h/--help and -v/--version work without a terminal.
Default interface: ncurses. /set default_interface idle|ncurses chooses the next fresh launch; /save input saves the choice in the main config.
Explicit -i/--idle or -N/--ncurses overrides that launch without saving the override. Lowercase -n still selects the nickname.
From the shell: vipirc --sessions; vipirc --detach-session NUMBER; vipirc --resume NUMBER; vipirc --close-session NUMBER.
Bare vipirc --resume retains the worker's current interface. vipirc -i --resume NUMBER selects minimalist; vipirc -N --resume NUMBER selects ncurses. Changing interfaces keeps IRC/history/transfers but discards drafts, pending send reviews, command recall and unapplied forms.
vipirc -i --manual prints this complete manual.

tls
---
Verified TLS is the default. The requested server hostname or numeric address and its certificate chain must verify; there is no verification bypass or silent plaintext fallback.
A port number alone does not disable TLS. Explicit --plain or /connect -plain selects unencrypted IRC and cannot use configured account/server credentials.
Use the provider's exact TLS hostname and port. A failure may be a wrong endpoint, expired/untrusted certificate or local trust configuration; inspect the concrete connection error before changing settings.
By default the TLS library's trust store is used. --ca-file FILE or connection ca_file= selects a custom PEM CA bundle; it does not pin a leaf certificate.
A custom bundle must be a nonempty regular file of at most 16 MiB. An ordinary symlink to a regular CA file is allowed; secret/config paths have stricter no-symlink rules.
The custom file is opened once, bounded and checked for size changes while read. FIFOs, devices and other nonregular inputs are rejected, and password-protected PEM cannot open an interactive prompt.
Bounded file size does not bound regular-file or network-filesystem I/O latency. Use a trustworthy readable CA bundle on suitable storage.
--check-config does not perform a handshake or prove that a CA or credential source will work. --test-mode never contacts a server.
TLS protects this connection only. With a bouncer, the upstream connection and retained plaintext history are controlled by the bouncer separately.

troubleshooting
---------------
Resume says busy after SSH loss: run --sessions, verify the job, then --detach-session NUMBER followed by --resume NUMBER. See /help sessions before using destructive --close-session.
Up does not recall text: Compose edits message text; Command recalls accepted commands. Open Command with / from the log. Sent chat and sensitive commands are not recall history.
A wrapped message seems clipped: the input view reserves rows for its editor and shows the newest visual rows above it. Leave the editor or reselect the channel to inspect retained text; visible rows alone do not prove remote delivery.
Changing channels showing the complete text indicates a viewport difference. If a rendering fault persists, record interface, composer mode, terminal dimensions, locale and sanitized steps without sharing passwords or private transcripts.
No channels after connect: inspect the server view and finish registration/authentication. Direct profiles use /autojoin list; bouncers restore memberships and use /join or /part.
Authentication fails: check the account, the one selected source, private permissions, TLS endpoint and GPG agent availability. /autoauth status shows configured paths without reading secrets.
Catch-up unavailable: the anchor may have rolled out, logging may have started later/stopped, or the log changed. See /help catchup and /help logging; saved logs do not recreate a dead worker.
An applied setting seems ignored: connection changes need a disconnected /connect, while saving and startup autoconnect are separate choices. Interface and terminal-signal launch preferences require a fresh launch.
Background/helper startup fails with child ownership: correct the launcher's SIGCHLD/automatic-reaping policy so the client can wait for its children.
Use --check-config for configuration diagnostics and doc/TROUBLESHOOTING.txt for ordered checks. Offline --test-mode tests the interface, not DNS, TLS, credentials or a real bouncer.

The command system
------------------
Press / on the log to open Command; the opening slash is already inserted. Enter with input focus runs the edited command; Escape cancels it.
Syntax: /COMMAND ARGUMENTS. Names are case-insensitive; use the shown option words. UPPERCASE words are placeholders, [items] optional, and | means choose an alternative.
Enter one command at a time. Spaces separate arguments; there is no shell quoting, expansion or chaining. Shell launch options belong outside this editor.
TEXT and credential PATH use the literal remainder, including spaces. To paste a complete /command, remove the prefilled slash first; pasted newlines become spaces, not separate commands.
Home/End/Delete/Backspace edit. Tab/Shift-Tab completes command names; Up from input recalls accepted history.
Down selects suggestions; Enter inserts the selected command for editing. A separate Enter after display executes it.
Choose Common, Recent history, Most used with this configuration, Alphabetical or Contextual in application Settings.
Common is a curated useful order. Contextual remembers the actual screen that opened command entry. Other prefix matches remain available.
? on a selected suggestion opens item and screen help. In the input it remains ordinary text.
Delete removes a selected recent entry or resets a personal frequency count; it never removes a catalog command.

/background - Keep connections running and release the terminal
---------------------------------------------------------------
Usage: /background

Detaches the running session after restoring the terminal. The shell receives this application's numbered resume command.
From the shell, --sessions lists this program's attached and detached private jobs; --resume resumes its sole available detached job.
Use --resume NUMBER when more than one job exists. NUMBER is the job ID, not a process ID; it stays stable until exit and may then be reused.
--detach-session NUMBER releases an attached terminal/controller but keeps the worker, IRC connections, drafts and history alive for --resume NUMBER.
--close-session NUMBER ends the whole job, all IRC connections and transfers, and its unsaved drafts and in-memory history. Success is reported only after verified completion.
If resume is busy after a lost SSH terminal, list jobs, detach that job, then resume it. See /help sessions for the recovery sequence.
An unresponsive worker or a legacy worker lacking a requested control can fail. Installing a binary does not update a running worker; restart it deliberately after an upgrade.
Resume redraws retained in-memory scrollback even when no chat arrived while detached. /set single_session on refuses a second background job so bare --resume remains unambiguous.
To start without a terminal, use --background from the shell; see --help for this program's options.
When background_away is on and this profile permits automatic away, /background or managed terminal loss queues the configured AWAY after detach. Resume clears only that client-generated away state; a manual /away is preserved.
Add --reconnect to retry transient connection failures. See /help deployment and /help reconnect.
No terminal multiplexer is required. A pending resolver or credential helper can require a retry.
Suspending an ordinary foreground process pauses its networking. A resumed job can suspend its foreground controller while its managed worker continues networking.
From the shell: vipirc --sessions; vipirc --detach-session NUMBER; vipirc --resume NUMBER; vipirc --close-session NUMBER.
Bare vipirc --resume retains the worker's current interface. vipirc -i --resume NUMBER selects minimalist; vipirc -N --resume NUMBER selects ncurses. Changing interfaces keeps IRC/history/transfers but discards drafts, pending send reviews, command recall and unapplied forms.

Examples:
/background

PORT defaults to 6697. A different port does not disable TLS; plaintext must be explicitly configured.
connect/disconnect do not change selection. close removes a secondary session/catalog entry, not its profile file.
Minimalist server numbers are 1..8, with primary 1. The primary remains available; disconnect it instead of closing it.
Numbers remain stable for the lifetime of their sessions. Panel 0 is reserved for application preferences.

Examples:
/server irc.example.org
/join #chat
/saveconf
/servers
/server 1

----------------------------------------------
Usage: /servers

A loaded profile stays available even when it is not connected.

/set - Choose application-wide input, output and presence preferences
---------------------------------------------------------------------
Usage: /set send_mode direct|review | /set composer_mode line|fullscreen | /set output_format compact|full | /set queue_notices on|off | /set program_messages on|off | /set persistent_logging on|off | /set single_session on|off | /set default_interface idle|ncurses | /set command_suggestions alphabetical|common|history|frequent|contextual | /set part_message [TEXT] | /set quit_message [TEXT] | /set background_away on|off | /set background_away_message TEXT | /set autoaway_minutes 0..1440 | /set autoaway_message TEXT

direct is the default: Enter submits the composition, with mandatory consent if it needs multiple IRC messages.
review adds a deliberate review step before ordinary messages are queued.
output_format compact is the default: selected chat shows [HH:MM:SS] <nick> text.
output_format full includes the server, date and target on each chat line. Mentions and other-server diagnostics retain necessary origin context in compact mode.
queue_notices off hides routine queued/paced acknowledgements. In the minimalist frontend, an explicitly reviewed send omits its redundant routine queue acknowledgement even when this setting is on. Errors and multi-message confirmation always remain visible.
program_messages off hides low-priority local feedback such as draft-cancelled, input-cleared and preserved-draft notices. Errors and safety confirmations remain visible.
persistent_logging on appends retained server/conversation lines to an owned 0600 .log file in the saved configuration's owned 0700 directory. It is off by default. Each log stops at 16 MiB; archive it and toggle logging off/on to resume. Unsafe files or a busy log stop logging with an error; live chat continues.
single_session on permits only one background job in this client namespace, so a bare --resume is unambiguous. Multiple IRC servers remain available inside that session.
default_interface controls the next fresh launch where interface selection is supported. It does not switch the current interface. /save input persists this application preference.
command_suggestions chooses alphabetical order, common commands, recent command history, most-used commands, or commands relevant to the originating screen.
composer_mode line keeps one input row below the live tail; fullscreen keeps a multi-line editor while reserving a live-tail pane. Line is the default.
part_message and quit_message provide default IRC departure reasons; an explicit /part or /quit message overrides them. Empty part_message or quit_message disables that default text.
background_away sends background_away_message after a successful /background or managed terminal loss. autoaway_minutes sets local-idle auto-away; 0 disables it.
Only client-generated away state is cleared automatically on resume or genuine local input. A manual /away is never overwritten or cleared by these features.
Common is the default. Contextual prioritizes channel, query, server or client commands while retaining matching commands from other groups.
Common uses a curated useful order. Contextual remembers the actual screen that opened command entry, including a client-wide summary reader.
These are application preferences and apply across servers. Use /save input or /save output to persist them.
/panel, followed by 0, edits these preferences and the global history limit together.
Default interface: ncurses. /set default_interface idle|ncurses chooses the next fresh launch; /save input saves the choice in the main config.
Explicit -i/--idle or -N/--ncurses overrides that launch without saving the override. Lowercase -n still selects the nickname.

Examples:
/set send_mode review
/set composer_mode line
/set command_suggestions contextual
/save input
/set output_format full
/set queue_notices off
/set program_messages off
/set persistent_logging on
/set single_session on
/save output

/soju - Control the selected soju bouncer
-----------------------------------------
Usage: /soju [COMMAND]

Requires a connected soju profile configured in /panel. No argument asks BouncerServ for help.
COMMAND is sent as one paced private message, without local echo or command history.
A direct IRC connection cannot use this shortcut. Replies appear in the server view.
Use the bouncer's own help for account and network commands.

Examples:
/soju
/soju network status

/summary - Summarize all current server sessions and activity
-------------------------------------------------------------
Usage: /summary

Shows every server, channel 0, channel/query views, unread activity, mentions, outgoing queues, startup commands and file transfers.
This is a local snapshot and works while disconnected. Press r in its reader, or run it again, to refresh.
Opening it does not change your conversation or mark anything read. The copied mentions feed is excluded from activity totals.
Mentions may also be unread messages; these totals are not added together. Joined and left channel views are identified separately.
The report uses its own scrollable reader and preserves drafts. Slash opens command entry; cancelling returns to the snapshot.
A failed refresh retains the previous snapshot. No network request is made by opening or refreshing it.
Credentials and the contents of queued messages or automatic commands are never printed.

Examples:
/summary

/unbind - Remove one or all custom key bindings
-----------------------------------------------
Usage: /unbind KEY|all

Removing a key restores its ordinary behavior wherever it had a custom action. all clears only the custom binding list.
The change applies across servers immediately. Use /save input to retain it after restart.

Examples:
/unbind F7
/unbind all
/save input

/users - Print the current or named channel's known users
---------------------------------------------------------
Usage: /users [#CHANNEL]

This is a textual roster, not a visibility toggle. User mode prefixes are included when known.
The roster opens in a separate reader, even when empty. Enter, Escape or q returns to the selected chat log.
Up/Down and Page Up/Down scroll the roster. In Help, Enter continues scrolling.
An incomplete or capacity-limited NAMES reply is labelled. It does not send WHOIS requests.

Examples:
/users
/users #ircnow

/watch - Manage extra literal mention strings
---------------------------------------------
Usage: /watch [list|add TEXT|remove TEXT]

Nickname mentions always remain enabled. Add/remove treats the remainder as literal text, not a regular expression.
Up to 32 additional strings of 1 to 127 UTF-8 bytes are supported per server. Use /save to persist.

Examples:
/watch list
/watch add release day
/watch remove release day
/mentions
