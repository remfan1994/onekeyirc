Configuration is literal INI: no shell, variable or tilde expansion. Unknown sections/keys and invalid values fail validation. Files are bounded at 64 KiB. Configuration and secret path traversal rejects symlink components and '..'. Reading an existing config requires an owned regular file that is not writable by another user. Inline credentials and any nonempty automatic- command list, even disabled, require exact mode 0600 or 0400. Reading config or credential files does not require a private parent directory. Saving requires an owned final parent with no group/other permissions; use mode 0700 for the ordinary private-directory layout. Generated configs use mode 0600 and private atomic replacement. Save rewrites supported values and replaces comments. --init-config uses atomic no-clobber publication: an existing object, including one created during initialization, is never replaced. A reported cleanup/directory-sync error after publication can leave the completed private config in place. Filesystems without hard links fail safely. Transcript logging has stricter exact-mode directory checks, described below.

Plaintext and GPG credential sources must be owned regular files with exact mode 0600 or 0400. Decrypted/plaintext passwords are one nonempty line: SASL permits up to 1024 bytes; server PASS up to 503 bytes. The complete ZNC identity-plus-password must also fit that bounded PASS frame. Credential selection has no fallback to another source when the selected source fails.

GPG decryption starts after verified TLS. It uses direct fixed arguments, bounded nonblocking pipes, a separate process group and a five-second deadline. The application does not invoke a shell, pass a secret in argv, create a plaintext temporary file, fetch keys, start helper daemons or prompt for a key passphrase. Unlock a protected key outside the client. Ciphertext input and created ciphertext are bounded at 64 KiB; helper status is bounded at 16 KiB. Success requires completed integrity-protected decryption and a successful helper exit. Diagnostics do not print decrypted text/helper output.

The setup panel can encrypt a new password with an existing local key's full 40/64-hex fingerprint. Hidden password/confirmation buffers stay bounded. Only the final explicit action starts encryption. It creates no public key. The offered default destination is beside the selected profile; merely viewing it creates nothing. Explicit acceptance may create missing owned mode-0700 parents. Custom parents must already exist; existing directories are not chmodded. Publication is mode 0600 and no-clobber, with directory/file identity and destination conflicts checked again before publication.

Apply only or Connect once can create the explicitly requested ciphertext without saving configuration. A failed config save can leave completed ciphertext for retry. Cancellation removes only unchanged files created by that attempt; it retains saved references and conservatively retains a file when the existing config cannot be safely checked. Publication followed by a sync error may therefore leave a reported file. Empty created directories can remain. Retry rechecks complete ciphertext, private mode and inode.

Temporary credential buffers are wiped where owned by the application. Inline values remain in config/session memory while required for Save or reconnect. This does not prove erasure from library/helper memory, swap, backups, snapshots or privileged memory inspection. Do not include real credentials in a report.
