La configurazione è INI letterale: non si espandono shell, variabili o tilde. Sezioni o chiavi sconosciute e valori non validi causano errore di convalida. I file sono limitati a 64 KiB. L'attraversamento dei percorsi di configurazione e segreti rifiuta componenti di link simbolici e '..'. La lettura di una configurazione esistente richiede un file regolare di proprietà dell'utente e non scrivibile da altri utenti. Le credenziali in linea e qualunque elenco non vuoto di comandi automatici, anche se disabilitato, richiedono esattamente il modo 0600 o 0400. Per leggere non occorre una directory madre privata. Per salvare, la directory madre finale deve appartenere all'utente e non concedere permessi al gruppo o ad altri; usare il modo 0700 per la normale struttura privata. Le configurazioni generate usano il modo 0600 e sostituzione atomica privata. Save riscrive i valori supportati e sostituisce i commenti. --init-config pubblica in modo atomico senza sovrascrivere: non sostituisce mai un oggetto esistente, anche se creato durante l'inizializzazione. Un errore segnalato di pulizia o sincronizzazione della directory dopo la pubblicazione può lasciare al suo posto la configurazione privata completa. I file system senza collegamenti fisici falliscono in sicurezza. Il log delle trascrizioni applica controlli più rigorosi dei modi esatti delle directory, descritti sotto.

Le sorgenti di credenziali in chiaro e GPG devono essere file regolari di proprietà dell'utente con modo esatto 0600 o 0400. Le password decifrate o in chiaro occupano una sola riga non vuota: SASL consente fino a 1024 byte, PASS del server fino a 503 byte. Anche identità ZNC completa più password devono rientrare nel frame PASS limitato. Se la sorgente scelta fallisce, non si passa a un'altra sorgente.

La decifratura GPG inizia dopo la verifica di TLS. Usa argomenti diretti fissi, pipe non bloccanti con limiti, un gruppo di processi separato e una scadenza di 5 secondi. L'applicazione non invoca una shell, non passa segreti in argv, non crea file temporanei in chiaro, non scarica chiavi, non avvia demoni ausiliari e non richiede la passphrase di una chiave. Sbloccare una chiave protetta fuori dal client. L'input cifrato e il testo cifrato creato hanno un limite di 64 KiB; lo stato del processo ausiliario è limitato a 16 KiB. Il successo richiede decifratura completa con protezione dell'integrità e uscita riuscita del processo ausiliario. La diagnostica non stampa testo decifrato o output dell'ausiliario.

Il pannello di configurazione può cifrare una nuova password con l'impronta completa di 40/64 caratteri esadecimali di una chiave locale esistente. I buffer nascosti della password e della conferma hanno limiti. Solo l'azione finale esplicita avvia la cifratura; non viene creata alcuna chiave pubblica. La destinazione predefinita suggerita è accanto al profilo selezionato: visualizzarla non crea nulla. Il consenso esplicito può creare directory madri mancanti, di proprietà dell'utente e con modo 0700. Le directory madri personalizzate devono già esistere; sulle directory esistenti non viene eseguito chmod. La pubblicazione usa modo 0600, senza sovrascrittura, e ricontrolla identità di file/directory e conflitti di destinazione prima di procedere.

Apply only o Connect once possono creare il file cifrato richiesto esplicitamente senza salvare la configurazione. Se Save fallisce, il file cifrato completo può rimanere per un nuovo tentativo. L'annullamento elimina soltanto i file immutati creati da quel tentativo; conserva i riferimenti salvati e, per prudenza, conserva un file quando non è possibile controllare in sicurezza la configurazione esistente. Un errore di sincronizzazione dopo la pubblicazione può quindi lasciare un file segnalato. Possono rimanere directory vuote create. Il nuovo tentativo ricontrolla l'intero file cifrato, il modo privato e l'inode.

I buffer temporanei delle credenziali di proprietà dell'applicazione vengono azzerati. I valori in linea rimangono nella memoria di configurazione/sessione finché necessari per Save o per riconnettersi. Ciò non dimostra la cancellazione dalla memoria delle librerie o dei processi ausiliari, dallo swap, dai backup, dalle istantanee o da un'ispezione privilegiata della memoria. Non includere credenziali reali in una segnalazione.
