Arabic terminal display (language pack r9, experimental)
=======================================================

STATUS

Arabic translation and terminal rendering are separate tasks. The catalogs
contain logical UTF-8 text. A terminal without Arabic shaping and bidirectional
layout can show that text with disconnected letters or the wrong reading order.

The optional visual mode shapes and reorders temporary display rows through the
system FriBidi shared library. r8 enabled this in minimalist screen readers,
labels and retained-history panes. r9 also covers the ordinary live WATCH log
and its notices, which had still bypassed conversion. It rejects invalid UTF-8
lead bytes and matches the signed FriBidiLevel return type of the public ABI.

USE

Use these commands only in a UTF-8 terminal without its own Arabic bidi/shaping:

    ONEKEYIRC_LANG=ar ONEKEYIRC_ARABIC_VISUAL=1 ./onekeyirc
    VIPIRC_LANG=ar VIPIRC_ARABIC_VISUAL=1 ./vipirc -i

Install the system's FriBidi package if the shared library is absent. The
application does not download or bundle it and has no hard link-time FriBidi
dependency. If the library or dynamic loader is unavailable, logical UTF-8
output remains in use. A non-UTF-8 locale retains the normal display fallback.

Leave the visual variable unset or set it to 0 on a terminal that already
handles Arabic. Applying visual reordering twice can make the result unreadable.

WHAT IS COVERED

- Minimalist interfaces: onekeyirc and vipirc -i.
- Help, command-response and context-help readers, setup labels, message review,
  scrollback, catch-up panes, and the live tail above the input editor.
- The append-only live WATCH transcript and operational notices, added in r9.
- Temporary marking of Latin tokens so commands such as /away, /help keys and
  --resume 7 retain their spelling and order within a physical row.

Only the final displayed row is converted. IRC packets, saved logs, retained
history, configuration, command syntax and the editor's input stay in logical
UTF-8. WATCH builds a whole temporary record before queueing it; a blocked
output queue cannot advance its history position or duplicate a partial row.
If a temporary conversion or frame exceeds its bound, logical output remains
available. Ordinary non-Arabic output keeps its existing path.

WHAT REMAINS UNFINISHED

- Full vipirc ncurses rendering has no visual-mode integration.
- The input editor still uses logical order. Visual RTL cursor movement,
  selection and editing are not implemented.
- Rows are wrapped by logical terminal-cell widths before shaping. They keep
  their top-to-bottom order, but this is not full paragraph-aware Arabic line
  breaking or joining across wraps. Extremely narrow rows can split a command
  token or an Arabic word; its stored bytes are unchanged.
- A terminal/font must provide the Arabic presentation glyphs. PTY byte tests
  cannot prove the appearance on a user's physical display.
- Selecting/copying visually transformed output may copy presentation forms
  and visual order. Use the logical saved log when original message bytes are
  required; persistent logging must already have been enabled.
- Native OpenBSD runtime, actual terminal fonts and fluent-speaker review are
  still required before claiming complete Arabic support.

CHECKS IN THIS PASS

The core regression covers an exact joined beh pair in visual reading order;
mixed Arabic and multi-token commands; malformed UTF-8 rejection; short output
buffers; a maximum-length marked row; missing-converter fallback; unchanged
retained text; and atomic queue retry without duplicated output.

Wrapped live records are checked at terminal widths 2, 12, 40, 100 and 400.
Offline pseudo-terminal checks exercise logical and visual /help output and a
live message sent only to the built-in in-process simulator at 40 and 100
columns. No public IRC server, account, credentials or screenshots are used.

Run after building:

    python3 tests/test_arabic_visual.py --binary ./onekeyirc
    python3 tests/test_arabic_visual.py --binary ./vipirc --full-client

The second command tests vipirc -i, not the ncurses interface. A binary compiled
with IRC_NO_ARABIC_VISUAL can be checked with --expect-fallback. The C regression
is tests/test_arabic_visual_core.c and builds like tests/test_idle_stream.c.

PRIMARY REFERENCES

FriBidi's public API documents logical-to-visual conversion and its single-line
paragraph scope; the bidi types header defines the signed FriBidiLevel type:
    https://github.com/fribidi/fribidi/blob/master/lib/fribidi.h
    https://github.com/fribidi/fribidi/blob/master/lib/fribidi-bidi-types.h

These implementation checks do not constitute native-speaker proofreading.
The English manuals remain the authoritative full reference.
