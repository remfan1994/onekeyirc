vipirc full-mode manual reader, optional language patch r26

English MANUAL.txt and its embedded source copy remain canonical. The optional
language pack supplies complete offline *drafts* under doc/FULL-MANUAL-XX.txt.
The full ncurses reader (/help or /manual) and the full-mode --manual command
use the selected file when it is available. Minimalist -i --manual uses its
existing translated topic/command system and is not changed by this feature.

Language selection uses VIPIRC_LANG, then ONEKEYIRC_LANG, then LC_ALL,
LC_MESSAGES and LANG (matching the existing catalog priorities). Supported
languages are id ms tr es pt fr de ru it ar. An unsupported/English language
selects the compiled English manual. The selected language is fixed when the
manual is first read in that process.

For a source-tree build, invoke the executable by path (e.g. ./vipirc):
    VIPIRC_LANG=ar ./vipirc --manual
    VIPIRC_LANG=es ./vipirc --test-mode
The full-mode reader then uses the adjacent doc/FULL-MANUAL-XX.txt file.
For an installed binary, ./configure --prefix=/absolute/path sets the installed
path: /absolute/path/share/doc/vipirc/doc/FULL-MANUAL-XX.txt.
Install the package's documentation with make install. Changing PREFIX only
at make install time does not change the executable's compiled document root:
rerun ./configure --prefix=... and rebuild instead.

An explicit VIPIRC_MANUAL_DIR=/absolute/path overrides both locations:
    VIPIRC_MANUAL_DIR=/path/to/your/doc VIPIRC_LANG=ru ./vipirc --manual
Only absolute directories are accepted for this override. If the requested
file cannot be opened or fails validation, the original embedded English
manual is used. Override failures do not fall back to an unrelated directory.
Normal runs do not search the current working directory. The development
fallback is anchored to the resolved executable path, not the working dir.

The loader accepts only one of ten fixed filenames; files must be regular,
nonempty and no larger than 512 KiB; at most 2048 lines and 8192 bytes per
line. It rejects malformed UTF-8, terminal escape/control bytes, and invisible
Unicode bidi override/annotation controls. It reads a complete document
before exposing it in the UI, never executes its contents, and does not create
or write any path. Symlinked final files are rejected where O_NOFOLLOW is
available; nonblocking open also rejects FIFOs without hanging. The operating system's file/directory ownership and permissions
still matter: do not give untrusted users write access to installed manuals.

Arabic text stays in logical UTF-8 in --manual output, so redirection and
copying preserve the source characters. Optional display shaping is handled
by the terminal/RTL renderer, not by rewriting the saved manual. Search in
the ncurses manual reader is literal UTF-8 with ASCII-only case folding;
search for the original English chapter headings, which remain visible in
translated draft manuals, to navigate reliably.

Security limits: loaded manuals are not authenticated against an external
publisher; replaceable local files are inside the user's filesystem trust
boundary. UTF-8 validation does not prevent visually confusable names and
Unicode lookalikes. This is not end-to-end IRC message encryption. The files
have not had native-speaker review; English SECURITY.md and MANUAL.txt remain
authoritative where a translated draft is unclear. Native OpenBSD and
Crostini tests still need to be performed.
