CURRENT SIGNAL POLICY (vipirc-1.0-a):
Use signals is off by default. Ctrl-C and Ctrl-Z cancel an unfinished compose or command; they do not end or suspend the application. Enable Use signals in panel 0 (or full vipirc Interface settings) to allow the terminal to generate its normal interrupt/suspend signals. Apply takes effect immediately; Save also persists [input] use_signals=true|false. The original terminal modes are restored on exit or suspension.

READING EXAMPLES

Examples starting vipirc belong in a shell; /commands belong in Command.
Enter one command at a time. In syntax summaries, UPPERCASE words are
placeholders, [items] are optional and | separates alternatives.
Opening Command supplies /. Before pasting a complete /command, remove that
prefilled slash; review the result, then press Enter. A pasted command block
is not a script: newlines become spaces. Paste on chat/watch stays chat text.

QUICK START

vipirc -h
    vipirc -v
    vipirc --test-mode
    vipirc --server irc.ircnow.org --channel '#ircnow' --nick tutankh-aten

The first three show help/version and open offline simulation. The last is a
real connection: quote #channel in a shell, and use a provider's actual TLS
endpoint. Verified TLS on port 6697 is the default; plaintext requires
--plain.

Interactive launches show the welcome, "Not vegetarian?
www.bloodguiltcurse.net will change your mind". A printable key, Enter, Tab
or a navigation key dismisses it. Configured terminal signals retain their
inherited roles; other controls do not dismiss it. Without a server the
client opens a disconnected workspace. Use Settings, /connect HOST or
--server to configure one.

An unconfigured primary nickname in full interactive mode is prompted with
your system login as the default. Enter accepts it; typing replaces it.
Unattended and saved secondary profiles use a valid login name or user
without a prompt. --nick overrides it; the server can reject it.

The initial server view shows registration and MOTD. Direct profiles join
configured channels after registration and required authentication; bouncers
restore their own memberships. Chat starts ready to type. Enter submits to
the selected channel/query; server and mentions views have no implicit
recipient. / at caret position zero opens Command. For a literal leading
slash, use //; bracketed pasted slashes remain literal.

Ordinary keys: F1 opens vipirc; F2 Servers; F3 Channels; F4 Queries; F5 Mentions/unread; F6
File transfers. Escape from a query opens Queries, from other chat opens
vipirc, from an ordinary panel returns to chat, and from Settings returns to
vipirc. The terminal's normal colors are preserved; bold brackets mark
focus. See GLOBAL HEADER AND CHAT CONTROLS for common list navigation.

LOCAL SESSION REMINDER

A running worker displays this local reminder once on its first attached
view:

    Cow killing is the bloodshed of the innocent. www.bloodguiltcurse.net - ban beef.

It is an ordinary local history entry, with no prompt, reserved input row or
IRC send. The once flag survives reconnects, server changes, reattachment
and frontend switches; retained history can still be revisited. It is
separate from the launch welcome.

GETTING HELP

vipirc -h              CLI summary; --help is equivalent.
    vipirc -v              Version; --version is equivalent.
    vipirc --manual        Full manual on standard output.
    vipirc -i --manual     Separate minimalist topic/command reference.
    man vipirc             Installed manual page.
    /help or /manual       Open this manual inside full vipirc.
    /help TEXT             Search this manual for TEXT in full vipirc.

In full mode, /help TEXT searches this manual; it does not open minimalist
topics. /help commands and /help ls locate COMMAND PROMPT; /help all opens
the whole manual. /view help also works. Search phrases need no quotes.
The reader works disconnected and preserves the underlying view/draft/caret.
Here / starts search. In a minimalist help/response reader, / opens Command.
For symptom-led steps, see doc/TROUBLESHOOTING.txt.

Press ? while navigating to explain the selected item and screen. Context
help includes an About screen link; Left/Right or Tab chooses an action, and
Enter follows it. Escape returns through item help to the exact origin and
selection. In an editable field, ? stays literal. Select a Command
suggestion before requesting its help.

Manual actions are Back, Search, Previous and Next. Left/Right or h/l chooses;
Enter runs. Up/Down or k/j scrolls a line, Page Up/Down a page, Home/End or
g/G reaches endpoints. Escape/q/Back returns to the opener (vipirc panel or
prior chat). F1..F6 opens available categories; view cycling skips the manual.
/ or Search edits a literal UTF-8 query (256 bytes maximum). Enter searches;
Escape cancels query editing. n/Next and N/Previous wrap through matches.
ASCII case is ignored; other characters are literal. Search has no regex/
shell syntax or recall history. Paste is ignored here and in search.

F1 contains Server, Nick, Settings, Manual, Command, Background, About and the
Insha-Allah license agreement. Server/Nick opens current-profile settings;
Nick focuses that field. About shows version/credits and an on-demand local
snapshot of PID, uptime, CPU totals, supported peak memory and server/view
counts. Peak memory is not current use; CPU totals are not a live percentage.
The license reader includes LICENSE.md in full. Escape/Enter/q/Back returns
from About/license to vipirc.

MINIMALIST INTERFACE

vipirc -i
    vipirc --idle --test-mode
    /connect irc.ircnow.org
    /join #ircnow
    /saveconf

-i uses the same vipirc config and server catalog. The nickname defaults to
a valid login or user. /saveconf saves preferences and healthy profiles and
remembers the selected connection, including a secondary, for the next bare
/connect. Saving does not enable autoconnect. /quickstart and /panel are
optional guides.

The log is the normal screen. / opens Command, ? opens context help, other
printable characters start Compose and are retained. Enter or Insert opens
empty Compose. In the live log, Up scrolls one retained row older, Page Up a
page, Home the oldest retained page; Down/Page Down/End stay at the live
tail. Left/Right/Delete/Backspace are inert there. In a history reader, End
or Escape returns live.

Compose arrows edit; they do not recall sent chat. Tab/Shift-Tab completes
nicknames in Compose and command names in Command. Command Down selects
suggestions; Up/Down browses them and Up from the first returns to input.
Enter inserts a selection; a separate Enter after display runs it. Up from
command input recalls accepted matching commands; Down returns toward the
original draft. See /help keys and /help commands for all controls.

Line composer mode keeps one input row below a live tail; fullscreen keeps a
multiline editor with a smaller live-tail pane. Traffic repaint preserves
draft/caret. Escape leaves an editor for the log; Escape on the log
backgrounds. In Review, Escape or typing restores the same
editor/draft/caret, while a fresh Enter confirms. Ctrl-D is inert unless explicitly bound; terminal
signals are inherited. A recognized paste remains literal and cannot submit.

    /set send_mode direct|review
    /set composer_mode line|fullscreen
    /set output_format compact|full
    /save input
    /save output

Direct sending, line composition and compact [HH:MM:SS] <nick> text are
defaults. Full output includes date/server/target; mentions and cross-server
diagnostics keep required context in either format. These primary-owned
preferences apply across servers. Independent byte-budget acknowledgement
and multi-message consent still apply.

/help ls lists topics; /help /ls explains the local list command. Use
/help COMMAND for syntax/examples, with one topic or command name at a time.
/manual and vipirc -i --manual give the complete minimalist reference, also
in doc/vipirc-idle-manual.txt. Commands/controls differ from full ncurses.
Help and long command results use a separate bounded reader.
Arrows/pages/Home/End scroll; Escape returns. Enter scrolls help but closes
a successful /users roster. / opens Command from a reader; cancelling
returns there. New command output replaces the old response. Summary r
refreshes its snapshot. Networking continues while reading.

/panel starts at 0 Application preferences, covering history, send/composer
modes, output, notices, logging, single-session mode, command suggestions
and default interface. Finish offers Save or Apply without saving; it never
connects or switches chat. Both frontends number profile panels 1..8: panel
1 edits the primary, labelled server 0 in full mode and 1 in minimalist mode.
These panels edit per-server settings, including bouncer identity. Finish
offers Save and connect, Save only (default), Connect once, or Apply only.
/quickstart asks server/TLS/port/nickname and defaults to Connect once;
it does not edit an existing bouncer login.

Enter keeps a shown answer; '-' clears optional fields. Escape steps back or
exits from the first question. Tab selects a heading for ? help, then
Tab/Enter resumes editing. Hidden passwords and answers never enter command
history. Only the final choice applies/saves/connects; an active connection
is not retargeted, and a later connection failure does not undo explicit
changes. Full vipirc also supports these guided flows; its /settings opens
the graphical form.

Minimalist /servers uses 1..8; full /servers uses 0..7. Channel 0 is the
server/MOTD in either interface. The primary history setting limits native
retention across all conversations, with the hard bounds described in /help
history. Optional plaintext logging is off by default. DCC uses the shared
explicit /dcc commands without graphical forms.

DEFAULT INTERFACE

To remember minimalist mode, run in either interface:

    /set default_interface idle
    /save input

Settings > Interface > Default interface or /panel > 0 also sets it.
Alternatively put default_interface=idle in the primary config's existing
[session] section, keeping other keys there. The unset default is ncurses.
This preference chooses fresh launches, including --background; it neither
switches the current frontend nor reconnects IRC.

Explicit -i/--idle or -N/--ncurses selects this invocation; the last flag
wins and an unrelated Save does not persist it. Lowercase -n/--nick remains
nickname. Restore the saved full default with /set default_interface ncurses
and /save input. Secondary profiles do not own this preference.

Bare --resume retains that existing worker's frontend. -i --resume NUMBER
requests minimalist; -N --resume NUMBER requests ncurses, without
reconnecting or replacing the worker. Legacy workers lacking switching
retain their frontend. onekeyirc always uses its minimalist frontend and
rejects -N/--ncurses. Switching discards frontend-local drafts and recall;
see RUNNING IN THE BACKGROUND before changing interfaces.

MINIMALIST WRAPPING AND INPUT HISTORY

Compose reserves input rows and leaves the newest wrapped visual rows above
it; older rows can leave that smaller viewport. Stored text and send plans
are not shortened. Leave input or reselect the conversation to inspect
retained lines; a local echo is not a delivery receipt. Resize recalculates
geometry while preserving draft/caret.

Compose Up/Down edits the caret, even when held. Only Command Up recalls
accepted commands; sent chat, sensitive service lines and keyed joins are
not recalled. The .commands file contains names/counts only. See COMMAND
PROMPT, INPUT EDITING and TROUBLESHOOTING.

MINIMALIST CATCH-UP AFTER RESUME

In vipirc -i, /catchup opens the selected channel or query at the first IRC
line of your most recent locally sent composition. Anchors are separate for
each server and channel/query; server/status and mentions views have none.
Select each conversation and run the command separately after resuming.

The reader first tries an eligible private log. Logging must already have
been enabled when the anchor was sent, remain healthy, and still contain
that exact anchor record in the same file. Enable it deliberately before the
absence:

    /set persistent_logging on
    /save output

The disk reader snapshots the current end instead of importing the whole
absence into permanent chat memory. Up/Down moves by visual row, Page
Up/Page Down by page, Home returns to the sent-message anchor, End reaches
the newest snapshot page, and Escape returns live. New network traffic
continues without moving the snapshot.

If that disk anchor is unavailable and the sent message is still retained in
memory, the command opens ordinary retained scrollback at it. In this
fallback Home reaches the oldest retained page, End or Escape returns live,
and earlier retained messages can also be browsed. This is the normal memory
reader, with the normal eviction limits, not a recovered disk archive.

A rotated/replaced log or changed anchor record cannot serve as the original
disk anchor. The record check detects accidental changes; it does not
authenticate data against another process under the same account. Sensitive
authentication traffic is not used as a durable anchor. If neither disk nor
memory retains an eligible anchor, the command explains the missing history
instead of claiming a complete catch-up.

The anchor belongs to the running worker. Detach/resume preserves it; a
fresh process does not reconstruct anchors or automatically reload old
transcript files. Disk-backed /catchup belongs to the minimalist frontend.
Full ncurses keeps its bounded in-memory Page Up/Page Down history.

COMMAND-LINE OPTIONS

-i, --idle
        Select minimalist mode for this launch; --help/--manual describe it.
    -N, --ncurses
        Select full mode for this launch. Last explicit interface flag wins.
        Neither override changes the saved default; -n still means nickname.
    -s, --server HOST
        Select the primary server: hostname or numeric IPv4/IPv6, not a URL.
    -p, --port PORT
        Port 1..65535. Defaults are TLS 6697 or explicitly plain IRC 6667.
    -c, --channel LIST
        Direct-profile autojoin after registration; comma lists/repeats work.
        Quote #channel for the shell. Bouncers restore memberships instead.
    -n, --nick NICK
        Override the effective startup profile's nickname.
    -C, --config FILE
        Select primary config and its .servers catalog/.d profile directory.
        File must exist unless --init-config creates it. See FILES AND
        ENVIRONMENT for defaults and literal configuration-path syntax.
    --tls
        Require verified TLS, the default. A bare port does not disable it.
    --plain
        Explicit plaintext; saved credential authentication is refused.
    --ca-file FILE
        Custom PEM authorities instead of system trust. Nonempty regular file,
        at most 16 MiB; an ordinary symlink is allowed. No password prompts.
        See TLS AND CUSTOM TRUST for checks and limits.
    --no-connect
        Suppress all startup connections or simulators. Connect explicitly later.
    --background
        Start a detached worker without a tty, TERM or welcome keypress.
        Saved default chooses its frontend unless -i/-N overrides it. Save
        autoconnect profiles or provide --server; --no-connect wins.
        Success confirms local setup, not a successful IRC login.
    --reconnect
        Retry transient network failures for this process, without initiating
        connection or saving a preference. Backoff: 5,10,20,40,80,160,300 seconds;
        60 registered seconds resets it. /disconnect cancels, /connect restarts.
        Certificate/auth/config/protocol failures remain disconnected.
        Pending chat is discarded. Auth/startup commands run on new connections;
        direct profiles replay autojoin, bouncers restore membership.
        Staged settings still need an explicit disconnected /connect.
    --test-mode
        Interactive offline simulation; no network/DNS/credential reads/saves.
    --resume [JOB]
        Attach the sole verified detached job or choose its number; --resume=JOB
        also works. Explicit absolute socket paths support compatible older
        workers. Bare resume retains its frontend; -i/-N requests one.
        Requires stdin/stdout/stderr on the same interactive tty. Multiple or
        unverified jobs prevent automatic selection; attached jobs are busy.
    --sessions
        List this account's attached/detached jobs without tty or config load.
    --detach-session NUMBER
        Release the verified controller while preserving the worker and state;
        then --resume NUMBER. Also accepts --detach-session=NUMBER.
    --close-session NUMBER
        End that whole worker, all IRC/transfers, drafts and memory history.
        Config/log files remain. Verified cleanup is required for success;
        a timeout can precede later completion, so recheck --sessions.
        Also accepts --close-session=NUMBER. See SESSION RECOVERY AND UPGRADES.
    --init-config
        Create a private config without replacing existing/concurrent files.
        A reported cleanup/sync error may leave the completed file in place.
    --check-config
        Validate config, overrides, catalog and saved profiles, then exit.
        Does not open secrets, run GPG, test CA/TLS, or prove reachability/login.
    --manual
        Print the complete selected interface's manual without a terminal.
    -h, --help
        Print CLI help without a terminal.
    -v, -V, --version
        Print version/attribution/license without a terminal.

Long options accept --name=value; ordinary short-option grouping works. --
ends options; positional operands are not used. CLI values override config,
then defaults. At normal startup non-host overrides affect the remembered
default; explicit --server selects the primary. --init-config/--check-config
apply to the primary. An unavailable remembered default requires --server or
repair before non-host overrides.

A case-insensitively different --server clears inherited credential sources,
auth, custom CA, bouncer identity/automatic-away choice, channels and
startup commands. Configure the new host explicitly. Same-host overrides and
--nick alone retain profile settings. A different --config selects a
separate workspace.

Resume/list/detach/close are separate management operations: do not combine
them, or mix them with --config/connection/startup options. Supported
interface flags may remain in an alias. --background cannot combine with
those operations, --init-config or --check-config. --test-mode cannot
combine with --init-config/--check-config (usage status 2).

OFFLINE TEST MODE

vipirc --test-mode
    vipirc --test-mode --config /absolute/config.ini --no-connect

Simulation exercises the real interface/editor/filters and applicable
protocol/queue handling without network sockets, DNS, password/CA reads, GPG
or saves. Configured hostnames are labels. Each profile has an independent
simulator; New server adds another. Missing server/nickname values do not
prompt; default demo channels are #test-one and #test-two when none are
configured.

Simulation starts after welcome regardless of saved autoconnect;
--no-connect leaves it stopped. /disconnect and /connect stop/start the
selected simulator. Exit and restart without --test-mode for real
networking. The local C simulator needs no external daemon or Python.

Events occur every two seconds: chat, mentions, watch strings, a query and
roster changes. Custom watch strings rotate one per 16-second cycle. /msg
gets a labelled simulated reply; JOIN/PART/NICK/WHOIS/TOPIC/AWAY have
simulated responses. This does not reproduce every server rule,
keyed-channel admission, SASL or actual delivery.

Try wrapping, editing across rows, resize, paste, warning/confirmation,
mentions and lists. The sample DCC offer is memory-only:
review/reject/cancel works, Send/Accept is refused before file/socket
access. Closing a secondary changes runtime only. Configuration and
count-file writes are disabled; edit configuration externally and restart
for permanent changes.

--check-config is a separate syntax/value check of saved files. Neither mode
proves real DNS, TLS, credentials or bouncer interoperability.

GLOBAL HEADER AND CHAT CONTROLS

F1 vipirc                Application, settings, help, About and license.
    F2 Servers (N)           Configured/retained server sessions.
    F3 Channels (N)          Selected server's retained channels.
    F4 Queries (N)           Selected server's private conversations.
    F5 Mentions/unread (M/U) Retained mentions / unread source conversations.
    F6 File transfers (N)    Retained transfers across all servers.

Only categories with content appear; vipirc is always present. Parted
channels with history and completed transfer records still count. Fixed
function-key numbers do not shift when categories hide. A hidden category is
not created by its shortcut; explicit list commands can still open empty
lists. TERM supplies key decoding; terminal-reserved keys must be forwarded
to the client. Pasted sequences never activate shortcuts.

The conversation has its own row below the header; a query nickname does not
replace Queries. Narrow headers keep the selected category visible. Settings
> Interface > Shortcut labels hides ordinary F1..F6 labels; unbound keys still
work. Hints separately controls optional guidance. Both preferences are
primary-owned and require Save for persistence.

Arrow keys operate the body/editor, never the top bar. Escape from a query
opens Queries with that query selected; from other chat it opens vipirc;
from ordinary panels it restores chat/draft/caret; Settings and license
return to vipirc. F1 opens vipirc directly. Safety dialogs and paste capture
handle input first.

On vipirc, b/Back returns to chat; Escape asks Really quit? [Y/N]. Only a
fresh y/Y confirms. Other ordinary keys cancel; paste, clicks and resize
cannot confirm. Terminal interrupt/suspend behavior follows TERMINAL
SIGNALS.

Lists share controls: Up/Down or k/j selects a row, Left/Right or h/l an
action, Enter executes. Home/End or g/G selects endpoints. Open is initially
selected; changing the row preserves the chosen action. Rows stop at
endpoints. Both row/action stay highlighted. Click an item to open it or its
action row to act on the selection. Delete invokes Close for
server/channel/query rows with the usual protection/confirmation; in editors
it deletes text.

Chat arrows edit, hjkl is literal, Tab/Shift-Tab completes nicknames, Page
Up/Page Down browses history, / at caret zero opens Command. Enter submits;
/clearinput clears the whole draft. Mouse mode additionally shows Clear/Send
beneath the fixed field. Both paths use the same message checks. Bracketed
chat paste is literal; tabs become spaces and paste never sends.
After paste ends, keys/clicks wait for a complete visible screen, a
later input batch and a quiet interval. Holding keys extends the wait.
Tiny/failed frames do not count; resize, release keys, then act.
Lists/readers/safety dialogs ignore paste. Active Command/Settings/transfer
editors accept data under their own rules.

NICKNAME COMPLETION

Tab completes the nickname token at the chat caret. Further Tab presses
cycle matching names in case-aware alphabetical order, wrapping; Shift-Tab
cycles backwards. Matching follows this server's advertised ASCII, strict
RFC1459, or RFC1459 nickname case rules. No lookup or outgoing message is
needed. Ordinary editing ends the current completion cycle.

At the beginning of a draft, completion adds ': '. At the end of a later
word it adds a space. Existing punctuation and following words remain intact
when completing inside a draft. Channels and URLs are not interpreted as
nickname prefixes. A candidate that would exceed the draft's byte or
character bound leaves the entire draft intact. Crossing the smaller IRC
message budget opens the normal early warning; completion never sends.

A channel uses its current roster. A query uses its peer and your nickname.
Server and mention views use peers known from this server's joined channels
and query list. Another server's users are never candidates. Current roster
changes apply to the next completion, without storing an extra user list.

COMMAND PROMPT

Open Command through F1's Command item or /, or type / at chat caret
position zero. The independent chat draft/caret is preserved. A slash
elsewhere or in bracketed chat paste is literal. Enter/Run submits;
Escape/Cancel returns to the opener, including Summary. Empty input does
nothing. Accepted commands return to chat unless they open another screen;
invalid/refused commands remain editable.

Settings > Interface > Command suggestions chooses:

    Commonly used: default curated order, adapted to connection/view state.
    Recent history: accepted complete command lines, newest first.
    Most used: personal canonical-command counts for the saved profile.
    Alphabetical: implemented command names.
    Contextual: rank for the screen that opened Command, retaining other matches.

Type a case-insensitive command-name prefix to filter; arguments are not
predicted. Down selects suggestions, Up/Down browses, Up from the first
returns to input. Enter on a selection inserts it without execution: a
catalog row preserves existing arguments, a history row inserts its full
line. Review/edit and press Enter separately after display. Extra Enter
bytes in that input batch cannot run it. ? on a selected row opens
item/screen help and restores the selection afterward; ? in input is
literal.

Delete removes a selected Recent history entry or resets a Most-used count,
never the supported command. Page Up/Page Down or wheel browses suggestions.
Invisible rows cannot be selected in tiny terminals. Right at the end of a
command-name prefix completes/cycles it; clicking a suggestion inserts it.
Tab does not navigate the header or execute. Nickname completion stays in
chat.

Up from input recalls accepted commands matching the original prefix; Down
returns toward newer entries and the original draft. Arguments match
byte-for-byte. Failed commands are not recorded. History holds at most 64
entries/64 KiB per server, deduplicates consecutive identical entries and
evicts oldest entries. Recall lasts while this frontend and server stay
open; changing frontend or ending the worker discards it.

Persistent usage counts are separate: CONFIG_PATH.commands holds at most 96
canonical names and bounded counts, never arguments/targets/chat. A saved
profile enables automatic private atomic updates on accepted
commands/resets; unsaved counts stay in memory until Save. Bad/missing count
files do not block startup. Test mode neither reads nor writes counts; the
main config does not store them.

Keyed joins and recognized service/authentication messages are omitted
entirely from recall. Harmless messages to known sensitive services are
omitted too. This filtering cannot recognize every arbitrary secret; do not
put secrets in ordinary chat. Bouncer controls follow BOUNCER CONNECTIONS.

Command paste is data: CR/LF/Tab become spaces, unsupported controls/size
violations are reported, and a fresh Enter/Run is still required. No shell
quoting, substitutions, command chaining or shell execution exists.
TEXT/PATH arguments consume their documented literal remainder; quote
#channel only in an actual shell, not inside these commands. /msg, /me and
// retain message budgets, pacing and mandatory default-No split consent; //
is literal chat and does not enter command recall. Join/New list actions
prefill /join or /pm.

CONNECTION AND STARTUP COMMANDS

/connect [-tls|-plain] [-nick NICK] HOST [PORT]
    /connect                       Reuse selected saved/applied profile.
    /server HOST [PORT]             Same direct connection route.
    /server NUMBER                 Select a profile without connecting.
    /server                        Open selected server/MOTD view.
    /server add HOST [PORT] [NICK]  Add a disconnected unsaved profile.
    /server connect NUMBER
    /server disconnect NUMBER
    /disconnect [NUMBER]
    /server close NUMBER           Close secondary; keep profile file.

New destinations use verified TLS6697 and a valid login nickname or user; no
credentials/channels are inherited. Matches preserve configured
transport/port/nick/auth and select an already active connection instead of
duplicating it. For bouncer profiles sharing a host, select the intended
number then bare /connect. No connection command saves implicitly. Full-mode
server slots are 0..7 (primary 0); minimalist slots are 1..8 (primary 1).
Server connect/disconnect does not change selection. Use each frontend's
/servers output, not the separate /panel chooser numbers.

Options precede HOST. -ssl aliases -tls; +PORT requests TLS; an ordinary
number never disables TLS. --tls/--plain/--nick forms also work. New
plaintext defaults to 6667. Passwords are not positional arguments. A
secondary Close removes its catalog reference, drafts/history and transfers
but keeps the physical profile.

    /autoconnect [on|off]
    /autojoin [list|add #CHANNEL|remove #CHANNEL|clear]
    /autoauth [status|off|sasl USER file PATH|sasl USER gpg PATH]
    /save [input|output|all]
    /saveconf

Autoconnect changes next startup, not the current connection. Autojoin
stages direct-profile joins for the next explicit /connect, without
joining/parting now. Its inquiry shows registration and running/pending
membership. Automatic retries retain running settings; disconnected /connect
adopts applied changes. /join acts immediately after registration. Bouncers
restore memberships and refuse autojoin edits; /autoauth changes are
likewise refused there in favor of Settings or /panel.

Autoauth stages verified-TLS SASL. Status shows complete current/pending
credential paths locally without reading them; ordinary settings output
redacts them. Full-mode inquiries have Refresh/Back and preserve drafts.
PATH is the literal remainder, including spaces. Inline secrets belong in
private config/Settings, not commands.

Bare /save writes the selected effective profile, including staged choices.
/save input and /save output both write the primary profile containing the
application preferences; they are aliases, not input-only/output-only saves.
Pending primary connection changes are included. /save all writes healthy
profiles; /saveconf also remembers the selected default for later /connect.
Saving does not enable autoconnect. Each file is private and atomic, but the
workspace is not one transaction: earlier successes survive later failures.
Unreadable profiles are not overwritten. Test mode never saves.

/set autoconnect on|off is a full-interface compatibility alias. /set
application preferences works in both interfaces; send/composer/output
presentation choices affect minimalist mode. /panel opens guided settings in
both; /quickstart asks four connection essentials. Full /settings opens
forms, minimalist /settings a report.

/list [MASK] [OPTIONS] requests the network channel directory after
registration. Only MASK reaches the server; --min-users/--max-users, --name
and --topic filter locally. --sort channel|users|topic, --asc/--desc and
--limit N control display; default users descending, limit 0 means no
display restriction within the 8192-entry cache. /list show can change
sort/order/limit without another request; /list clear clears the cache. /ls
and /cl instead list local views.
Disconnect or an explicit server LIST rejection leaves partial cached results
available but releases the request. Retry /list after registration, or clear
with /list clear; incomplete results are not a full network directory.

The full browser uses Up/Down or j/k for rows, Left/Right or h/l for sort
column, s to reverse, Page Up/Page Down and g/G for navigation, Enter to
join, r to repeat the current request, / for Command, Escape to return. A
column click sorts. In minimalist mode /list show prints its cached
directory. /summary gives a separate local workspace snapshot.

SESSION SUMMARY

/summary opens a local snapshot of the whole running client in a separate
scrollable reader. It works while disconnected and groups entries by server.
It includes connection state and nickname, channel 0, joined and left
channel views, queries, unread and mention counts, outgoing queues, pending
startup commands, and file transfers with their current status. Totals omit
the copied mentions feed to avoid counting its source messages twice.
Mentions may also be unread messages; those two totals are not added
together.

Opening or refreshing the summary does not switch conversations, mark them
read, send a network request, or replace a chat draft. It reports queue
counts without exposing queued message text, automatic-command text, or
credentials. It shows current state rather than interpreting chat content.

In the full interface, use Up/Down or k/j, Page Up/Page Down, and Home/End
or g/G to read. Press r or R, activate Refresh with the keyboard, or click
Refresh to take another snapshot. Escape or Back returns to the origin. In
vipirc -i, r refreshes the response reader. A failed refresh retains the
previous snapshot. Networking continues while the reader is open. Slash
opens Command from Summary; cancelling it returns to that snapshot. Press ?
to read help for the summary and its reader.

SETTINGS

F1 > Settings or /settings opens Interface, all server profiles and New
server, without switching chat. Rows show autoconnect and saved status.
Server fields include transport/identity/autojoin/autoconnect, account and
server-PASS sources, custom CA, bouncer
type/username/network/client/automatic away, history, mentions and ignores.
Interface contains global User list, Mouse, Hints, Shortcut labels, notices,
logging, single-session mode, command suggestions and default interface.

    Edit    Apply    Save    Back    Cancel

Up/Down or k/j selects fields; Left/Right or h/l selects an action; Enter
acts. Home/End or g/G reaches endpoints. Edit toggles a boolean, opens a
choice, or edits text/number. Editor Enter stages only that value;
Tab/Shift-Tab validates and stages it before moving. Invalid input remains
editable. Letters in editors are text. Empty existing watch/ignore fields
remove them; Add creates another within limits.

Apply validates and updates live preferences, watch/ignore/autoconnect, then
stays in Settings with Edit selected. Connection fields (including bouncer
identity) become pending for the next explicit disconnected Connect. Apply
never saves, reconnects or retargets a live session. /nick, /join and /part
affect the running connection. Save privately/atomically writes the
effective profile, then applies; /save also preserves pending choices. A
first secondary Save creates its isolated profile and catalog entry.

Interface Apply updates all current/future server slots; Interface Save
writes the primary config before applying. A failed/blocked Interface Save
leaves all sessions unchanged. Secondary interface keys cannot override the
primary at startup. History remains per-server in full mode. Default
interface chooses a fresh launch only.

Hints hides optional guidance, preserving titles, controls, errors and
safety confirmations. Shortcut labels hides ordinary F1..F6 prefixes. Both
default on and save under [interface]. These preferences are independent of
the terminal's normal colors and bold focus.

Changing Server to a case-insensitively different value clears inherited
authentication, auth user, all account/PASS sources and autojoin in the
staged form. Changing bouncer type clears inherited credentials/commands;
enter intended values afterward. The active session is untouched. File
fields are not read/decrypted while editing; inline plaintext fields are
masked and preserve password spaces. Transport selects verified TLS versus
explicit plaintext, independently of encrypted password storage.

Back returns to Settings home. Cancel/Escape closes the entire form, even
from a field/popup, discards unapplied changes and returns to vipirc.
Already applied preferences/pending choices and chat drafts remain. Test
mode permits in-memory Apply but refuses Save. Creating/connecting through
Settings preserves the active chat selection.

Bracketed paste works only in an active field, inserts without committing
and converts tabs to spaces; CR/LF/Escape/unsupported controls are rejected.
Paste on lists/choice popups is ignored. Review then press Enter to stage.
Guided /panel is a separate question-by-question flow described under
MINIMALIST INTERFACE.

CUSTOM KEY BINDINGS

No custom keys are assigned by default. App -> Key bindings or /bindings
opens a table in full vipirc. Add/Edit chooses a key name and local action;
Remove deletes a row. Apply changes memory; Save also writes the primary
config; Escape/Cancel discards unapplied edits. Chat drafts are preserved.
The table has its own controls, unaffected by custom bindings.

In either interface, use /bindings keys and /bindings actions to list names.
Examples to choose yourself: /bind F7 summary; /bind Alt-c command. Enter
these as separate commands. /unbind F7 removes one; /unbind all clears the
custom table. /save input saves changes for all server profiles. In -i mode,
/bindings lists the table and /bind and /unbind edit it through commands.

Keys: F1..F12, Ctrl-A..Z, Alt-a..z/0..9, Up, Down, Left, Right, Home, End,
PageUp, PageDown, Insert, Delete, Backspace, Tab, Shift-Tab, Enter, Escape.
Ctrl-H/Backspace, Ctrl-I/Tab, Ctrl-J/Ctrl-M/Enter and Ctrl-[/Escape are aliases.
Alt letters use lowercase terminal bytes. Terminal/multiplexer interception
and signal mappings take precedence; no signal key is reassigned.

Actions: compose, command, bindings, help, manual, summary, servers, channels,
queries, unread, mentions, transfers, settings, quickstart, next, prev,
clearinput, cancel, background, quit. No arbitrary command or send macros.
Restored full-mode commands require a fresh Enter to acknowledge, then a
separate Enter after a pause to run. A closed original target blocks Run.
Custom actions run only in main chat/command input, never in paste, password
fields, setup, readers or confirmations. Unframed paste is still typing.
Minimalist shortcut readers retain draft/caret; destination/editor changes
refuse a nonempty draft. clearinput deliberately removes the current draft.

The primary [hotkeys] section stores KEY=action rows, with no default rows.
Unknown/duplicate/overflow entries reject a load atomically. Up to 64 entries
are supported. See doc/HOTKEYS.txt for saving, terminal limits and examples.

TERMINAL SIGNALS

Literal Ctrl-D is ignored unless explicitly bound in main chat/command input;
it can also cancel the F1 quit question. Pasted Ctrl-D cannot answer that
question. To exit normally, run /quit in Command. Custom terminal signal
assignments still take precedence over ordinary key handling.

Terminal signal handling is inherited by default. The client does not assign
Ctrl-C or Ctrl-Z: those keys act only if the terminal maps them to signals
and has signal handling enabled. Custom interrupt, quit and suspend keys are
preserved. To explicitly enable terminal signal handling, set this primary
configuration preference and start a new client process:

    [input]
    use_signals=true

The default is false, which preserves the incoming enabled or disabled
state. This setting never changes the terminal's key assignments. The client
restores the original terminal settings on suspension and exit.

When enabled, terminal interrupt exits without saving drafts. Suspending an
ordinary foreground process pauses its networking and may cause a timeout;
fg resumes it. In an already managed/resumed job, suspension pauses its
foreground controller while the worker keeps networking; see RUNNING IN THE
BACKGROUND.

RUNNING IN THE BACKGROUND

/background or F1 > Background keeps IRC, accepted transfers, drafts and
memory history alive while restoring the terminal. It prints the numbered
resume command, for example vipirc --resume 1. First detach creates one
worker/private endpoint; subsequent detaches retain its number, state and
endpoint. Ordinary foreground use has neither endpoint nor extra helper.

Resume rereads terminal capabilities, size and locale on the same host/Unix
account. stdin/stdout/stderr must share one interactive tty. One foreground
controller handles signals/resize; only one terminal can attach at once.
SESSION RECOVERY AND UPGRADES explains job selection and busy attachments.

Start unattended with vipirc --background --reconnect --config
/absolute/config.ini after saving wanted autoconnect profiles. --background
does not enable autoconnect, and --no-connect suppresses it. Its success
confirms only local setup. No tty/TERM is needed until attachment. The
endpoint is prepared before resolver/credential helpers. Bare resume keeps
the worker's frontend; explicit -i/-N switches it without reconnecting or
replacing the worker. Changing interfaces retains conversation history and
accepted transfers but discards drafts, pending send reviews, command recall
and unapplied forms. Finish or copy wanted drafts before switching.
Same-interface detach/resume preserves this local state. Legacy workers may
retain only their existing frontend.

Configured terminal signals keep their roles. Suspend stops the resumed
controller while its worker keeps networking; fg restores interaction.
Suspending an unmanaged foreground process pauses networking. See TERMINAL
SIGNALS for inherited mappings and SESSION RECOVERY for terminal loss.

First detach may ask for a retry while resolver/credential helpers finish.
Ignored SIGCHLD/automatic child reaping prevents first background startup
and helper creation; the launcher must leave children waitable. Managed
re-detach starts no new worker.

Directory/socket are owner-private. Discovery probes at most 64 slots within
one 1500 ms deadline, removes only verified stale entries without a held
lifetime lease, and uses no guessed PID signals. Unresponsive jobs remain
unverified. Identity/incarnation checks prevent a reused number redirecting
attachment during handoff. Another process under the same account remains
trusted. single_session=true refuses a second worker in the vipirc namespace
without restricting servers inside it.

Worker state is not serialized: reboot, quit or termination ends
drafts/anchors/memory. Optional logs save transcript only. Test mode can
background using its local endpoint without enabling IRC/DCC networking. No
terminal multiplexer is required.

SESSION RECOVERY AND UPGRADES

A shell job is one client worker and all of its IRC connections, transfers,
drafts and retained history. Its job ID differs from both an
operating-system PID and a server number shown inside the client.

Recover a job whose old SSH terminal is still attached:

    vipirc --sessions
    vipirc --detach-session 1
    vipirc --resume 1

Choose NUMBER from the current list. --detach-session releases the verified
controller, waits for detached state, and keeps the worker/IRC state alive.
Bare --resume selects only a sole verified detached job; multiple or
unverified candidates need explicit selection. It never takes over an
attached terminal. Job numbers remain stable until exit, then may be reused.

CLOSE A SESSION FROM THE SHELL

Use this only when the entire job should end:

    vipirc --sessions
    vipirc --close-session 1

Close ends all of that worker's IRC connections and transfers and discards
its unsaved drafts and in-memory history. Saved configuration and existing
plaintext log files remain. --close-session=1 and --detach-session=1 are
also accepted. These management commands do not require an interactive
terminal or load configuration. Do not combine them with --resume,
--sessions, each other, --config or connection options. Supported interface
flags can remain in an alias without changing the selected job.

The client uses the owned private endpoint, peer-ownership checks and the
chosen worker's identity token. Success means application cleanup and
release of the original job lease were confirmed, not merely that a request
was accepted or an independent observation of OS process exit. Requests have
a bounded deadline. A failed or timed-out operation does not unlink a live
endpoint or signal a guessed PID. If a request was accepted before timeout,
it may complete later; recheck --sessions.

A worker blocked on an open, permanently unread terminal may not reach its
control poll until output clears or the terminal closes. An entirely wedged
worker may require operating-system intervention after identifying the
actual process. A nonzero close status means completion was not confirmed.

SSH DISCONNECT RECOVERY

Loss of the terminal or controller in an already managed job detaches its
worker. Hangup/error readiness, stdin EOF/EIO, stdout failure, controller
EOF and SIGHUP preserve its connections and retained state. Full-mode
lost-terminal and externally requested close cleanup redirects obsolete
worker output before curses cleanup; the foreground controller restores its
own tty.

An ordinary foreground process that has never become managed retains normal
SIGHUP termination behavior. Start with --background or use /background
first when a resumable job is required. The client does not change SSH
client/server idle-timeout policy. Ordinary synchronous terminal drawing can
still block on a terminal that remains open but is no longer being read.

UPGRADING A RUNNING WORKER

Installing/rebuilding does not replace code in a running worker. Save wanted
configuration, deliberately quit/close it, check the installed --version,
then start a fresh job. Do this for security updates too. Logs survive;
drafts, recall and catch-up anchors do not.

A legacy worker can lack newer detach/close controls or frontend switching.
Keep its compatible executable until it is stopped if needed to attach and
quit through its existing controls. A failed legacy operation is never
reported as success merely because an endpoint disappeared. Existing config
files remain usable by the current release; an older executable may reject
keys explicitly saved by a newer one.

See doc/SESSION-CONTROLS.txt for the same workflow, and doc/OPENBSD-VPS.txt
for unattended host setup. Installing this source archive does not stop or
deploy anything on a remote host automatically.

SERVERS AND UNREAD ACTIVITY

Full ncurses lists server slots 0..7, with primary 0. They share one event
loop, each with independent credentials, identity, channels/queries,
mentions, rosters, history and drafts. F2 or /servers opens these actions:

    Open    New    Connect    Disconnect    Close    Away    Back

Common list navigation is under GLOBAL HEADER AND CHAT CONTROLS. Open shows
that server's MOTD (channel 0), preserving drafts/carets. Connect/Disconnect
acts on the selected row. Away toggles the registered server's acknowledged
away state using the default message Away. New (also n) opens a form;
Back/Escape returns to chat.

Primary server 0 cannot close. Disconnect retains views/drafts and accepted
DCC transfers. Secondary Close always confirms, default No; it discards that
server's memory, cancels its offers/transfers, removes its catalog reference
and keeps its profile file. Closing the selected secondary returns to
primary. Test-mode Close changes runtime only.

New has Server, Port, Transport, Nickname, Autojoin and Autoconnect; actions
are Edit, Add, Connect, Advanced, Cancel. Advanced exposes identity,
authentication sources and CA choices before first connection. Enter in a
field stages it; Escape cancels the form. Fresh profiles use TLS6697, login
identity/default and autoconnect off, with no inherited secrets, CA,
channels, watch/ignore lists. Only application preferences are shared. Add
creates disconnected state regardless of the autoconnect checkbox; Connect
creates/connects immediately. Both select the new server and require
explicit Save for persistence.

Rows show new N !M for unread activity/mentions; display caps at 999+
without changing internal counts. Showing a conversation clears only its
source counts; a covering list does not mark new text read. Totals omit
copied Mentions and Help. Outgoing echoes add no unread count. Reading
Mentions marks its feed independently, leaving source counts.

F5 or /unread groups retained mentions first, then unread conversations, by
server. Mentions show complete wrapped text/timestamps; source entries
identify Server/Channel/Query. Actions are Open, Clear mentions, Back. Open
selects the source; a closed query may reopen by recorded nickname without
sending or restoring discarded history. Closed channels are not joined;
unavailable servers are reported. Stable source identity, not row
position/text, determines navigation.

Clear mentions or /mentions clear removes copied mentions across servers
without changing conversation histories/unread counts/drafts/queues. New
mentions can arrive immediately. Page keys scroll a long selected mention
before moving entries. Bare /mentions selects only the current server's
feed.

VIEWS AND USERS

Each server has its server/MOTD view 0, channels, separately numbered
queries, mentions and rosters. Headers identify the server; the server view
contains registration/MOTD/errors. Mentions retain source, sender and
complete message text within protocol bounds. Long display lines wrap
without shortening stored text.

/sl or /servers opens servers; /cl or /channels opens channels; /ql or
/queries opens queries. /server selects MOTD, /channel NUMBER or #NAME a
channel, /pm NICK|NUMBER a query. /next and /prev cycle views. /summary
snapshots workspace state; /unread combines sources/mentions; /list requests
the network directory. Canonical syntax is in COMMAND REFERENCE INDEX.

/users toggles the channel roster; on/off/up/down controls
visibility/scroll. Settings > Interface uses the same primary preference.
Small terminals may hide the sidebar until space returns. Membership and
privilege prefixes follow server JOIN/PART/QUIT/NICK/KICK/NAMES, not local
guesses. Query/server views have no channel roster.

Unsolicited private messages create query views only while fewer than eight
exist; later messages remain visible with context in server/mentions.
Explicit /pm or /msg can create more within the 32-view bound. /clear clears
retained view memory without deleting disk transcripts; /clearinput clears
its independent draft.

CHANNEL CHOOSER AND CLOSING CONVERSATIONS

F3 or /channels (/cl, /views) shows server/MOTD entry 0 and retained channel
views, including parted ones. Common list navigation applies; actions are:

    Open    Join    Part    Close    Back

Join opens Command with /join prepared, preserving drafts. Part leaves the
channel and keeps history; Close removes the view. p parts, c closes, o
opens Join. /channel NUMBER or #NAME selects a retained view; /view NUMBER
uses channel numbering and /view NAME selects a named view. Numbers can
change after closure; use the current list.

Close first parts a joined channel, discards its history/draft and cancels
queued target chat; an in-flight message may finish. A nonempty draft
requires confirmation, default No. Server and mentions views cannot close;
/disconnect stops server networking. /close [NAME|NUMBER] closes the
specified channel/query or current conversation. Channel 0 cannot part.
Back/Escape restores chat.

QUERY LIST

F4 or /ql (/queries) lists only this server's private conversations,
numbered from 1 independently of channels. Actions use the common list
controls:

    Open    New    Close    Back

New opens Command with /pm prepared; in an empty list, Open on New query...
does the same. c closes, o/n opens New. Close confirms a nonempty draft,
default No. /pm NICK|NUMBER or /query NICK|NUMBER opens/selects without
sending, even disconnected. /msg NICK TEXT sends explicitly; /close NICK
closes by name.

Escape from a query opens Queries with that query selected, however it was
opened; Escape/Back from the list restores it and its draft. The query name
stays in the conversation row rather than replacing a header category.

MENTIONS AND WATCH STRINGS

Your current nickname is watched automatically. Nickname matching follows
the IRC server's advertised case mapping and nickname boundaries. A nickname
change updates this automatic match.

    /watch add project name
    /watch remove project name
    /watch list

Custom watch values are literal substrings, not regular expressions or shell
patterns. IRC/ASCII letter and symbol case rules are used; non-ASCII
characters match exactly. Up to 32 custom values of 127 UTF-8 bytes each are
accepted. Use /save during normal operation to preserve changes in the
selected configuration. In test mode, changes remain in memory. Mentions are
retained in memory, subject to the history limits. They are not a permanent
notification archive or an on-disk log. Timestamps are local receipt dates
and times, in YYYY-MM-DD HH:MM:SS form.

CONVERSATION COMMANDS

/join CHANNEL [KEY]     request to join one channel, optionally with a key
    /part [CHANNEL] [MESSAGE] leave a channel with an optional PART reason
    /close [NAME|NUMBER]   close a channel/query; number is a channel number
    /pm NICK|NUMBER               open/switch a private view without sending
    text
    /msg TARGET TEXT       send text to one nickname or channel
    /me TEXT               send an IRC action to the current conversation
    /nick NICK             request a different nickname
    /away [MESSAGE]        set away with text; without text, clear away
    /back                  clear away status; takes no argument
    /whois NICK            request information about a nickname
    /topic                 request the current channel topic
    /topic TEXT            request a new current-channel topic
    /connect [HOST [PORT]] connect directly, or reuse the selected server
    /disconnect [NUMBER] disconnect this or a numbered server; retain
    views/drafts
    /dcc or /transfers     open the shared File transfers screen
    /cancel               stop unsent chat messages on this server
    /background           keep running and return to the shell
    /quit [MESSAGE]       exit all server sessions with an optional QUIT reason
    /settings             edit app-wide preferences and any server profile
    /save [input|output|all] save selected, primary, or all profiles
    /saveconf             save profiles and remember the selected connection
    /set autoconnect on    enable connection at future startup after saving
    /set autoconnect off   disable it

/away MESSAGE sends one standard AWAY message. Text is limited to the
current wire limit minus 8 bytes (504 bytes at the usual 512-byte limit);
oversized text or controls are rejected, never split. /away with no text and
/back clear away. These require registration. The indicator changes only on
server acknowledgments and resets on disconnect/reconnect. The server list's
Away action sends Away as the message or clears an acknowledged away state,
preserving the view and draft. A disconnected server must connect first.
Edit ignored senders in the Settings Ignore fields, or use the local /ignore
and /unignore commands.

/join accepts one channel and at most one key token. Keys must be printable
ASCII without spaces, colon, or comma, and the complete JOIN must fit the
wire limit. The key is not logged or saved; only the channel name enters
auto-join. Re-enter the key when needed after reconnecting or restarting.
The offline simulator acknowledges away changes and accepts transient join
keys, but does not test a real channel's key or admission policy.

The server decides permissions, nickname availability, channel admission,
and whether topic changes are allowed. Local command acceptance does not
guarantee server acceptance or delivery to another participant. Messages you
submit wait briefly while vipirc sends chat lines at least 1.2 seconds
apart. /cancel removes those still waiting on the selected server, across
its channels and queries. It does not erase your draft or recall text
already sent. A message already being transmitted may finish. For a direct
profile, /join and /part update the autojoin selection; /save preserves it
for future launches unless pending Settings startup choices override it.
Bouncer profiles leave membership restoration to the bouncer. /part also
discards queued text for that channel while retaining the view and its
history. A message already in flight may finish before PART. Text after the
channel is the PART reason; when the channel is omitted, text is the reason
for the selected channel. With no explicit reason, [presence] part_message
is used. Closing a joined channel uses the same default PART reason.

/quit MESSAGE uses that text as the best-effort IRC QUIT reason on live
server sessions. Without text, [presence] quit_message is used; an empty
default sends a bare QUIT. Shutdown remains bounded and never waits
indefinitely for a dead network.

Automatic away status is separate from manual /away. With background_away
on, a successful Background action or managed terminal loss queues the
configured AWAY only after the terminal has detached. Resuming clears only
that automatic status. autoaway_minutes applies the same rule after local
input inactivity; zero disables the idle timer. A bouncer profile suppresses
these automatic changes unless [bouncer] automatic_away=true is enabled. Any
manual /away remains set until /back or an explicit /away with no message.
Incoming IRC traffic never counts as local user activity.

LOCAL IGNORE FILTERS

/ignore or /ignore list       list masks in the server view
    /ignore MASK                 add a mask; /ignore add MASK also works
    /unignore MASK               remove it; /ignore remove MASK also works
    /ignore clear                remove all masks

These local commands work disconnected. Use /ignore add NICK for nicknames
literally named list, add, remove, or clear. Up to 32 masks of 127 ASCII
bytes each are accepted. A plain mask must be an exact valid nickname.
Wildcards require full nick!user@host form with three nonempty components;
for example, *!*@*.example. Within each component, * matches zero or more
bytes and ? matches one byte. Other permitted bytes are literal; there are
no regex classes, escaping, or shell expansion. Nick uses IRC case rules;
user and host ignore ASCII case. Whitespace, controls, and non-ASCII are
invalid. Removal compares stored patterns under those case rules; it does
not expand wildcards to remove other masks.

Only incoming user-originated PRIVMSG/NOTICE is filtered, before mentions or
query creation. A source needs an explicit user prefix; nickname-only masks
can match incomplete user/host details, while full masks require all three
parts. Bare server notices and all protocol/membership state remain visible.
Existing history is retained. Filtering is local, not a server ban. Settings
edits the same list; Apply acts live. /save or Settings Save persists it in
normal mode; test-mode edits stay in memory. Config repeats mask= in
[ignore].

DELAYED STARTUP COMMANDS

Each profile may run up to 16 literal commands after registration and
required SASL succeed. Default delay is 15 seconds, then at least 2 seconds
between completed commands; a stalled connection never creates a catch-up
burst.

    /autocommands [list|add COMMAND|remove NUMBER|clear|on|off]
    /autocommands delay SECONDS       0..300
    /autocommands interval SECONDS    2..60
    /autocommands add /msg ChanServ OP #room mynick
    /save

Supported commands are /msg, /join, /nick, /away, /back, /whois and their
documented exact aliases. Each is at most 511 UTF-8 bytes and must fit one
IRC line; no silent split, shell, raw IRC, loops or current-conversation
substitution exists. /join takes one channel/optional transient key. Lists
redact message/key text; execution omits command history/local echo/query
creation. Replies arrive normally; automatic joins do not switch chat.

Edits apply next connection. /cancel stops remaining startup commands and
queued chat without retracting sent/in-flight bytes. Closing/parting a
target cancels a remaining sequence referring to it. Failure cancels later
commands and identifies position without secret text. Reconnect starts a new
sequence; bouncer profiles also run explicit startup commands. Offline mode
runs none.

[autocommands] has enabled, delay_seconds, interval_seconds and repeated
command= lines. Bytes after = are literal, including spaces/#/;/=. Any
nonempty list, even disabled, requires an owned regular 0600/0400 config;
enabled nonempty lists require verified TLS. New profiles start empty; a
changed destination clears an unchanged inherited list. Save deliberately;
GPG credential storage does not encrypt these configuration commands.

PROGRAM AND QUEUE NOTIFICATIONS, QUERY NUMBERS, AND ALIASES

/set queue_notices off hides routine queued/paced acknowledgments in all
interfaces and servers. /set queue_notices on restores them. In the
minimalist frontend, an explicitly reviewed send omits its redundant routine
queue acknowledgment even when queue notices are enabled. /set
program_messages off separately hides low-priority local feedback such as
draft-cancelled, input-cleared, preserved-draft, and similar success/cancel
notices. Errors, byte-limit warnings, and send confirmations remain visible.
Both defaults are true. /save output or /saveconf persists the global
[output] settings. The same preferences appear in /panel Application
preferences and graphical Interface settings.

/ql numbers private queries separately, starting at 1. /query 2 or /pm 2
selects its second entry; a nickname works in the same argument. Closing a
query renumbers later entries. Opening a query sends no message. Channel 0
still opens the server's messages and MOTD.

Common exact aliases include /j, /leave, /message, /privmsg, /nickname,
/names, /nicks, /conn, /disc, /unaway, /detach, /saveconfig, /configure and
/preferences. They share command validation, completion and privacy rules.
Unknown spellings remain errors rather than guessing an action to execute.

Membership changes, MOTD, WHOIS, invites and common errors use readable
messages with useful server detail. Internal identity/capability replies do
not add duplicate protocol bookkeeping to the chat display. Unknown replies
retain the server's text without treating a numeric code as the explanation.

FILE TRANSFERS

F6, /dcc or /transfers opens the workspace-wide list, identifying each
originating server. Common list controls apply; actions are:

    Accept    Reject    Send...    Cancel transfer    Back

Review needs at least 12 rows by 20 columns. Escape from a browser/field
returns to its form, then from the form/list returns to chat, preserving
drafts and accepted transfers. This is active classic IPv4 DCC SEND only: no
CHAT, resume, passive/reverse transfers, auto-accept, address discovery or
port forwarding. Maximum file size is 4,294,967,295 bytes. Received files
are never opened/executed for you.

DCC is an unencrypted direct connection independent of IRC TLS, without
cryptographic peer authentication. Offers expose the advertised IPv4;
acceptance exposes the recipient's IP. Verify sender, endpoint, intended
file and byte size before accepting each offer.

An incoming offer opens no file/socket until explicit acceptance. List
Accept opens a review with Directory/Save as and Edit/Accept/Cancel. Enter
in a field stages it; only the form's Accept starts transfer. Paste inserts
data only in an active editor; it cannot accept. Reject creates nothing.

The full-mode offered receive directory is $XDG_DATA_HOME/vipirc/downloads
when absolute, otherwise $HOME/.local/share/vipirc/downloads when HOME is
absolute; without one enter an explicit path. Missing ancestors are created
0700 only on Accept. The final parent must be owned/private; the new file is
0600. Existing files, symlinks and '..' are refused. A basename must be
visible/nonhidden, with no separators, control/bidirectional-formatting
characters or quotes. Quoted wire filenames may include spaces.
Failed/cancelled partials are removed only while still the originally
created file, never a replacement.

Send... opens Nickname, Source file, Advertised IPv4 and Listen port, with
Edit/Browse, Offer, Cancel. A query supplies its peer default; the form
identifies the IRC server. Only Offer starts a listener and queues a paced
offer through that registered server. The source must be an existing regular
file without symlinks or '..'. Port 0 selects an available port; explicit
ports are 1..65535. NAT can require reachable advertised IPv4 and
forwarding; no UPnP/public-address service is called.

Browse begins at launch directory: arrows select, Enter opens a
directory/chooses a file, parent/Backspace goes up, Type path accepts an
absolute filename, Escape cancels without changing the source. Selection
fills the form without offering it or changing process cwd. Each loop
examines at most 64 entries; listing retains 512 and stops after 4096
examined. Use Type path for omitted entries. Symlinks/unsafe names are
omitted and metadata is rechecked at selection/offer.

    /dcc alice file.txt
    /dcc send -address 203.0.113.10 -port 5000 alice file with spaces.txt
    /dcc list
    /dcc accept 1 /home/me/private-downloads
    /dcc reject 2
    /dcc cancel 3

Replace the example IP with a reachable one. Command PATH is the literal
remainder including spaces, without shell quotes. Relative paths refer to
launch cwd, even after backgrounding/browsing. The default advertised IP is
the IRC socket's local IPv4; IPv6-only connections need an explicit IPv4
override, NAT may require one. Command-form accept without DIRECTORY uses
launch cwd and the same private-directory checks. Bare /dcc prints a list in
minimalist mode. Both frontends share manager/limits/cancellation.

With SSH, all paths, addresses and connections belong to the host running
vipirc, not the terminal's local computer. Accepted transfers continue
through chat/view switches and IRC Disconnect. Closing the originating
server cancels its transfers; quit stops all. Failure/cancel/expiry removes
a queued offer, but cannot recall one already sent/in flight.

Limits are 8 pending offers, 4 active/listening/connecting transfers and 12
retained records across the workspace. Records recycle oldest
completed/failed first only when full; IDs are not reused during a run.
Offers expire after 5 minutes, transfers stop after 2 minutes without
progress. Streaming uses bounded buffers and cumulative 32-bit
acknowledgments. Test mode permits review/reject/cancel of a memory sample;
Send/Accept refuses before file/socket work.

INPUT EDITING

Enter                  Submit or review composition.
    Left/Right             Previous/next character group.
    Up/Down                Move through wrapped input rows, not chat recall.
    Home/End               Start/end of complete composition.
    Backspace/Delete       Remove previous/current character group.
    Tab/Shift-Tab          Complete next/previous nickname.
    Escape                 Open Queries from a query, otherwise vipirc.
    /clearinput            Clear entire draft, including offscreen text.

F1..F6 opens available panels. Chat letters including hjkl are literal.
Typed Enter sends; explicit newlines enter through bracketed paste, with
pasted tabs becoming spaces. A typed slash at caret zero opens independent
Command, preserving the draft; later/pasted slashes are text.

The draft is one logical buffer: wrapping inserts no text, Backspace crosses
visual rows, and resize preserves text/caret. The fixed field reserves
floor(B/W)+1 rows for payload budget B and usable columns W, clamped to
terminal space. Typing/deleting does not resize it; longer drafts scroll
inside. View/protocol-budget/terminal-size changes recalculate height.
Command has its own field and /msg or /me never replaces the chat draft.

A bare raw Escape waits about 500 ms; a partial sequence permits 1000 ms
between continuation bytes while networking continues. Complete decoded keys
act immediately. An opening paste marker delayed beyond its first-Escape
grace can act as Escape; in the minimalist log it can background the client.
Once capture begins, closing paste markers remain recognized across
arbitrarily delayed split reads. Its trailing keys cannot cancel the
draft or change modes before the visible review/quiet-input boundary.

Input needs valid UTF-8 or explicit ASCII locale mode; see FILES AND
ENVIRONMENT. A base character and following zero-width marks move/delete
together; full Unicode grapheme segmentation is not implemented. Unsupported
glyphs get a visible replacement. Draft limits are 8192 Unicode scalars and
16384 UTF-8 bytes, whichever arrives first. Invalid encoding/controls are
rejected. Pasted newlines remain visible and affect the send plan; the
smaller IRC budget governs warnings/splitting.

MOUSE CONTROLS

Mouse is enabled by default when curses/TERM/terminal support it. /mouse
toggles, /mouse on|off sets it, and Settings > Interface edits/saves the
primary-owned [interface] mouse preference. Keyboard operation works without
it; the terminal/SSH multiplexer must forward events.

Click a header category to open it, chat to place the caret, Clear to erase
the entire draft, Send to submit through normal checks. Clear/Send hides
when unavailable. Nicknames in chat/roster offer Whois/Query; clicking
#channel selects or joins it. Displayed token identity, not a later
replacement at those coordinates, determines the action. URLs and clipboard
contents are not opened.

Item clicks open server/channel/query rows; action clicks act on the
selection. Wheel changes selection while preserving the action. Over chat
history/roster it scrolls three visual rows/users. Settings and transfers
retain their own field/action controls. Chat needs at least 9 rows by 20
columns; narrow headers keep focus visible.

Mouse does not acknowledge early-length or split-send dialogs; use their
keyboard choices. Command Run/Cancel requires a fresh action after paste.
Pasted click sequences/newlines cannot activate it, and clicks from an old
layout are not reused on a newly opened screen.

MESSAGE LENGTH AND FLOOD PREVENTION

IRC's ordinary line limit is 512 bytes including CR/LF, not 512 displayed
characters. UTF-8 scalars use 1..4 bytes and glyphs can combine scalars.
Command, target and relay identity consume space. For :nick!user@host
PRIVMSG target :text, the payload is:

    B = L - (len(nick) + len(user) + len(host)
             + len(target) + len("PRIVMSG") + 9)

Lengths are bytes; L is 512 or a recognized smaller LINELEN. Actions
subtract their envelope too. Conservative allowances apply until identity is
known. Changing identity/target can change B; vipirc does not assume larger
lines are accepted.

Full-mode editing warns when a logical line reaches B or the draft needs
several messages. Enter/Escape acknowledges continued editing and sends
nothing; other keys cannot dismiss it, and key-repeat protection applies.
The warning rearms after returning below the threshold.

Minimalist editing instead blocks additional insertion at the boundary until
Enter explicitly authorizes continued editing; that Enter sends nothing.
Backspace/Delete can reduce text and Escape cancels. /msg, /me and // are
measured by their real payload, unrelated local commands are not. Paste
stays intact within storage bounds and is checked after capture.

Full ncurses asks separately before submitting a multi-message draft:

    This text needs N IRC messages. Send all to TARGET? [y/N]

Only affirmative y sends; Enter/n declines and keeps the text. Minimalist
mode instead shows Review: a fresh Enter confirms, Escape returns to editing.
Both require explicit split consent even in direct mode. Splits preserve
complete UTF-8 scalars and nonempty text; explicit newlines separate messages
and empty lines are skipped. Commands remain single-line; compose multiline
chat in the conversation.

Chat is paced at least 1.2 seconds apart through a 64-message queue. /cancel
removes still-unsent work; it cannot retract an in-flight or delivered
message. Protocol control such as PONG is separate. A network may impose
stricter limits or reject text; local acceptance/echo does not prove remote
delivery.

CONFIGURATION

vipirc --init-config --server irc.ircnow.org --channel '#ircnow'
    vipirc --check-config

Generate an editable starting point, edit it, then validate. One file
describes one profile; --config selects the primary and adjacent
saved-server catalog. Up to eight profiles share a process. Separate primary
paths can form independent workspaces. The shipped examples and
--init-config provide complete syntax.

Current sections and supported fields:

    [connection]
      server, port, tls, nick, username, realname, channel, autoconnect,
      auth, auth_user, password_file, password_gpg_file, password,
      server_password_file, server_password_gpg_file, server_password, ca_file
    [bouncer]
      type=none|znc|soju, username, network, client, automatic_away=false
    [interface]
      user_list=true, mouse=true, hints=true, shortcut_labels=true,
      history_lines=500
    [input]
      send_mode=direct|review, composer_mode=line|fullscreen,
      command_suggestions=common|history|frequent|alphabetical|contextual,
      use_signals=false
    [hotkeys]
      optional KEY=action rows; empty by default, at most 64
    [output]
      format=compact|full, queue_notices=true, program_messages=true,
      persistent_logging=false
    [session]
      single_session=false, default_interface=ncurses|idle
    [presence]
      part_message=, quit_message=Client quit, background_away=true,
      background_away_message=Detached from terminal,
      autoaway_minutes=15, autoaway_message=Idle
    [autocommands]
      enabled=true, delay_seconds=15, interval_seconds=2, repeated command=
    [mentions]
      repeated word=literal phrase
    [ignore]
      repeated mask=nick!user@host

This key map is a reference, not a config block to paste: each actual
key=value occupies its own line. Defaults choose direct send, line composer,
Common suggestions, compact output and ncurses launch. Application
preferences belong to the primary config and apply across servers;
connection/auth/bouncer/watch/ignore/startup lists belong to each profile.

Nickname differs from IRC username; empty interactive primary nickname
prompts with a login default. Username defaults from the account; realname
is a descriptive USER field, not necessarily a legal name. channel is a
comma-separated direct-profile autojoin list without spaces; empty means
server view. Bouncers restore their own memberships.

For direct SASL, auth=sasl needs auth_user and exactly one password source.
Server PASS independently chooses one server_password source. More than one
source per credential is an error without fallback; both paths require
verified TLS. Bouncers require empty auth_user and derive their login; see
BOUNCER CONNECTIONS. Inline secrets remain plaintext; file/GPG rules are
under AUTHENTICATION.

History accepts 50..5000 lines per view, default 500, with an 8 MiB
per-server text cap that can evict sooner. Minimalist retention also has its
global 2048-record/512 KiB caps. Booleans accept lowercase true/false,
yes/no, 1/0. Unknown sections/keys and invalid/oversized values fail with a
line number where applicable. Most duplicates use the last value; repeated
watch/ignore/autocommand entries accumulate within limits.

Lines beginning # or ; after whitespace are comments; there are no inline
comments. Ordinary value edges are trimmed. No quoting, escapes,
variable/tilde expansion or shell evaluation exists. Prefer absolute literal
paths. Apply/Save rejects outer ASCII spaces in ordinary fields so they do
not change on reload; interior spaces remain allowed where valid.

password=, server_password= and autocommands command= preserve every byte
after = except line endings, including spaces, =, # and ;. Do not add quotes
or inline comments. Empty password means no source; spaces alone are
nonempty. Password controls/newlines are invalid.

/save regenerates supported settings including pending choices, replacing
comments/formatting; keep notes separately. File edits load in a fresh
process, not --resume. Save is disabled in test mode. Generated files are
0600 in an owned 0700 final parent; existing config must be owned and not
writable by others.
Symlinks (including path components) and '..' are refused. Any nonempty
inline password or startup-command list, even disabled, requires an owned
regular 0600/0400 config. Writes replace one file atomically, not an entire
workspace transaction.

single_session=true prevents a second managed vipirc worker, not extra
servers inside one worker. Presence defaults are listed above;
autoaway_minutes=0 disables the idle timer. Automatic return clears only
client-generated away, never a manual /away. Bouncer automatic away is
separately off by default.

Legacy [interface] keymap=original|vim and focus_style=reverse|brackets are
accepted but ignored and omitted on Save; other values are invalid.
The ordinary navigation and bold bracket focus remain. /keymap explains this
compatibility behavior rather than selecting a mapping. Queue/program
notices may be hidden independently; errors and required confirmations
remain visible.

HISTORY, LOGGING AND PRIVACY

There are separate kinds of history:

    Retained conversation/mention records: bounded memory for display.
    Command recall: accepted command lines in memory, with secret filtering.
    Command frequency counts: canonical names/counts in CONFIG_PATH.commands.
    Optional transcript: plaintext records in each saved profile's .log file.
    Bouncer replay: messages supplied by the bouncer under its own policy.

Detach/resume preserves live memory. /quit, --close-session, process failure
or reboot ends it. A new process loads saved configuration and optional
command counts; it does not import old transcript files as live conversation
history or recreate a previous catch-up anchor. /clear clears the current
view's retained memory without deleting an existing disk transcript or
retracting an IRC message.

Enable a transcript with /set persistent_logging on and save it with /save
output, or use Settings > Interface > Persistent logging. This is off by
default and applies across servers, with a separate file for each saved
profile. All path and file privacy checks described under CONFIGURATION
still apply.

Each log stops at 16 MiB; nothing is automatically rotated or deleted. An
unsafe path, busy lock or write failure disables logging for the affected
profile with an error while chat continues. Archive the old file, then turn
logging off/on to resume writing. Rotation can invalidate the old catch-up
anchor; send a new eligible message before relying on a later absence's
durable catch-up.

Known credential/service messages and sensitive copies under current or
old nicknames are excluded, including qualified service destinations.
Ordinary chat, unknown service syntax or manually pasted secrets
can still reach a log, and the remote service may retain its own copy.
Turning logging off prevents new records without erasing old ones. Private
permissions are not encryption and do not protect from another program
running under the same Unix account. Regular files on slow or
network-mounted storage can still delay disk I/O.

A saved transcript is CONFIG_PATH.log in an owned directory of exact mode
0700. Every path component must pass no-symlink/no-parent-traversal checks.
The opened file must be owned, regular, single-link and exactly 0600.
Nonblocking file/lock handling rejects a FIFO or busy log; the 16 MiB cap
applies per saved profile.

SAVED SERVER PROFILES

For primary path P, the adjacent P.servers catalog lists up to seven
secondary profiles in the private P.d directory. For the default path, these
are config.ini.servers and config.ini.d beside config.ini. Catalog syntax is
[servers] followed by repeated profile=ID entries. Generated names use
server-<24 lowercase hexadecimal characters>.ini. Manual IDs may contain 1
through 63 ASCII letters, digits, underscores, hyphens, or dots; the first
character must be a letter or digit, and consecutive dots are forbidden.
Directory components and arbitrary paths are not accepted as profile IDs.

Servers > New creates no file. Its first explicit /save or Settings Save
creates a separate mode-0600 profile in the mode-0700 directory and
registers it in the catalog. Subsequent saves update that server's profile.
Saving a secondary never replaces the primary configuration. Startup catalog
updates are locked. Invalid catalog/profile entries produce visible errors;
healthy profiles remain usable.

Close removes a secondary's catalog reference but keeps its profile file.
The primary cannot be closed. --check-config checks the selected primary,
catalog, and referenced profiles without connecting. At normal startup,
non-host connection overrides apply to the remembered default server;
explicit --server selects the primary. --init-config and --check-config also
apply their overrides to the primary. --no-connect suppresses startup for
all profiles. In test mode, Save is disabled and Close changes runtime only.

AUTOMATIC CONNECTION, JOIN, AND AUTHENTICATION

Each saved profile has independent autoconnect, direct autojoin and
credentials. Save wanted startup settings through Settings or the commands.
Explicit primary --server starts a connection; saved autoconnect profiles
start independently. --no-connect suppresses all. /connect or Servers >
Connect starts one explicitly. No new profile inherits another's secrets.

For a direct network account, configure:

    [connection]
    tls=true
    auth=sasl
    auth_user=your_registered_account
    password_gpg_file=/home/yourname/.config/vipirc/sasl.gpg

Select exactly one source for each independent credential:

    SASL account                  Server PASS
    password_gpg_file              server_password_gpg_file
    password_file                 server_password_file
    password                      server_password

The *_gpg_file source is encrypted; *_file is private plaintext; inline
values are literal plaintext in config. There is no extension guessing or
fallback. Inline leading/trailing spaces, #, ; and = are preserved; do not
quote or append comments. Config with inline secrets must be owned regular
0600/0400; generated Save is 0600. Values remain in session configuration as
needed for reconnect/Save.

Plaintext/decrypted passwords are one nonempty line, optionally
LF/CRLF-ended, without control bytes: SASL at most 1024 bytes, ordinary PASS
at most 503. Both file kinds must be owned regular 0600/0400, with no
symlink or '..' path components. No password is accepted as a CLI option.
Bouncers have assembled identities and source constraints described under
BOUNCER CONNECTIONS.

Encrypted files contain one integrity-protected OpenPGP message, at most
65536 bytes. Optional gpg in PATH must support the fixed options (GnuPG
2.2.20 or newer). It starts directly after verified TLS, without a shell,
with bounded output and a five-second deadline. No plaintext temporary file
or in-app passphrase prompt is used; other sessions continue. A
failed/locked/invalid/oversized/timed-out credential stops authentication.

The helper uses --no-options, --batch, --no-tty, --pinentry-mode error and
--no-autostart, with key retrieval/import/dirmngr disabled. Prepare/unlock
outside vipirc:

    gpg --output /dev/null --decrypt /absolute/password.gpg

Then retry /connect. That command contains a path, not a password. The
existing agent must decrypt noninteractively; an SSH host/session may have
different files, PATH, GnuPG home and agent cache.

--check-config validates source selection/config privacy without opening
secrets or GPG. --test-mode never decrypts/reads credentials; inline values
are parsed but unused. Neither proves a real credential works.

Required SASL PLAIN is sent only after TLS verification and server support.
Failure stops connection before direct autojoin instead of proceeding
unauthenticated. The client does not register network accounts.
Nickname-service syntax is network-specific; direct automatic account
authentication uses SASL. Server PASS is distinct from a nickname account;
bouncer upstream authentication is separately configured there.

BOUNCER CONNECTIONS

Use Settings or /panel to choose ZNC/soju, then provider hostname/TLS port,
bouncer username, existing upstream network and optional stable client name.
Use one saved profile per network. Profiles sharing a host should be
selected by server number before bare /connect.

[bouncer] supports type=none|znc|soju, username, network, client and
automatic_away. Username/network are required, client optional; each permits
at most 63 ASCII letters/digits/dots/underscores/hyphens. Enter components
separately and only the password in its password source.

ZNC requires auth=none, empty auth_user, no SASL source and exactly one
server-password source. It builds username/network or
username@client/network, appending the password for PASS. Identity,
separator and password must fit the 503-byte payload, reducing the usable
password length. soju requires auth=sasl, empty auth_user, one
authentication-password source and no PASS source. It derives
username/network or username/network@client as its SASL identity. Both
require verified TLS. Configure upstream network/NickServ authentication on
the bouncer separately.

Bouncers restore memberships; local autojoin is not replayed and /autojoin
edits are refused. /join and /part change memberships. /autoauth changes are
refused too: use Settings or /panel for coherent identity/source changes.
Explicit startup commands still run, so review any inherited direct-profile
commands before reuse. Automatic idle/background away is off unless
automatic_away=true; manual /away and /back remain available.

    /znc                   Ask ZNC for Help.
    /znc ListNetworks      Send one ZNC control command.
    /soju                  Ask soju for help.
    /soju network status   Send one soju control command.

The shortcut requires the matching bouncer type. Arguments are literal
service text fitting one IRC message, using normal pacing. /msg *status or
*module addresses ZNC; /msg BouncerServ addresses soju. Remote command
availability is defined by that bouncer; start with its help.

Control text is excluded from local echo, recall and persistent logs.
Recognized outgoing service replay copies remain suppressed even with an old
nickname. Replies appear in the server view without persistent logging.
Typed editor text remains visible and remote logging is separate.

Known pushed history retains original UTC timestamps and routes outgoing
private messages to their recipients. Replay does not trigger CTCP/DCC,
fresh mentions or live-state mutation. Storage is bounded; unknown batch
kinds are conservatively display-only. No on-demand archive browser,
automatic network discovery or automatic profile-per-network creation is
implemented.

TLS covers client-to-bouncer only; upstream TLS/auth/access/retention need
separate setup. See doc/BOUNCERS.txt and examples/bouncer-znc.ini /
examples/bouncer-soju.ini. Controlled fixture results do not prove every
live provider/version.

TLS AND CUSTOM TRUST

Verified TLS checks the requested hostname/numeric address and certificate
chain. No bypass or silent plaintext fallback exists; a port number alone
never disables TLS. Use the provider's exact endpoint. --ca-file FILE or
[connection] ca_file=FILE selects PEM authorities instead of the TLS
library's default store; this is custom trust, not leaf pinning.

A custom bundle must be a nonempty regular file <=16 MiB. Ordinary symlinks
to regular CA files are allowed, unlike config/credential paths. The loader
opens once with nonblocking flags, reads a pinned descriptor within the size
bound, and rejects detected growth/shrink. FIFOs/devices/nonregular inputs
fail. The bounded-memory PEM parser preserves supported certificate trust
metadata/CRLs and cannot prompt for a password.

These checks do not bound regular/network-filesystem I/O latency. Use
trustworthy suitable storage. --check-config does not test CA
loading/handshake, and offline simulation never exercises TLS. Diagnose
certificate errors before changing trust; plaintext credentials are refused.
TLS covers this connection, not end-to-end chat or the bouncer's upstream.
DCC is separately unencrypted.

SECURITY AND RESOURCE BOUNDS

TLS verifies the certificate chain and the requested hostname or numeric
address. There is no certificate-verification bypass or silent downgrade.
Plain IRC is available only through an explicit setting; it exposes IRC
traffic to observers on the connection path and cannot use saved secrets.
TLS protects the client-to-server connection, not end-to-end chat privacy.

Operational startup rejects mismatched real/effective user or group IDs and
disables core dumps before reading configuration. Linux also disables
process dumpability. The client is an ordinary process without an OS
sandbox; another process under the same account is within its trust
boundary.

Recognized private authentication commands require verified TLS even when
entered as ordinary message text, split across a send plan or queued.
Detection cannot reliably recognize arbitrary new secret syntax; keep
credentials out of chat and shell arguments.

Incoming IRC data is untrusted. Unsafe control sequences and formatting are
sanitized before display. Input and network buffers are bounded. The client
does not execute received text, launch URLs, run shell commands, load
scripts or plugins, or reply automatically to CTCP requests. Action messages
are displayed as text. DCC SEND offers require explicit per-file review and
acceptance; their direct connections are not encrypted by TLS.

Limits in this release:

    Server sessions per process           8
    Views per server, including builtins  32
    Users stored per channel           4096
    Custom mention strings per server     32
    Ignore masks per server               32
    Queued chat messages per server       64
    Command history entries per server    64
    Command history text per server  64 KiB
    Retained history text per server   8 MiB
    Input Unicode scalars per draft     8192
    Input UTF-8 bytes per draft        16384
    Pending DCC offers, whole workspace    8
    Active DCC transfers, workspace        4
    Retained DCC records, workspace       12

The history cap applies per server, not as a total-process memory cap. At
eight sessions the maximum retained history text is 64 MiB. Server state is
allocated as needed; fewer sessions do not reserve eight full histories.
Libraries, view metadata, user lists, input, and transport use more memory.
Conversation history is memory-only unless optional persistent logging is
enabled. The separate mention view is not a permanent archive; its eligible
source conversation may be logged. Settings, credentials and optional
plaintext logs are local files; other software with your account's
privileges can read them. No client can guarantee safety against every
hostile server or a compromised terminal, operating system, or library.

CREATING ENCRYPTED PASSWORD FILES

Creating a GPG credential: /panel works in both interfaces. Select the
server, choose gpg as the authentication or server-password source, then
choose create. Create offers an absolute destination in a credentials
directory beside the selected configuration. For the default primary
configuration this is:

    ~/.config/vipirc/credentials/account-password.gpg

The server PASS password uses server-password.gpg. Existing names are
skipped with numbered alternatives. The actual absolute path is shown in the
panel; the tilde above is explanatory, not literal configuration syntax.
Enter accepts the offered location and may prepare its private directories
with mode 0700. Viewing the offer creates nothing. A custom destination must
have an existing owned private parent; existing directories are never
chmodded. The destination and local gpg availability are checked before
asking for the key and password. Enter the full 40- or 64-digit hexadecimal
fingerprint of an encryption key already in the local GPG keyring, then
enter and repeat the hidden password. Existing encrypted files remain
selectable. Paths entered in the panel are stored as absolute paths, so
another launch directory does not change their meaning. No key is downloaded
or generated, and no plaintext password file is made.

Only the final Save, Apply, or Connect choice starts encryption and
publishes the explicitly requested new mode-0600 ciphertext. Apply only and
Connect once can create ciphertext while leaving configuration unsaved.
Existing files and symlinks are refused. Each helper has a five-second
deadline; the interface continues processing network events. Encryption
failure keeps settings unapplied and reports the affected path and reason
without secret or helper output. Finish distinguishes proposed destinations
from files already created. A successful result directs you to /autoauth
status for complete paths; a failed save or partial publication keeps the
relevant locations in the scrollable review. A failed config save can be
retried without reencrypting. Cancellation removes only unchanged new files
from this attempt; files already referenced by a saved config are retained.
Escape moves back one question and cancels pending creation; closing setup
wipes its hidden inputs. Offline mode refuses creation before any GPG,
keyring, or file access. For later decryption, unlock the private key
outside the application if needed.

TROUBLESHOOTING

Ordered checks: doc/TROUBLESHOOTING.txt. Do not share private logs or secrets.

Connection: read the server error and check host/port/TLS. /connect retries
manually; --reconnect retries transient faults. See TLS AND CUSTOM TRUST;
do not work around verification failures by sending credentials over plain IRC.

Authentication: /autoauth status shows current/pending paths, never secrets.
Check account/source rules under AUTOMATIC CONNECTION, JOIN, AND AUTHENTICATION.

GPG: see CREATING ENCRYPTED PASSWORD FILES for destination preflight and
AUTHENTICATION for decryption limits, permissions and external unlocking.

Channels: finish registration/authentication. /autojoin shows direct-profile
pending joins; bouncers restore channels. See CONNECTION AND STARTUP COMMANDS.

Resume busy: inspect --sessions, then --detach-session NUMBER and --resume
NUMBER. --close-session ends the worker. See SESSION RECOVERY AND UPGRADES.

Up/display: Compose arrows edit; Command recalls accepted safe commands.
For hidden wrapped rows, inspect retained text. See MINIMALIST WRAPPING
AND INPUT HISTORY.

Text widths: use matching UTF-8 locale, TERM and font; resize preserves the
draft/caret. Small terminals constrain panes. See FILES AND ENVIRONMENT.

Save: test mode refuses writes. Check private paths and permissions under
CONFIGURATION; saving, applying and startup autoconnect are separate actions.

Logging/catch-up: inspect the exact error; chat continues. Limits, rotation,
new sent anchors and fallback are under HISTORY, LOGGING AND PRIVACY.

Child ownership: SIGCHLD children must remain waitable. Ignoring it or
automatic reaping prevents first background/helper startup; fix the launcher.

FILES AND ENVIRONMENT

Default primary configuration:

    $XDG_CONFIG_HOME/vipirc/config.ini
    $HOME/.config/vipirc/config.ini

XDG_CONFIG_HOME takes precedence when nonempty and must be absolute. HOME
supplies the fallback; account database information is used if an absolute
home cannot be obtained from HOME. --config FILE selects another primary and
its adjacent saved-server workspace. Paths written in configuration are
literal, with no variable, tilde or shell expansion; the displayed variables
above describe how the defaults are chosen. Your shell still performs normal
argument quoting and expansion before passing command-line arguments.

For primary path P, P.servers stores saved profile IDs and the optional
[servers] default=PROFILE_ID choice managed by /saveconf. P.d/ contains
secondary profile files. Each saved configuration may have a .commands file
of canonical command counts and an optional .log transcript. Generated
configurations and secondary profiles require explicit Save;
accepted-command counts update their existing saved workspace automatically.
An unreadable or missing remembered default is reported rather than silently
retargeting a connection.

The full interface offers $XDG_DATA_HOME/vipirc/downloads as the default DCC
receive directory when XDG_DATA_HOME is absolute, otherwise
$HOME/.local/share/vipirc/downloads when HOME is absolute. The offered
directory is created only after explicit acceptance. Command-form /dcc
accept NUMBER without DIRECTORY uses the process's launch directory and
requires it to be owned and private. Choosing/browsing a path never changes
that launch directory.

PATH locates the optional gpg executable; no shell is invoked, and that
executable is part of the trusted local environment. GNUPGHOME is
interpreted by GnuPG for its key/agent environment. The client does not
expand it inside credential paths. Remote SSH operation uses the environment
and files on the host running vipirc.

TERM describes capabilities for ncurses; it does not select the text
encoding. LANG, LC_CTYPE and LC_ALL select the locale. Use an installed
UTF-8 locale that matches the terminal for Unicode editing and widths.
locale, locale charmap and locale -a help inspect the host; locale names
differ across systems.

Interface translation: set VIPIRC_LANG to id (Indonesian), ms (Malay),
tr (Turkish), es (Spanish), pt (Portuguese), fr (French), de (German),
ru (Russian), it (Italian), or ar (Arabic) when starting vipirc.
The override also accepts values such as id_ID.UTF-8. Both the ncurses and
-i interfaces select the same catalog. English is the fallback. A detached
worker keeps the display language chosen when that worker was launched.
IRC slash commands, config keys, and control values remain in English.
This release translates selected interface controls, not every help page,
security warning or error. See doc/LOCALIZATION.md for details.

The active LC_CTYPE is respected. A non-UTF-8 or invalid locale selects
explicit ASCII terminal mode, shown on the welcome. Non-ASCII input is
refused with a status message; incoming non-ASCII code points display as '?'
without changing stored network text. The client does not guess/transcode
legacy encodings or force a locale. Select an installed UTF-8 locale and
restart for Unicode use. ASCII remains the one-byte subset of UTF-8; SSH
does not change IRC's encoded byte limits.

EXIT STATUS

0     Normal completion or interactive exit.
    1     Operational failure, such as initialization, save or session control.
    2     Invalid options/configuration or no terminal for interactive use.
    130   SIGINT interrupted the welcome after terminal cleanup.
    131   SIGQUIT interrupted the welcome after terminal cleanup.

A successful --background status confirms local worker setup, not remote IRC
login. A failed session-close status means completion was not verified;
recheck --sessions because an accepted request may finish later.

PLATFORMS, BUILD, AND LICENSE

Targets include Linux, ChromeOS's Linux environment and the BSDs. Building
needs C11, POSIX interfaces, GNU/BSD getopt_long, wide-character curses and
compatible TLS development files. The client needs no language runtime.
Python 3 serves tests/documentation generation; shipped exports allow an
ordinary build and chat without it. See INSTALL for dependency details.

    ./configure
    make
    make check-offline
    make check
    make install PREFIX="$HOME/.local"

See INSTALL for dependency and build details, SECURITY.md for the security
model and limits, and the release validation report for platforms actually
tested. Native BSD execution is a separate validation step; portability
intent is not evidence of having tested every Unix-like operating system.
make check-offline runs the CLI/PTY suite without a network socket. The
broader make check suite also uses local loopback fake servers.
