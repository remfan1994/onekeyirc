/help about
-----------

Una aplicación de ThatIAm.vip (www.thatiam.vip), diseñada por remfan1994.

Licencia: IALA (Insha-Allah License Agreement); consulte el texto de licencia incluido.

Aviso de bienvenida: ¿No es vegetariano? www.bloodguiltcurse.net le hará cambiar de opinión

Una sesión en ejecución también muestra este recordatorio local una vez al adjuntar una interfaz:

Matar vacas es derramar sangre inocente. www.bloodguiltcurse.net - prohibamos la carne de vacuno.

El recordatorio no requiere otra respuesta y no se envía a IRC. Reconectar o volver a adjuntar la interfaz no reinicia su marca de una vez por proceso de trabajo.

/help aliases
-------------

Los alias deben coincidir exactamente; no se ejecutan nombres ambiguos ni aproximados.

/conn = /connect; /disc = /disconnect; /detach = /background; /exit = /quit

/j = /join; /leave = /part; /message y /privmsg = /msg

/nickname = /nick; /names y /nicks = /users; /unaway = /back

/channellist = /cl; /querylist = /ql; /serverlist = /servers

/configure y /preferences = /panel; /saveconfig = /saveconf

/autocommand = /autocommands

El autocompletado sugiere nombres canónicos; conserva los argumentos y el mismo filtro de historial sensible.

/help authentication
--------------------

Use TLS verificado con /autoauth sasl USER file PATH o /autoauth sasl USER gpg PATH.

El archivo de clave o el contenido GPG descifrado aporta la credencial; las rutas son literales.

Use /panel para crear una credencial cifrada con GPG para una huella de clave pública local existente.

Use una clave GPG ya desbloqueada. No se ejecuta pinentry en el editor del chat.

También se admiten password= y server_password= en texto claro en archivos privados de configuración.

Elija una sola fuente por credencial. /settings y /summary ocultan las rutas de los archivos.

/autoauth status muestra las rutas actuales y pendientes sin leer los archivos ni mostrar claves.

Los ajustes de autenticación se aplican en el siguiente /connect tras desconectar; /save los guarda.

En un perfil bouncer, gestione el inicio y su fuente juntos desde /panel; se rechazan cambios de /autoauth.

Los archivos de credenciales deben ser normales, propios, con modo 0600 o 0400; no se admiten enlaces simbólicos ni recorrido del directorio padre.

El límite SASL es 1024 bytes; PASS normal admite 503 bytes. El inicio ZNC combinado debe caber en una línea IRC.

--check-config valida configuración y fuentes sin leer credenciales ni probar el acceso. Vea /help tls y /help bouncers.

/help bouncers
--------------

Abra /panel, elija un servidor y seleccione el tipo znc o soju.

Indique host y puerto TLS del bouncer, usuario del bouncer, red ascendente existente y, opcionalmente, nombre de cliente estable.

Guarde un perfil por red ascendente. Seleccione el perfil correcto antes de /connect sin argumentos si comparten servidor.

El cliente compone la identidad. ZNC usa la fuente de clave del servidor; soju la de autenticación. Introduzca solo la clave del bouncer, no un nombre combinado ni la clave de NickServ.

El bouncer restaura canales. No reproduce /autojoin local ni acepta cambios: use /join y /part.

Los comandos de arranque explícitos siguen activos. Revíselo antes de activar el perfil para evitar uniones o comandos de servicio repetidos.

El estado away automatico por inactividad/segundo plano esta desactivado salvo activación. /away y /back manuales siguen funcionando.

La historia recibida usa fechas UTC originales, dirige privados a su destinatario y no crea menciones, ejecuta CTCP/DCC ni cambia el estado activo.

El historial es limitado. No hay búsqueda de archivos bajo demanda, descubrimiento de redes ni perfiles automáticos por red.

Use /znc o /soju sin argumentos para obtener ayuda. El control no entra al historial ni al eco; las respuestas aparecen en la vista del servidor sin registro persistente.

Se ocultan las copias de control saliente reconocidas incluso con un alias antiguo al reproducir. El texto escrito aun puede verse y el bouncer guarda registros segun su propia politica.

El cliente solo conecta al bouncer. Configure aparte TLS, autenticación y retencion en la conexión ascendente.

Vea doc/BOUNCERS.txt y los ejemplos del bouncer en examples/ para configuración y limites de las pruebas realizadas.

/help configuration
-------------------

[connection] incluye server, port, tls, nick, username, realname, channel, autoconnect, auth y fuentes de credenciales.

[bouncer] type=none|znc|soju, username, network, client y automatic_away definen el perfil bouncer de cada red; véase /help bouncers.

[input] send_mode=direct|review y [output] format=compact|full, queue_notices=true|false, program_messages=true|false, persistent_logging=true|false son preferencias del archivo principal.

[input] command_suggestions=common|history|frequent|alphabetical|contextual ordena los comandos; common es predeterminado.

[input] composer_mode=line|fullscreen elige el editor/comandos minimalista; line es predeterminado. Ambos conservan la vista de mensajes recientes.

[input] use_signals=false desactiva las señales generadas por la terminal mientras el cliente controla la tty. true activa las asignaciones de señales existentes. «Aplicar» surte efecto ahora; «Guardar» guarda esta preferencia en la configuración principal.

[hotkeys] contiene hasta 64 atajos KEY=action opcionales, sin valores iniciales. Pertenece a la configuración principal; vea /help hotkeys.

[session] single_session=true|false permite o no varios trabajos en segundo plano; false es predeterminado.

[session] default_interface=ncurses|idle es una preferencia principal. Las opciones de inicio se explican abajo.

El formato compact es predeterminado. history_lines en la configuración principal limita el historial de todos los servidores.

[mentions] word= e [ignore] mask= pueden repetirse.

[autocommands] contiene enabled, delay_seconds, interval_seconds y líneas command= repetidas para un servidor.

Estos comandos son texto sin cifrar en la configuración privada. /autocommands los administra sin mostrar secretos en listas ni historial.

Los servidores adicionales guardados usan el catálogo .servers y directorio .d contiguos.

Conecta con /connect HOST y usa /join #channel y /saveconf para guardar la configuración funcional.

/saveconf guarda preferencias y perfiles válidos; recuerda el servidor seleccionado para un futuro /connect sin argumentos.

/quickstart hace cuatro preguntas de conexión. /panel usa 0 para preferencias y 1..8 para perfiles; panel 1 edita el principal.

Los cambios del panel son privados hasta «Finalizar». Aceptar una ruta GPG puede preparar el directorio 0700; cifrado, escritura y conexión esperan la opción final.

Para conservar cambios: /save para el servidor elegido, /save input o /save output para el principal, o /saveconf para perfiles válidos y predeterminado.

La configuración guardada usa <config_path>.commands para leer/escribir recuentos de comandos; el archivo principal no guarda recuentos.

El archivo privado limitado solo contiene nombres canónicos y recuentos, nunca argumentos ni historial. El modo de prueba no lo lee ni escribe.

Los cambios [connection] de /autojoin o /autoauth entran en vigor en el siguiente /connect desconectado; no alteran la sesión activa.

Los archivos de configuración son privados; cada archivo se sustituye atómicamente, no todo el conjunto a la vez. Sin importar/exportar.

Las secciones, claves o valores desconocidos dan error. La configuración usa valores literales, sin comillas shell, escapes, variables ni ~.

Los valores normales se recortan en los extremos. password= y server_password= conservan todo tras = salvo el salto de línea; no añada comentarios ni comillas.

Guardar reescribe ajustes admitidos y sustituye comentarios y formato manual. Conserva tus notas fuera de la configuración generada.

Véase /help authentication para secretos, /help tls para CA, /help logging para registros y /help sessions para trabajadores activos.

/help deployment
----------------

Use --background para iniciar una sesión sin terminal ni pulsar una tecla de bienvenida.

Configure y guarde /autoconnect on para cada servidor que deba iniciarse.

--background no activa autoconnect por sí solo; --no-connect sigue impidiendo las conexiones iniciales.

El aviso habitual aparece una vez antes de separarse. El éxito indica un trabajo local, no un inicio de sesión IRC.

Desde otro terminal con la misma cuenta, use --sessions y --resume [NUMBER].

--sessions incluye trabajos adjuntos. --detach-session NUMBER libera la terminal adjunta sin destruir el trabajo, para reanudarlo desde otra. --close-session NUMBER termina el trabajo seleccionado y todas sus conexiones IRC.

Use el ID de trabajo listado, no un PID. Los procesos sin respuesta o antiguos sin el control solicitado pueden fallar. Consulte /help sessions para recuperar sesiones y actualizar.

Reiniciar el VPS termina los trabajos, borradores e historial en RAM. Una tarea del sistema puede iniciar otro cliente.

Las instrucciones de OpenBSD y un ejemplo opcional de rc.d están en doc/OPENBSD-VPS.txt.

Ejecute el cliente como usuario normal y use rutas absolutas para configuración y credenciales. Una clave GPG bloqueada no puede pedir datos al arrancar.

--check-config valida ajustes, no el acceso a credenciales, DNS, TLS ni el inicio de sesión IRC.

Use --reconnect para cortes de red temporales; vigilar caídas del proceso corresponde al sistema operativo.

Los lanzadores deben permitir esperar a los hijos: ignorar SIGCHLD o recogerlos automáticamente impide el primer inicio en segundo plano o crear el resolvedor o ayudante de credenciales. Volver a separar un trabajo gestionado no crea otro proceso.

/help documentation
-------------------

Encuentre una tarea con /help ls. /help commands explica la entrada de comandos y enumera los disponibles. Use un tema o comando cada vez.

/help COMMAND muestra sintaxis, efectos y ejemplos. /help /ls explica el listado local; /help ls enumera los temas.

/help all o /manual abre esta referencia. --help explica las opciones de inicio; la salida de --manual en modo minimalista puede guardarse en un archivo.

README.md orienta sobre la documentación; MANUAL.txt describe la interfaz e INSTALL la compilacion. La página man instalada explica el uso desde la shell.

CONTRIBUTING.md explica los cambios; doc/SOURCE-MAP.txt ubica el código; tests/README.md enumera pruebas. DESIGN.md documenta propiedad y orden de ejecucion.

doc/TROUBLESHOOTING.txt ofrece diagnosticos por sintomas. SECURITY.md define las amenazas; doc/BOUNCERS.txt y doc/SESSION-CONTROLS.txt explican operaciones. Cada auditoria vale solo para la version y entorno indicados.

/help history
-------------

El historial mostrado y de comandos está limitado en RAM. El registro persistente es opcional y viene desactivado.

Cambiar de vista vuelve a mostrar sus registros recientes; /mentions muestra líneas de origen coincidentes.

El ajuste de historial limita los registros de todos los servidores y vistas en conjunto; edítelo mediante /panel y después 0.

Se conserva como máximo el menor entre ese ajuste y 2048 registros, con un límite estricto independiente de 512 KiB.

En un canal o conversación privada, /catchup empieza en su última composición enviada localmente. Prueba un registro privado apto y luego la memoria retenida; /help catchup explica ambos lectores.

La recuperación persistente es por servidor y conversación. El registro debe estar activado al enviar el punto de referencia; es texto privado sin cifrar, limitado a 16 MiB por perfil guardado, no almacenamiento cifrado.

La recuperación de comandos conserva hasta 64 entradas y 64 KiB, eliminando las más antiguas. /clear borra el historial de conversación, no el de comandos.

Las sugerencias de historial reciente usan estas líneas completas. Delete elimina la fila de historial seleccionada.

Las sugerencias de más usados emplean hasta 96 nombres canónicos de comandos y contadores acotados en <config_path>.commands.

En configuraciones guardadas, aceptar comandos y reiniciar frecuencias actualiza automáticamente ese archivo privado. No se guardan allí argumentos, destinatarios ni mensajes.

Los perfiles sin guardar conservan los contadores en memoria hasta el primer Guardar correcto. La ausencia o inutilidad de los archivos de contadores no impide iniciar.

La ayuda y las respuestas de comandos de varias líneas usan un lector separado con un búfer limitado a 512 KiB. No pasan al historial de chat.

Los comandos aceptados pueden recuperarse en el editor de comandos. Se omiten cambios de autenticación, entradas a canales con clave y mensajes sensibles a servicios.

Up/Down en Compose mueve el cursor, no recupera mensajes enviados. Solo Command recupera comandos aceptados.

Separar y reanudar en la misma interfaz conserva borradores e historial de comandos. Cambiar de interfaz, donde se admite, descarta estos y los formularios de configuración; salir o reiniciar el sistema también borra el chat en memoria y sus puntos de recuperación.

Los contadores de frecuencia guardados solo contienen nombres. Los registros antiguos sin cifrar sobreviven a la salida, pero no se importan automáticamente en otra sesión ni en el editor.

/clear borra el historial en RAM de una vista, no el registro antiguo en disco. El bouncer aporta su propia reproducción.

/help hotkeys
-------------

Las teclas personalizadas son opcionales y no hay ninguna por defecto. Siguen funcionando la navegación y el editor.

Use /bindings para ver la lista, /bindings keys para teclas y /bindings actions para funciones locales.

Asigne con /bind KEY ACTION; vuelva a asignar para sustituir. Quite con /unbind KEY o /unbind all.

Los cambios afectan de inmediato a todos los servidores; /save input los guarda en la configuración principal. Los perfiles extra no la sustituyen.

El formato es [hotkeys] y una línea KEY=action por tecla, hasta 64. Las teclas duplicadas, incluidos alias del terminal, son errores.

Las acciones solo funcionan en el chat principal y la línea de comandos; no en contraseñas, ajustes, pegado, lectores ni confirmaciones.

En la interfaz mínima, los lectores conservan borrador y cursor. Un atajo que cambie de vista o editor exige terminar o borrar el borrador.

No se admiten acciones de enviar, comandos arbitrarios, shell ni macros de texto. Segundo plano y salir conservan sus efectos habituales.

Se admiten F1..F12, Ctrl-A..Z, Alt-a..z/0..9 y teclas de navegación; los caracteres imprimibles siguen siendo texto.

Ctrl-H/Backspace, Ctrl-I/Tab, Ctrl-J/Ctrl-M/Enter y Ctrl-[/Escape comparten bytes; no se pueden asignar por separado.

Las señales y atajos del terminal/multiplexor tienen prioridad. Ctrl-C o Ctrl-Z solo sirven si llegan a la aplicación; no se reasignan.

El pegado delimitado reconocido no ejecuta atajos. El pegado sin delimitar parece escritura; consulte /help keys.

/help keys
----------

Registro: / abre Comando; ? explica el registro seleccionado de conversación o vigilancia. Otras teclas imprimibles abren Redactar conservando ese carácter.

Las asignaciones propias pueden reemplazar estos controles en el chat principal o Comando; no hay ninguna predeterminada. Consulte /help hotkeys.

Registro en vivo: Up retrocede una fila, Page Up una página y Home va a la más antigua retenida. Down/Page Down/End siguen en vivo; Left/Right/Delete/Backspace no abren Redactar.

Insert o Enter abre Redactar vacío. Las flechas, Home/End, Delete y Backspace editan. Tab/Shift-Tab completa apodos en Redactar y nombres de comandos en Comando.

El modo de redacción en línea mantiene una fila de entrada bajo el final del registro en vivo; el modo de pantalla completa mantiene un editor de varias líneas y un panel de registro en vivo más pequeño.

En Comando, Down selecciona sugerencias. Up/Down recorre la lista; Up desde la primera vuelve a la entrada.

Enter sobre una sugerencia la inserta sin ejecutarla. Léala o edítela y, después de verla, pulse Enter de nuevo para ejecutarla.

En Comando, Up recupera comandos aceptados coincidentes; Down vuelve hacia la entrada original. En Redactar, Up/Down mueve el cursor incluso al mantenerse pulsado; Enter envía.

Delete elimina la fila de Historial reciente seleccionada o reinicia el contador seleccionado de Más usado. Los comandos del catálogo siguen disponibles.

? sobre un comando seleccionado lo explica y enlaza con la ayuda de su pantalla. En todos los editores de texto, ? es texto normal.

Revisión usa una pantalla alternativa temporal; borrador y aviso nunca entran en el historial de chat. Un nuevo Enter confirma; Escape o escribir restaura editor, borrador y cursor. Up/Down, Page Up/Down y Home/End permiten recorrerla.

En ayuda o respuestas, Up/Down desplaza; Page Up/Down cambia de página; Home/End va al principio o al final.

En la lista de usuarios, Enter vuelve al registro; en ayuda y otros lectores de respuestas, Enter avanza una línea.

En el lector, / abre Comando con autocompletado e historial habituales. Escape cancela esa entrada y vuelve al lector.

En un lector de resumen, r actualiza la instantánea; ? explica la respuesta y su lector.

En ayuda contextual, Enter sigue el enlace resaltado Acerca de la pantalla. Escape vuelve a la ayuda del elemento y luego a la pantalla de origen exacta.

En configuración, Tab selecciona el encabezado de la pregunta; ? explica su opción o pantalla. Tab/Enter vuelve a editar la respuesta.

Ejecutar un comando reemplaza la respuesta anterior. Las confirmaciones breves vuelven al registro; los errores breves mantienen el comando editable.

Escape cancela Redactar o Comando y vuelve al registro. Desde Revisión, Escape vuelve al editor conservando el borrador. Escape en el registro deja el cliente en segundo plano.

Escape solo espera unos 500 ms; una secuencia en curso admite 1000 ms entre bytes sucesivos. La actividad de red continúa.

Las secuencias completas de teclas se procesan al instante. Si el marcador inicial de pegado se retrasa más que ese margen tras su primer Escape, puede dejar el cliente en segundo plano.

Una vez iniciada la captura del pegado, su marcador de cierre sigue reconociéndose aunque las lecturas se dividan o sufran demoras arbitrarias.

Las teclas de interrupción, salida y suspensión conservan sus asignaciones; «Usar señales» = no desactiva sus señales mientras el cliente está activo.

[input] use_signals=false No (predeterminado) desactiva las señales del terminal mientras la aplicación lo controla; Ctrl-C/Ctrl-Z cancelan el borrador. Yes activa las asignaciones existentes sin cambiarlas. Las señales externas del proceso siguen funcionando ([input] use_signals=true).

Las señales de terminal activadas terminan o suspenden tras restaurar la terminal; fg reanuda un trabajo suspendido.

Ctrl-D no actúa salvo que se le asigne una acción en el chat principal o Comando. /quit sale; /background libera la terminal mientras continúa la actividad de red.

Las pantallas habituales omiten recordatorios repetidos de teclas; este tema sigue siendo la referencia completa del teclado.

El pegado delimitado reconocido se mantiene literal. Las teclas esperan un editor visible, entrada nueva y una pausa. Los cuadros demasiado pequeños o fallidos no pueden aprobarlo; amplíe la terminal y suelte las teclas.

Pegar en el registro de vigilancia abre Redactar con barras literales. Pegar en Comando conserva ese modo; CR/LF/Tab se convierten en espacios. Revíselo y pulse Enter de nuevo.

Un pegado sin delimitadores no se distingue de la escritura; use compatibilidad con pegado delimitado.

/help limits
------------

Los límites de IRC se miden en bytes, no en caracteres visibles. Un carácter UTF-8 puede ocupar varios bytes.

El cliente calcula el espacio contando destino, comando y retransmisión; nunca divide un carácter UTF-8.

Al llenar un mensaje, se bloquea más texto hasta confirmar con Enter que se seguirá editando; ese Enter no envía nada.

Un mensaje dividido requiere permiso separado, incluso en modo directo. Se envía una línea de chat cada 1.2 segundos.

Un envío permite como máximo 64 mensajes y 16384 bytes de texto. Acorte el texto o envíelo aparte deliberadamente.

Hay como máximo 8 espacios de servidor y 32 vistas por servidor, incluidas las reservadas.

/help logging
-------------

El registro persistente es opcional y empieza apagado. /set persistent_logging on lo activa; /save output lo guarda.

Cada perfil guardado añade a CONFIG_PATH.log. El directorio padre final debe pertenecer al usuario y tener modo 0700; el archivo debe ser regular, propio, de un enlace y modo exacto 0600. Se prohíben enlaces simbólicos y rutas por padres.

Los registros son plaintext, no copias cifradas. Maximo 16 MiB por archivo; un fallo detiene el registro, no el chat.

Archive el registro lleno fuera de su ruta activa y reactive el registro. La rotación o reescritura puede invalidar el marcador de /catchup: envíe otro mensaje válido antes de confiar en él.

Se excluyen credenciales conocidas y borradores sin enviar, incluso autenticación repetida con apodos antiguos. Chats corrientes, servicios desconocidos y secretos escritos a mano sí pueden guardarse. El servidor y el bouncer retienen por separado.

/catchup usa un registro sano solo si el marcador local exacto se guardó durante este proceso. No pide archivos históricos al bouncer ni importa registros de procesos anteriores.

/clear solo borra la RAM. Los registros sobreviven a salir, --close-session y guardar. Desactivar el registro detiene entradas nuevas; no borra las anteriores.

La E/S del disco puede retrasar el proceso con almacenamiento lento. Consulte /help catchup, /help history y SECURITY.md.

/help messages
--------------

Use /join #channel para entrar y seleccionar un canal, o /query NICK para abrir una conversación privada.

Seleccione un canal retenido con /channel. /msg TARGET TEXT envía a un destino y /me TEXT envía una acción.

/query abre una conversación sin enviar nada; /pm es un alias. /ql separa las conversaciones privadas de los canales.

El envío directo es predeterminado; /set send_mode review añade revisión. /set composer_mode line|fullscreen cambia la presentación.

Al alcanzar el límite de un mensaje hay que confirmar que se seguirá editando; dividirlo requiere otro consentimiento.

Hay que terminar de entrar y autenticarse antes de poner mensajes en cola. /cancel cancela la cola, no lo ya enviado.

/help reconnect
---------------

--reconnect habilita reintentos en este proceso; no guarda ajustes ni inicia una conexión.

Sin esta opción, una conexión fallida exige /connect. /autoconnect controla solo el inicio.

Los fallos temporales de DNS, rechazo/pérdida de conexión y tiempos de espera se reintentan tras 5, 10, 20, 40, 80, 160 y 300 segundos.

Una conexión registrada durante al menos 60 segundos reinicia la espera. El sondeo no bloquea con pausas.

Errores de certificado, autenticación, protocolo malformado y configuración quedan desconectados hasta corregirse.

Un ERROR del servidor antes del registro se retiene; después del registro puede iniciar una reconexión.

/disconnect explícito cancela el reintento pendiente. Otro /connect inicia un intento nuevo.

Los reintentos usan la configuración actual; los cambios pendientes aún requieren /connect explícito.

Los mensajes pendientes se descartan al desconectar y nunca se reenvían automáticamente.

Se repiten autenticación y órdenes de inicio activas. Perfiles directos repiten autojoin tras el registro; bouncers restauran sus canales.

El modo de prueba sin red nunca se reconecta a la red.

/help security
--------------

El texto remoto se sanea antes de mostrarse. La entrada se interpreta como comandos IRC locales, nunca de shell.

No hay /raw, acceso a shell ni aceptación automática de archivos. El pegado delimitado reconocido no ejecuta comandos.

TLS verifica la identidad del servidor. SASL, PASS y los comandos privados de autenticación requieren TLS verificado. Mantenga actualizada la biblioteca TLS del sistema; vea SECURITY.md.

Un paquete CA propio debe ser un archivo PEM normal, no vacío, de hasta 16 MiB; nunca pide contraseña.

Las contraseñas configuradas se ocultan en la ayuda y ajustes. Los comandos de credenciales conocidos no se recuperan del historial; los secretos escritos como texto normal pueden conservarse.

No se guarda un registro de conversaciones en disco por defecto. Los cambios de configuración requieren guardarse explícitamente.

Otro proceso de la misma cuenta, el servidor IRC o bouncer y un terminal o sistema comprometido quedan fuera de estas protecciones. TLS no cifra el chat de extremo a extremo.

Los registros opcionales y los secretos en la configuración son texto plano. Se filtran comandos sensibles conocidos, pero no se detectan de forma fiable todos los secretos en el chat.

Consulte /help tls, /help authentication, /help logging y SECURITY.md para conocer límites y revisiones previas.

/help sessions
--------------

Un trabajo es un proceso cliente con sus servidores, transferencias, borradores e historial. El número de servidor dentro del programa no es el ID de trabajo de la shell.

En la terminal ejecute --sessions. Consulte si el trabajo esta unido o separado y use su ID, no el ID de proceso.

Si la antigua terminal SSH retiene el trabajo, use --detach-session NUMBER y luego --resume NUMBER. IRC sigue activo.

--resume sin número solo elige un trabajo separado verificado. Varios trabajos requieren número; uno conectado esta ocupado hasta separarlo. Los números pueden reutilizarse al salir.

Use --close-session NUMBER solo para terminar todo el trabajo. Cierra IRC y transferencias; se pierden borradores e historial RAM, pero siguen los ajustes y registros guardados.

Cerrar confirma exito solo tras limpiar. Si hay espera agotada, consulte --sessions: puede terminar despues. Un fallo no elimina el punto activo ni envia señales a un PID supuesto.

Solo un trabajo gestionado sobrevive a la pérdida del terminal. Un proceso normal en primer plano no se vuelve reanudable al perder SSH. Inicie con --background o use /background primero.

Un trabajo pertenece a una cuenta Unix y un host; solo admite un terminal conectado. Otro programa de esa cuenta esta dentro del mismo limite de confianza.

Instalar un ejecutable no cambia el código de un proceso activo. Guarde la configuración, cierre el anterior, compruebe --version e inicie un proceso nuevo.

Un proceso antiguo puede carecer de controles nuevos o cambio de interfaz. Conserve el ejecutable compatible hasta detenerlo si lo necesita para reconectar.

El cliente no cambia la politica de inactividad de SSH. Vea /help background, /help deployment y doc/SESSION-CONTROLS.txt.

/help startup
-------------

Ejecute el programa, cierre la bienvenida y escriba /connect irc.example.org y /join #channel.

No hace falta crear antes un perfil de servidor, alias ni número. /server HOST equivale a una conexión directa.

Si no indica un apodo, se usa su nombre de inicio de sesión válido o, si no sirve, user. No se pide un apodo.

Guarde la configuración y la opción predeterminada con /saveconf. En el siguiente inicio, /connect las reutiliza.

Guardar no activa la conexión automática; es una elección aparte. /quickstart y /panel son guías opcionales.

También sirven las opciones del shell: --server HOST, --channel '#CHANNEL' y --nick NICK. Ponga #CHANNEL entre comillas.

En el inicio normal, --nick, --port, --channel, --tls, --plain y --ca-file sustituyen el valor predeterminado guardado.

Un --server explícito elige la primera conexión. --init-config y --check-config usan el archivo principal de configuración.

Si cambia --server a otro host, se borran las credenciales anteriores, la CA personalizada, la identidad del bouncer, los canales y los comandos de inicio.

Si no está disponible el valor predeterminado guardado, indique --server o corríjalo antes de aplicar cambios a la conexión.

Autoconnect, autojoin y autoauth corresponden a cada perfil de servidor guardado. Vea /help autoconnect para activarlos.

--no-connect impide conexiones al arrancar; --test-mode simula actividad sin red ni escritura de configuración.

--sessions enumera trabajos conectados y desconectados de la terminal. --resume [NUMBER] vuelve a unirlos; vea /help background.

--close-session NUMBER cierra el trabajo elegido y todas sus conexiones IRC tras confirmar su cierre. NUMBER es un ID de trabajo, no un PID.

Tras perder la terminal, use --sessions, luego --detach-session NUMBER y --resume NUMBER. El proceso conserva su código hasta reiniciarse; vea /help sessions.

-h/--help y -v/--version funcionan sin terminal.

/help tls
---------

TLS verificado es la opción predeterminada. Se comprueban nombre/dirección y certificados; no hay excepcion ni retorno a plaintext.

El puerto no desactiva TLS. --plain o /connect -plain elige IRC sin cifrar y no puede usar credenciales de cuenta/servidor.

Usa el nombre de host y puerto TLS exactos del proveedor. Puede fallar por destino erróneo, certificado vencido/no fiable o almacén local; lee el error primero.

TLS usa por defecto las CA de confianza del sistema. --ca-file FILE o ca_file= elige un paquete PEM CA, no fija el certificado final.

El paquete CA personalizado debe ser un archivo normal no vacío de hasta 16 MiB. Se admite enlace simbolico a CA; las rutas de secretos/configuración son más estrictas.

El archivo CA se abre una vez y se revisa su tamaño al leerlo. Se rechazan FIFO, dispositivos y archivos no normales; PEM con clave no puede pedirla.

Limitar el tamaño no limita la latencia I/O de archivos normales o de red. Use un paquete CA fiable en almacenamiento adecuado.

--check-config no prueba el enlace TLS ni garantiza que funcionen las CA o las credenciales. --test-mode no contacta servidores.

TLS solo protege esta conexión. El TLS ascendente y el historial plaintext del bouncer se gestionan aparte.

/help troubleshooting
---------------------

Ocupado tras caer SSH: use --sessions, compruebe el trabajo, luego --detach-session NUMBER y --resume NUMBER. Evite --close-session. See /help sessions.

Up no recupera texto: Compose edita mensajes; Command recupera comandos aceptados. Abra Command con / desde el registro. Chats enviados y comandos sensibles no se recuperan.

Si un mensaje ajustado parece cortado: el editor reserva filas y muestra las lineas visuales más recientes. Salga del editor o vuelva al canal; lo visible no confirma entrega remota.

Si al cambiar de canal aparece todo el texto, la diferencia es de vista. Si persiste un fallo, anote interfaz, modo, tamaño del terminal, locale y pasos depurados; no comparta claves ni chats privados.

Sin canales: revise la vista del servidor y la autenticación. Perfiles directos: /autojoin list; bouncers: /join o /part.

Falla autenticación: revise cuenta, origen, permisos, TLS y agente GPG. /autoauth status muestra rutas sin leer secretos.

Sin recuperacion: el ancla pudo salir del historial, el registro empezar tarde o detenerse, o cambiar el archivo. Vea /help catchup y /help logging; los registros no restauran un proceso muerto.

Cambio sin efecto: se requiere /connect tras desconectar. Guardar no activa autoconnect; las preferencias de inicio exigen reiniciar.

Si falla el inicio de procesos auxiliares, corrija la politica SIGCHLD o de recoleccion automatica del iniciador para que el cliente pueda esperar a sus hijos.

Use --check-config y doc/TROUBLESHOOTING.txt. --test-mode solo prueba la interfaz, no DNS, TLS, credenciales ni un bouncer real.

/help /autocommands
-------------------

Preparar comandos diferidos para la siguiente conexión
Uso: /autocommands [list|add COMMAND|remove NUMBER|clear|on|off|delay SECONDS|interval SECONDS]

Los comandos pertenecen al servidor seleccionado. Se ejecutan una vez tras registrarse y completar el SASL requerido.

Espera predeterminada: 15 segundos; al menos 2 segundos entre comandos terminados.

Use delay 0..300 e interval 2..60 para cambiar las esperas. Una conexión atascada no dispara una ráfaga posterior.

Comandos admitidos: /msg, /join, /nick, /away, /back y /whois, con sus alias exactos documentados.

Máximo 16 comandos de 511 bytes UTF-8 cada uno. Cada comando debe caber en un mensaje IRC; nunca se divide solo.

No hay shell, IRC sin procesar ni expansión de la conversación actual. Unirse automáticamente no cambia la vista.

Guarde con /save. El archivo debe ser privado (0600 o 0400); una lista habilitada y no vacía exige TLS verificado.

El modo de prueba no ejecuta comandos automáticos. Su texto se guarda literalmente en el archivo de configuración, sin cifrado GPG.

Ejemplos:
/autocommands add /msg ChanServ op #chat mynick
/autocommands delay 15
/autocommands interval 2
/autocommands list
/save

/help /background
-----------------

Mantener las conexiones y liberar la terminal
Uso: /background

Restaura el terminal y separa la sesión activa. El shell muestra el comando numerado para reanudarla.

En el shell, --sessions enumera los trabajos privados conectados o separados; --resume reanuda el único trabajo separado disponible.

Si hay varios trabajos, use --resume NUMBER. NUMBER es el ID del trabajo, no el PID; permanece hasta salir y después puede reutilizarse.

--detach-session NUMBER libera el terminal conectado, pero mantiene el proceso, las conexiones IRC, los borradores y el historial para --resume NUMBER.

--close-session NUMBER termina el trabajo, sus conexiones IRC y transferencias, borradores sin guardar e historial en memoria. Solo confirma éxito tras verificar el cierre.

Si la reanudación está ocupada tras perder SSH, enumere los trabajos, separe ese trabajo y reanúdelo. Consulte /help sessions.

Un proceso que no responde o una versión antigua sin el control solicitado puede fallar. Instalar otro binario no actualiza el proceso activo: reinícielo tras actualizar.

Al reanudar aparece el historial retenido, aunque no haya mensajes nuevos. /set single_session on impide otro trabajo en segundo plano, de modo que --resume sea inequívoco.

Para iniciar sin terminal, use --background desde el shell. Consulte --help para las opciones.

Si background_away está activo y el perfil lo permite, /background o la pérdida del terminal envía AWAY tras separarse. Al reanudar solo se quita ese estado automático; /away manual persiste.

Añada --reconnect para reintentar fallos pasajeros de conexión. Consulte /help deployment y /help reconnect.

No requiere multiplexor de terminal. Una resolución de nombres o un auxiliar de credenciales pendiente puede requerir otro intento.

Suspender un proceso normal en primer plano pausa su red. Un trabajo reanudado puede suspender su controlador de terminal mientras el proceso gestionado sigue conectado.

Ejemplos:
/background

/help /catchup
--------------

Leer esta conversación desde el último mensaje que envió
Uso: /catchup

Un registro de marcador alterado o reemplazado no vale como original. Un proceso nuevo no recupera marcadores de registros antiguos. Consulte /help logging y /help history.

/catchup

/help /connect
--------------

Conectar a un servidor o reutilizar la conexión guardada
Uso: /connect [-tls|-plain] [-nick NICK] HOST [PORT] | /connect

Empieza con /connect irc.example.org. No necesitas crear antes perfil, alias ni número de servidor.

Se selecciona la conexión y se abre su vista de servidor/MOTD. Una conexión activa equivalente no se duplica.

Un destino distinto recibe nueva autenticación; no se copian credenciales ni canales de otro servidor.

/connect sin argumentos usa el servidor seleccionado y sus ajustes aplicados. /saveconf recuerda el predeterminado para el próximo inicio.

Si varios perfiles bouncer comparten host, elige uno con /server NUMBER y luego usa /connect solo.

Se aceptan números de servidor existentes por compatibilidad. El modo de prueba sigue sin red; guarda los cambios expresamente.

Ejemplos:
/connect irc.example.org
/join #chat
/saveconf
/connect
/connect -nick mynick irc.example.org +6697
/connect -plain localhost 6667

/help /dcc
----------

Ofrecer, revisar y administrar transferencias directas de archivos
Uso: /dcc [list|NICK PATH|send [-address IPV4] [-port PORT] NICK PATH|accept NUMBER [DIRECTORY]|reject NUMBER|cancel NUMBER]

Sin argumentos, lista las transferencias. /dcc NICK PATH ofrece un archivo en el servidor seleccionado.

PATH es el texto literal restante, con espacios; se interpreta respecto al directorio desde el que se inició el proceso.

El cliente nunca cambia ese directorio, ni al explorar archivos ni al ejecutarse en segundo plano.

El envío breve anuncia la IPv4 local del enlace IRC. Tras NAT, use -address con su IPv4 accesible y -port con un puerto redirigido.

No consulta servicios externos para descubrir la dirección. Una conexión IRC solo IPv6 requiere indicar una IPv4.

DCC es una conexión directa sin cifrar. El par recibe la IP anunciada; aceptar una oferta también le revela su IP.

Las ofertas entrantes no se abren hasta /dcc accept NUMBER. DIRECTORY usa por defecto el directorio inicial y debe ser propio y privado.

No sobrescribe destinos existentes; rechaza enlaces simbólicos y archivos especiales. El modo de prueba no toca archivos ni sockets.

Use /dcc reject NUMBER para rechazar una oferta, o /dcc cancel NUMBER para cancelar una transferencia activa.

Los números de transferencia se comparten entre servidores del proceso. Cerrar el servidor de origen las cancela; desconectar IRC no cancela una aceptada.

Ejemplos:
/dcc alice file.txt
/dcc list
/dcc accept 1 ./downloads
/dcc send -address 203.0.113.20 -port 5000 alice file.txt
/dcc cancel 2

/help /list
-----------

Solicitar y filtrar el directorio de canales de la red
Uso: /list [MASK] [--min-users N] [--max-users N] [--name TEXT] [--topic TEXT] [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list show [--sort channel|users|topic] [--asc|--desc] [--limit N] | /list clear

Requiere un canal al que te hayas unido o una conversación privada y una conexión registrada. Se aplican los límites de mensaje y las reglas de envío.

La interfaz revisa un mensaje dividido antes de ponerlo en cola.

Ejemplos:
/me waves

/help /mentions
---------------

Ver menciones o borrar las menciones retenidas de todos los servidores
Uso: /mentions [clear]

Selecciona las menciones de este servidor. Contiene líneas recientes limitadas y sus marcas de tiempo originales.

/mentions clear elimina las copias de menciones guardadas de todos los servidores actuales sin cambiar de vista.

Se conservan el historial de la conversación original, los contadores de no leídos y las tareas pendientes.

Usa /watch para añadir textos literales; /channel o /pm vuelve a una conversación donde puedes enviar.

Ejemplos:
/mentions

/channel #ircnow

/help /panel
------------

Abrir el panel de configuración interactivo
Uso: /panel

Elija 0 (predeterminado) para las preferencias de la aplicación, o los paneles de perfil 1..8; el panel 1 edita el principal. Son opciones de panel, no ID de trabajos del intérprete de órdenes.

Las preferencias de la aplicación incluyen retención del historial, modo de envío, formato de salida, avisos de cola y sugerencias de comandos para todos los servidores.

Funcionan sin un servidor configurado. Sus opciones finales son 1 Guardar (predeterminada) y 2 Aplicar sin guardar; ninguna conecta.

Un panel de servidor solo contiene sus ajustes de conexión, inicio, autenticación, menciones y exclusiones.

Elegir un panel no cambia la conversación de chat.

Enter conserva el valor mostrado; '-' vacía un campo opcional. Escape retrocede una pregunta cada vez; repítalo para salir sin aplicar los cambios.

Tab selecciona el encabezado de la pregunta. Allí, ? muestra ayuda sobre la opción y su pantalla; Tab o Enter vuelve a la respuesta.

Toda respuesta editable conserva ? como texto literal, incluso como primer carácter y en máscaras con comodines.

Los términos vigilados y las máscaras de exclusión se introducen uno a uno; una nueva entrada vacía termina la lista.

La entrada de credenciales se oculta y las respuestas de configuración nunca entran en el historial de comandos. Los archivos de credenciales existentes no se leen durante la edición.

Para una fuente GPG, elija Crear nuevo o Usar existente. Al crear se ofrece una ruta privada predeterminada; Enter la acepta y prepara su directorio (0700).

Otro destino debe estar en un directorio existente de su propiedad con modo 0700. La ruta se comprueba antes de preguntar por la clave y la contraseña.

A continuación se solicita la huella completa de una clave pública local y la contraseña dos veces. Nunca se reemplazan archivos ni enlaces simbólicos existentes.

Las rutas de credenciales se guardan como rutas absolutas. /autoauth status muestra sus ubicaciones configuradas completas sin leer su contenido.

El cifrado solo empieza tras Finalizar, mantiene IRC operativo y nunca usa archivos temporales de texto sin cifrar. Escape cancela el trabajo pendiente.

Si falla el guardado de la configuración, el cifrado ya terminado queda disponible para un reintento deliberado; se conservan los archivos referenciados por una configuración guardada.

El modo de prueba no inicia GPG ni crea archivos de credenciales. Desbloquee externamente la clave privada correspondiente antes de autenticarse.

Las opciones finales del panel de servidor son 1 Guardar y conectar, 2 Solo guardar (predeterminada), 3 Conectar una vez y 4 Solo aplicar.

Abrir el panel o responder sus preguntas anteriores no aplica ni guarda nada, ni establece conexiones.

Conectar una vez aplica sin guardar; Solo aplicar no guarda ni conecta. Una conexión activa nunca cambia de destino ni reconecta implicitamente.

Una conexión fallida no deshace los cambios ya aplicados o guardados con la acción final.

Use /quickstart para configurar más brevemente el servidor, transporte, puerto y apodo.

Ejemplos:
/panel

/help /part
-----------

Salir de un canal con motivo opcional y conservar su historial
Uso: /part [#CHANNEL] [MESSAGE]

Sin canal, sale del canal unido seleccionado. El texto tras el canal es la razón PART; sin canal, el texto es la razón para el seleccionado.

Sin razón explícita, usa part_message si está configurado. Quita la entrada del autoingreso activo.

Cancela los mensajes en cola para ese canal; un envío ya iniciado puede terminar. Usa /close para quitar la vista.

Ejemplos:
/part
/part Going offline
/part #old Moving elsewhere

/help /quickstart
-----------------

Abrir la configuración guiada de conexión
Uso: /quickstart

Edite el servidor, transporte TLS, puerto y apodo del perfil actual en ese orden; luego revise los ajustes.

TLS verificado es el valor predeterminado. Debe elegir explicitamente una conexión en texto plano.

Enter conserva el valor mostrado. Escape vuelve una pregunta; repitalo para salir sin aplicar. Las respuestas no van al historial de comandos.

En la revisión final elija 1 Guardar y conectar, 2 Solo guardar, 3 Conectar una vez (predeterminado) o 4 Solo aplicar.

Abrir el asistente y responder preguntas no aplica ajustes, guarda archivos ni conecta.

Conectar una vez aplica sin guardar; Solo aplicar no guarda ni conecta. Una conexión activa nunca cambia de destino ni reconecta implicitamente.

Una conexión fallida no deshace los cambios ya aplicados o guardados con la acción final.

Use /panel para perfiles de bouncer y más opciones. Quickstart no modifica un inicio de sesion existente del bouncer.

Ejemplos:
/quickstart

/help /save
-----------

Guardar el servidor actual, las preferencias de la aplicación o todos los perfiles
Uso: /save [input|output|all]

/save sin argumentos escribe los ajustes efectivos del servidor elegido, incluidos cambios de conexión pendientes.

/save input y /save output guardan el perfil principal completo, preferencias y conexión preparada. No guardan solo la sección nombrada.

/save all guarda cada perfil valido por separado. Si uno falla, los anteriores quedan guardados y se informa de los fallos.

Cada reemplazo de archivo es privado y atómico, pero no una transaccion global. El modo de prueba nunca escribe configuraciones.

Ejemplos:
/save
/set send_mode review
/save input
/save all

/help /saveconf
---------------

Guardar configuración y recordar la conexión elegida
Uso: /saveconf

Guarda preferencias de la aplicación y todos los servidores válidos, y recuerda el servidor elegido como predeterminado.

En el siguiente inicio, /connect usa ese valor guardado; no hace falta número de servidor ni otra configuración.

Incluye apodo, canales unidos, autenticación y opciones de inicio; prevalecen los cambios explícitos pendientes.

Esto no activa la conexión automática al iniciar. Usa antes /autoconnect on si la deseas.

Cada archivo se sustituye de forma privada y atómica. Lo ya guardado permanece aunque falle otro archivo.

Se recuerda el servidor predeterminado solo si se guarda bien; se informan errores y no se sobrescriben perfiles ilegibles.

El modo de prueba nunca escribe configuración. /save mantiene opciones más específicas por perfil y preferencias.

Ejemplos:
/connect irc.example.org
/join #chat
/saveconf
/quit

/help /server
-------------

Conectar a un servidor o seleccionar uno existente
Uso: /server [-tls|-plain] [-nick NICK] HOST [PORT] | /server [NUMBER|add HOST [PORT] [NICK]|connect NUMBER|disconnect NUMBER|close NUMBER]

Con un nombre de host equivale a /connect directo. No exige crear un perfil antes.

Sin argumentos muestra mensajes/MOTD del servidor actual. NUMBER selecciona un espacio sin conectarlo.

add crea un perfil con credenciales nuevas, TLS verificado y autoconnect apagado; no selecciona, conecta ni guarda.

PORT es 6697 por defecto. Otro puerto no desactiva TLS; debes elegir explícitamente una conexión sin cifrar.

connect/disconnect no cambian la selección. close quita una sesión/entrada secundaria, no su archivo de perfil.

Los servidores minimalistas se numeran 1..8, principal 1. El principal permanece: desconéctalo, no lo cierres.

Los números no cambian durante la sesión. Panel 0 se reserva para preferencias de la aplicación.

Ejemplos:
/server irc.example.org
/join #chat
/saveconf
/servers
/server 1

Muestra los servidores 1..8 (principal 1) del modo mínimo, el seleccionado, su estado y autoconnect por servidor.

/help /set
----------

Elegir preferencias de entrada, salida y presencia para toda la aplicación
Uso: /set send_mode direct|review | /set composer_mode line|fullscreen | /set output_format compact|full | /set queue_notices on|off | /set program_messages on|off | /set persistent_logging on|off | /set single_session on|off | /set default_interface idle|ncurses | /set command_suggestions alphabetical|common|history|frequent|contextual | /set part_message [TEXT] | /set quit_message [TEXT] | /set background_away on|off | /set background_away_message TEXT | /set autoaway_minutes 0..1440 | /set autoaway_message TEXT

direct es el valor predeterminado: Enter envía el texto; si requiere varios mensajes IRC, hay que confirmar.

review añade una revisión deliberada antes de poner los mensajes normales en cola.

output_format compact es el predeterminado: el chat seleccionado muestra [HH:MM:SS] <nick> texto.

output_format full incluye servidor, fecha y destino en cada línea. compact conserva el origen necesario de menciones y diagnósticos de otros servidores.

queue_notices off oculta avisos rutinarios de cola. En modo mínimo, un envío ya revisado omite el aviso repetido. Los errores y la confirmación de mensajes múltiples siempre aparecen.

program_messages off oculta mensajes locales secundarios como borrador cancelado, entrada vaciada o borrador conservado. Los errores y confirmaciones de seguridad siguen visibles.

persistent_logging on añade chat a un .log privado (0600) en directorio de configuración privado (0700). Desactivado por defecto; tope 16 MiB: archive y cambie off/on. Un archivo inseguro/ocupado detiene el registro, no el chat.

single_session on permite solo un trabajo en segundo plano del cliente, para que --resume sin número no sea ambiguo. Admite varios servidores IRC en esa sesión.

default_interface selecciona la interfaz del próximo inicio nuevo, si es compatible. No cambia la actual. /save input guarda esta preferencia.

command_suggestions ofrece orden alfabético, comandos comunes, recientes, más usados o relevantes para la pantalla de origen.

composer_mode line reserva una fila de entrada bajo el chat en vivo; fullscreen usa editor multilínea y panel de chat. Por defecto: line.

part_message y quit_message son motivos de salida IRC predeterminados; /part o /quit explícitos los sustituyen. El valor vacío desactiva ese texto.

background_away envía background_away_message tras /background correcto o pérdida de terminal. autoaway_minutes fija away por inactividad; 0 lo desactiva.

Solo el estado away creado por el cliente se borra al reanudar o recibir entrada real. Un /away manual nunca se cambia ni borra.

«De uso frecuente» es el predeterminado. «Contextual» prioriza comandos de canal, consulta, servidor o cliente sin ocultar otras coincidencias.

«De uso frecuente» usa un orden útil seleccionado. «Contextual» recuerda la pantalla que abrió el comando, incluido el lector de resumen general.

Son preferencias globales del cliente. Use /save input o /save output para conservarlas.

/panel seguido de 0 modifica esas preferencias y el límite global del historial.

Ejemplos:
/set send_mode review
/set composer_mode line
/set command_suggestions contextual
/save input
/set output_format full
/set queue_notices off
/set program_messages off
/set persistent_logging on
/set single_session on
/save output

/help /summary
--------------

Resumir todas las sesiones de servidor actuales y su actividad
Uso: /summary

Muestra todos los servidores, channel 0, vistas de canales/consultas, actividad sin leer, menciones, colas salientes, comandos de inicio y transferencias.

Es un resumen local que funciona desconectado. Pulsa r en su lector o ejecútalo de nuevo para actualizar.

Abrirlo no cambia la conversación ni marca mensajes como leídos. Las menciones copiadas se excluyen del total de actividad.

Las menciones pueden estar sin leer; no sumes ambos totales. Las vistas de canales unidos y abandonados se distinguen.

El informe tiene lector desplazable y conserva borradores. Barra inclinada abre comandos; cancelar vuelve al resumen.

Si falla actualizar, conserva el resumen previo. Abrirlo o actualizarlo no envía peticiones a la red.

Nunca muestra credenciales ni contenido de mensajes en cola o comandos automáticos.

Ejemplos:
/summary
